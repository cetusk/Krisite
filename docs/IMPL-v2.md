## 2. ★★ 分裂の検証を、同値な増分計算に置き換えた（2026-09-07）

### 2.1 何が問題だったか

`split_contacts` の末尾は、**`mesh::check_topology` を 2 回呼んでいました。**

```
(1) 面が増減しないこと      O(1)
(2) 分裂後の多様体性        check_topology(out)    → `unresolved` に要る
(3) §5.5 の予測との検算     check_topology(tris)   → 純粋な診断
```

**`check_topology` は大域の `std::map` を 2 つ作ります** — 無向辺の表（$3F$ 回の挿入）と、
**頂点ごとのリンクの表**（頂点ごとに `std::map` を 3 つと `std::set` を 1 つ）。
**出力が数百万三角形になると、これが出口の大半を占めます。**

### 2.2 同値であることの論証 ★

**4 つの観測から出ます。実装より先に、こちらを確定させました。**

#### 第一に、出力の辺は元の辺ごとに分かれてできます

`out` は `tris` の複製で、**分裂した頂点の ID だけが書き換わります。**
新しい ID は `next_id`（= `vertex_count`）から始まるので、**既存 ID と衝突しません。**

> **したがって、相異なる元の辺が出力で 1 本に併合されることはありません。**
> 出力の辺は**元の辺 1 本の中で分かれる**ので、元の辺ごとに数え直せば足ります。

#### 第二に、分裂した頂点に接しない辺は、次数も向きも変わりません

自明ですが、**費用の議論の核心です。** 分裂する頂点は全体のごく一部なので、
**組み直しが要る辺もごく一部**です。

#### 第三に、`vertex_manifold` は「頂点ごとに成分が 1 個か」と同値です

**前提**: すべての辺の次数が 2 で、各辺を 2 枚が逆向きに辿ること。

**このとき各頂点のリンクは閉路の直和になります。** 三角形 $(v,a,b)$ は
リンク上の有向辺 $a \to b$ を与え、辺 $(v,a)$ に接する 2 枚のうち一方が
$a$ から出る弧を、他方が $a$ に入る弧を与えるからです。
**閉路の本数は、その頂点に接する三角形の連結成分の数に等しい。**

**逆向きも成り立ちます。** 辺 $(v,a)$ を 2 枚が同じ向きに辿るなら、
その 2 枚はどちらも $a$ から出る弧を与えるので**リンクの出次数が 2** になり、
`check_topology` も `vertex_manifold = false` を返します。
**片側だけが真になることはありません。**

#### 第四に、$\Delta V$ / $\Delta E$ も同じ枠組みで出ます

`check_topology` の `v` は「参照されている頂点 ID の個数」、`e` は「無向辺の本数」です。
**前者は $O(3F)$ の走査、後者は上の数え直しの副産物**です。
$F$ は不変なので $\Delta\chi = \Delta V - \Delta E$（§5.5 の恒等式そのもの）。

#### ★ 前提: 出力に退化三角形が無いこと

**第三の論証は「同じ頂点を 2 度使う三角形が無い」ことを使っています。**
あるとリンクの議論が崩れます。

> **前提は宣言せず、実行時に検査します**（`CLAUDE.md`「前提を書いたら、検査も
> 書いてください」）。**破れたらその場で正解器（`check_topology`）を呼びます。**
>
> **これは「保守的に倒す」ではありません。** 同値性の前提が成り立たない場合だけ
> 正解器を呼ぶ、という形です。**一般解（`SPEC-phase2.md` §2.4.4 (2)）が
> 入っている限り、この経路は踏みません**（`verify_fallback` が数えます）。

### 2.3 実装

`mesh::detail::split_topology`。**新しい大域の `std::map` を作りません。**

| 段 | 費用 |
|---|---|
| 出力に退化三角形が無いことの検査 | $O(3F)$ の比較 |
| 参照されている頂点の数（前後） | $O(3F)$ + `vector<char>` 1 本 |
| 出力の辺の数え直し（元の辺ごと） | 既存の `edge_tris` を 1 回走査 |
| 頂点まわりの成分数 | **三角形の角（$3F$ 個）の素集合** 1 本 |

**`edge_tris` は分裂そのものが既に作っている表**なので、走査は追加の確保を伴いません。

**採らなかった代案**:

| 案 | 却下の理由 |
|---|---|
| `check_topology` を `unordered_map` で書き直す | **同じ量を安く測るだけ**で、頂点リンクの表（本体）は残ります |
| `edge_tris` の値型に角の添字を持たせる | **辺 1 本につき `std::vector` がもう 1 本**増えます。$E \approx 1.5F$ なので、大きい対で数百 MB。**その場で 3 回比較して求めるほうが安い** |
| `compute` が作った扇の割り当てを流用する | **変異ビルドで `compute` が早期に返る**ので（変異 8a / 8b）、そこに依存すると**変異の検出力が落ちます** |

## 9. 連鎖で断片数がどう増えるか（依頼 3。2026-09-08）

**詳細は `DESIGN-phase5-hotspots.md` §15。ここには判断と、なぜそう調べたかだけ書きます。**

### 9.1 決め手の対照を「冪等な連鎖」にした理由

**依頼は $(A \cup B) \setminus D$ の 1 段目と 2 段目を比べることでした。**
**しかしそれだけでは、増分が【幾何が複雑になったから】なのか
【表現が細かくなったから】なのかが分かれません**（演算も入力も違うため）。

**そこで $(A \setminus D) \setminus D$ を足しました。** 差は冪等なので**幾何は同一**です。
**位相（$C$, $\chi$）が一致したまま断片が増えれば、増分は表現だけから来ています。**

**実測**: 位相は一致、断片は +16.1%（小さい模型）/ +2.1%（`425318`）。

### 9.2 ★ 固定深度にしたら増分が完全に消えたこと

**適応分割を切ると、断片数も三角形数も 1 枚も変わりませんでした**（12,906 / 26,006）。
**そして連鎖の食い違い（新しい鍵との突き合わせ）も 0 になりました。**

## 15. 案 E の測定（`SPEC-phase5.md` §5.10.10。2026-09-08）

**詳細は `DESIGN-phase5-hotspots.md` §21。ここには判断だけ書きます。**

### 15.1 結論 — 案 E は成立します

**`side` の被符号値は、$b=21$ で >192 ビットが 0.0%、$b=26$ で 0.0〜0.1%。**
**観測した最大は 162〜212 ビット**（上界は 209 / 254）。

**≤ 128 の累積は $b=21$ で 86.7〜99.4%、$b=26$ で 52.3〜87.1%。**

### 15.2 ★ リム数は減らせません

**`CLAUDE.md`「乱択の実測値でリム数を減らさない」。上界の 4 リムは維持します。**
**できるのは「実行時に幅を見て狭い経路に入る」ことだけで、これは同値な置き換えです。**

### 15.3 ★ 予測が半分外れ、構造の理解の誤りが出ました

**「分類はレイキャストなので幅が大きい」と予測しましたが、外れました。**

**レイキャストの `side` の大半は【軸平行平面】に対する前判定です**
（`raycast.hpp` の 282 / 306 / 323 行）。**D の絞り込みは 85 倍なので、
候補の 99% 近くが前判定で落ちます。**

> **「分類はレイキャストだから幅が大きい」という理解が粗すぎました。**
> **分類の中身の 99% は前判定で、それは軸平行です。**

### 15.4 測る量の定義について

**仕様側が「中間結果の最大ではなく、最終的な被符号値の幅」と定義してくださったのが
効きました。** 前者は上界で決まるので、測っても何も分かりません。

**そして区分を 4 つ（64 / 128 / 192 / それ以上）にする指示も効きました。**
**$b=26$ では ≤128 が 52.3% しかありませんが、≤192 は 99.9% です。**
**3 区分（64 / 128 / それ以上）で測っていたら、
「$b=26$ では案 E が半分しか効かない」と誤った結論を出していました。**
