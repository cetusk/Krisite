## Phase 1 が分岐点である理由

Phase 1 は **EMBER 系を続けるか断念するかを決めるフェーズ**です。

この方式で難しいのは論文の中核ではなく**出力抽出**です。並列化のために入力を
セルに分割する以上、**セル境界の継ぎ目**が構造的な弱点になります。同じ幾何点が
複数のセルで独立に計算されるので、それが同一の頂点だと認識されなければ、
そこで割れるか非多様体になります。

そこで Phase 1 では、適応分割・並列化・最適化をすべて外し、**継ぎ目だけを変数として
残した最小構成**で可否を判定します。詳細と中止条件は `SPEC-phase1.md` §11。

### 中止した場合

`csg/` を Manifold（Apache-2.0）のラッパとして実装し、Phase 2〜4 を飛ばして
Phase 5 系（点群コーデック、GWN、メッシュ化）へ進みます。

**Phase 0 の算術基盤は無駄になりません。** GWN の分類器、点群の量子化、
メッシュ化の述語でそのまま使えます。撤退は失敗ではなく、想定された分岐の一方です。

## Phase 2 以降の見通し（確定ではありません）

### モジュール構成（Phase 1 で確定）

```
include/krisite/
  arith/    固定幅厳密整数
  geom/     平面・点・述語
  octree/   八分木（セル境界は 2 の冪の格子座標に置くこと）
  mesh/     三角メッシュ、頂点テーブル、位相検査
  csg/      arrangement、縫合、分類、ブール演算
```

`bool` は C++ の予約語なので `csg` です。**`octree/` は Phase 5 の Morton 線形八分木と
同じものに育てます。** セル境界を 2 の冪に置く制約はそのためです。

### Phase 2 — 適応分割

Phase 1 で固定した分割を適応化し、early-out を入れます。

**最適化の順序が Phase 1 の実測で決まりました。** `side` : `intersect3` の呼び出し比が
**1.26 : 1** で、`intersect3` が述語時間の 94.9%（推定）を占めます。原因は
`split_fragment` が構成点を毎回作り直していることなので、

1. **断片の構成点を保持する**（回数を減らす）
2. `intersect3` の混合幅化（単価を下げる）

の順です。§12 は 2 を挙げていますが、**1 が先**です。詳細は `IMPL-phase1.md` §5.6。

**非多様体出力の意味論**も Phase 2 の課題です。正則化ブールは多様体出力を保証
できません（§9.3.2）。Manifold は頂点分裂で多様体化していることが実測で分かって
います（`IMPL-phase1.md` §7.8）。

### Phase 3 — 並列化

work-stealing。**継ぎ目の整合性は Phase 1 で解決済みであることが前提**です。
未解決のまま並列化すると、非決定的な破損が出て原因追跡が困難になります。

**構造は Phase 1 の実測で決まりました。** 併合グループの空間的な広がりが
全ケース・全深度で **1 以下**（1 セルとその面・辺・頂点隣接に収まる）なので、
**「セル並列 + 境界併合」で組めます。大域整列は要りません。**
第2段の発火率が 44% に達しても、局所性が保たれるので構造は変わりません（§5.4）。

### Phase 5 以降 — 点群とメッシュ化

| 内容 | 備考 |
|---|---|
| 独自フォーマット（八分木 + rANS） | 拡張子 `.kris`、マジック `"KRIS"` |
| G-PCC エクスポータ | データモデルを G-PCC 上位互換に保っておくこと |
| 点群入出力（PLY / PCD / LAS） | LAS は **LASzip 単体**（Apache-2.0）。LASlib は LGPL なので不可 |
| GWN（一般化巻き数） | 自前実装。開曲面・非多様体の内外判定 |
| メッシュ化（SDF / GWN + Manifold DC） | 点群→メッシュ、スキャン融合、非多様体修復を兼ねる |

**データモデルの規律だけは今から守ってください。** 座標系は
`origin(double3) + scale(double) + 符号付き整数`、点順序は Morton 昇順を正準、
八分木は幅優先の占有ビット列。これを守れば、後の G-PCC 変換器が
「エントロピー層の差し替え」で済みます。崩すと全面再設計になります。

## 通しての約束

各仕様書と実装ノートに散っているものの再掲です。**フェーズをまたいで守る規律です。**

- **リム数の数値リテラルは `geom/widths.hpp` 以外に書かない**
- **乱択の実測値でリム数を減らさない**（真の最大に届かないため）
- **述語を追加するときは、先にビット幅を導出して `widths.hpp` に定数を足す**
- **述語を実装する前に、その述語の差分テストを書く**
- **正解器は被検体と別経路で書く**（同じ変形を使う正解器は正解器ではない）
- **プラットフォーム検証は CI が正。**開発コンテナに GCC / MSVC を入れて代用しない
- **GPL / LGPL のコードを参照・移植しない。**判断に迷ったら実装せず確認を求める
- **対称性の高い入力はバグを構造的に隠す。**軸平行だけのコーパスは、4 平面同時交差・
  クリップの分岐バグ・変異テストの検出力の 3 つを同時に隠していた（Phase 1 の実例）
- **変異テストはコーパスに依存する。**「どのコーパスで検出されるか」を必ずセットで
  指定し、**素通りする組合せも固定する**
- **フォールバック連鎖は最も一般的なものを先に用意する。**狭い十分条件から始めると、
  退化配置でその条件のほうが先に破れる
