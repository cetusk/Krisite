## 1. 座標モデル（Phase 0）

```
実座標 = origin + scale × integer_coord

origin : double[3]     バウンディングボックス原点
scale  : double        格子幅
coord  : int32[3]      格子座標。各軸 coord ∈ [-2^(b-1), 2^(b-1))
```

**入力点はすべて符号付き整数です。浮動小数点は境界（ファイル入出力）でのみ扱います。**

**$b$ は既定で 21。** 理由は **64bit Morton コードに 3 軸 21bit がちょうど収まる**ため
（$21 \times 3 = 63$）。**コンパイル時パラメータで、$b = 26$ でもテストが通ります。**

> **$b$ の既定を変えるかは未決です**（`SPEC-phase5.md` §1.6）。
> **メッシュ処理では $b = 26$ が有利という実データがありますが、
> Morton が 128bit になります。** **Phase 6（点群）の着手前に決めてください。**

## 2. ビット幅（Phase 0）

**幅は型で表します。** `fixed_int<N>` の $N$ が伝播するので、
**上界を超えるとコンパイルが落ちます。**

| 述語 | 必要幅 | $b=21$ | $b=26$ |
|---|---|---|---|
| `side`（平面 対 同次点） | $9b+20$ | 209（4 リム） | 254（4 リム） |
| `cmp_h`（同次点の比較） | $13b+27$ | **300（5 リム）** | 365（6 リム） |
| `cmp_axis_int`（軸座標 対 整数） | $7b+15$ | 162（3 リム） | — |
| `kRadialDet` / `kRadialDot` | $8b+16$ | 184（3 リム） | — |
| `kRadialAlign` | — | 393（実測の最大 354） | — |

### 2.1 ★ 新しい述語を足すときの手順

**必ずこの順序で行ってください。**

```
1. ビット幅を導出し、widths.hpp に定数として入れる
2. GMP 差分テストを書く（退化した配置を明示的に構成すること）
3. 実装する
```

**乱択だけでは退化に当たりません。** radial sort の述語では、
**乱択 20 万件で $\det = 0$ が 1 件も出ませんでした。**

**そして幅の検査は、その幅を実際に使う入力で行ってください。**
**整数点だけで測ると `kRadialAlign` は 106 ビットに見えますが、
構成点を通すと 354 ビットです。**

## 3. パイプラインの契約（Phase 3 で確定）

```
from_mesh : TriMesh（整数座標） → PolySoup
boolean   : PolySoup × … → PolySoup            ★ CSG について閉じる。n 項
to_mesh   : PolySoup → TriMesh
```

**`boolean` が `PolySoup` を返すのが要点です。**
**出力を再び入力にできるので、演算を連鎖しても位相が壊れません。**
**そして連鎖でビット幅が伸びません**（構成点を保持するため）。

### 3.1 各段の中身

| 段 | 内容 |
|---|---|
| `from_mesh` | 量子化、面積 0 の三角形の除去、**PWN の検査**（$\partial S = 0$） |
| `boolean` | 適応分割 → 局所 BSP → 分類 → 断片の確定 |
| `to_mesh` | 構成点 → 頂点の併合 → T 頂点の解決 → 接触の分裂 → 三角形化 |

## 4. 入力の制約（Phase 3 §1.1）

**受け入れるのは PWN（piecewise-constant winding number）な入力です。**

| 入力 | $\partial S$ | 扱い |
|---|---|---|
| 閉じた多様体 | 0 | 受け入れ |
| **自己交差した閉曲面** | 0 | **受け入れ**（self-union で解く） |
| **辺を共有して貼り合わせた 2 つの閉曲面** | 0 | **受け入れ**（非多様体だが PWN） |
| **向きが反転した閉曲面** | 0 | **受け入れ。ただし巻き数が負になります** |
| 1 辺に 3 枚 | $\ne 0$ | 拒否 |
| 開曲面 | $\ne 0$ | 拒否 |

> **★ 量子化は $\partial S$ を保つとは限りません**（2026-09-06 訂正）。
> **面積 0 の三角形を取り除けば辺の集合が変わります。**
> **CP2 では 8 模型が、量子化と除去のあとで $\partial S \ne 0$ になりました。**

## 5. ★★ 指示関数（Phase 3 §5.2。2026-09-04 訂正）

**source ごとに「その立体の内側か」を定める述語を置きます。**

$$\text{内側}_i \iff w_i > 0$$

> **初版は $w_i \ne 0$ と定めていました。誤りです。**
>
> **自己交差した閉曲面の巻き数は、向きに応じて正にも負にもなります。**
> **立体の内部に対応するのは、巻き数が【正】の領域です。**
> **負の領域は「面が裏返っている部分」であって、立体の内部ではありません。**

**演算は、この述語の論理式です。論理式そのものは変わりません。**

| 演算 | 条件 |
|---|---|
| $\bigcup_i A_i$ | いずれかの $\text{内側}_i$ |
| $\bigcap_i A_i$ | すべての $\text{内側}_i$ |
| $A \setminus B$ | $\text{内側}_A$ かつ **not** $\text{内側}_B$ |
| self-union（$n=1$） | $\text{内側}$ |

**巻き数から内外を決める箇所を 1 つに保ってください。** 直し漏れが起きません。

### 5.1 出力の規則（EMBER §3.4）

| $(f_{op}(w_F), f_{op}(w_B))$ | 扱い |
|---|---|
| (out, in) | そのまま出力 |
| (in, out) | 向きを反転して出力 |
| (in, in) / (out, out) | 捨てる |

## 6. 出力の意味論（Phase 2 §2.3）

**非多様体な出力を、正当な出力として扱います。**

**2 つの立体が辺で接していれば、どんな実装でも次数 4 になります。**
**これは契約の範囲内です。**

### 6.1 ★ ただし「機構の未実装による非多様体」は別です（2026-09-06）

**`SPEC-phase2.md` §5.1.2.1 の配置（2 枚のシートが別の場所で繋がっており、
連結成分では分けられない）は、radial sort があれば分けられます。**

> **これを「除外」に分類しないでください。**
> **未実装であることが記録から見えなくなり、直す動機も消えます。**

**`unresolved > 0` の対は失敗として数えてください。**

## 7. 分割の判定（Phase 2 §3.1。2026-09-06 訂正）

| 判定 | 意味 |
|---|---|
| $C$ が $A$ と $B$ の両方の三角形を含む | 交差の可能性がある。分割の候補 |
| **$C$ が片方しか含まず、局所 BSP が省かれる** | **分割不要** |
| **$C$ が片方しか含まず、$P_C$ が小さい** | 分割不要 |
| **$C$ が片方しか含まないが、$P_C$ が大きい** | **★ 分割する** |
| 最大深度に達した | 打ち切り |

> **初版は「片方しか含まないセルは分割不要」でした。誤りです。**
> **局所 BSP を入れたとき、この判断を見直していませんでした。**
> **割らないと $O(P_C^2)$ を払います**（実測 168 倍以上）。

**閾値は $P_C^2$ で判定し、実測から決めてください。既定は $P = 128$。**

**そして「局所 BSP が省かれる葉なら除外」を必ず入れてください。**
**入れないと、NSI を宣言できる対で 1.75 倍遅くなります。**

## 8. 三角形化（Phase 2 §2.4.4 (2)）

**退化三角形は「捨てるのではなく作らない」。**

**捨てると $\chi = n-(2n-3)+(n-2) = 1$ が崩れ、次数 1 の辺が残ります。**

### 8.1 一般解（2026-09-06 に実装済み）

```
1. 元の角だけで扇分割する
2. T 頂点を持つ元の辺ごとに、その有向辺を持つ三角形を 1 つ見つけ、
   対頂点 o から扇に開く: (a,t1,o), (t1,t2,o), ..., (tk,b,o)
```

**退化が 0 枚になり、三角形の枚数は 1 枚も変わりません。**

### 8.2 ★ 述語を使わないこと

**起点の選択にも、退化の判定にも、述語を使ってはいけません。**
**「同次点 3 つの 2D 向き」という新しい述語が要り、$20b+43$ 規模の
ビット幅導出が発生します。**

**組合せで厳密に判定できます** — 三角形 $(o, v_i, v_{i+1})$ が退化するのは、
**$v_i$ と $v_{i+1}$ が $o$ に接する同一の元の辺の上にあるとき**です。

## 9. 並列化（Phase 4）

| 項目 | 決定 |
|---|---|
| プール | **永続**。呼び出しごとの生成は 8 スレッドで中核の 40% |
| 待ち方 | **走り出したワーカーだけを待つ** |
| **決定性** | **スロットに書き、添字順に結合。器は決定性を持たない** |
| 正準な代表点 | **同値な構成点から辞書順最小を選ぶ** |

### 9.1 ★ 出力はスレッド数に依らずバイト単位で同一であること

**これは Phase 4 の中心的な要求です。**

### 9.2 構造の測定はスレッド数にも熱にも依りません

**$\sum_\ell P_\ell^2$ も葉の数も、40% 遅い実行と完全に一致します。**
**構造だけ要る測定は、機械の状態を気にしなくてよい。**

## 10. 検査の体系

| 検査 | 何を見るか |
|---|---|
| 位相 | 辺多様体、頂点多様体、向きの整合、**退化なし**（索引の重複のみ）、$\chi$ が偶数 |
| 体積の恒等式 | GMP で厳密に |
| 分割戦略不変性 | 深度や閾値を変えても意味論が同じ |
| 決定性 | スレッド数に依らずバイト一致 |
| 二項正解器との一致 | 別経路の実装と比べる |
| **変異** | **100 件。「テストが緑」と「テストが検証している」を分ける** |

### 10.1 ★ `no_degenerate` は索引の重複しか見ません

**これは意図された設計です**（§8.2 の述語の禁止）。

**幾何的に退化した三角形は `TJunctionStats::degenerate_kept` が組合せ的に数えます。**

### 10.1.5 ★★★ 正しさの検査では見つからない欠陥があります（2026-09-08 追加）

**「ヒントを出す機構」が壊れても、判定が厳密なら答えは正しく、遅くなるだけです。**

**実例**: `interior.hpp` の `approx`（浮動小数点で当たりをつける関数）が
**すべての負の値で $2^{128}$ を返していました。3 フェーズ気づかれていません。**

> **番人が「両方の経路が使われること」しか見ておらず、
> 【どちらが主経路か】を見ていませんでした。**
> **主経路が 2.5% でも「両方の経路が使われた」は真です。**

**ヒントを出す機構には、次の検査を置いてください。**

| 検査 | 内容 |
|---|---|
| **成功率** | **主経路が何回試され、何回成功したか** |
| 回帰 | **その関数の出力そのもの**（符号と桁）。ヒントでも直接検査すること |
| 予言 | 設計が正しいなら成り立つはずの性質（例: 格子が細かいほど成功率が上がる） |

### 10.2 ★ 正解器は被検体と別経路で書く

**同じ変形を使う正解器は正解器ではありません。**
**できれば言語ごと変えてください**（C++ の実装を Python の有理数で検算した例があります）。

**現在の正解器**: 固定深度の分割（Phase 1）、過剰分割（Phase 2）、
二項の実装（Phase 3）、逐次の実装（Phase 4）。

> **★ 実データの検査には正解器がありません。**
> **上記はすべてコーパスの検査で使うものです。**
> **実データで確かめられるのは、体積の恒等式と位相だけです。**

## 11. 実装上の禁止

| 禁止 | 理由 |
|---|---|
| `arith/` での動的確保・例外・グローバル状態 | 組込み環境への移植性 |
| 浮動小数点（境界を除く） | 厳密性 |
| MSVC に無い組み込み関数（`__int128`、`__atomic_*`、`__builtin_*`） | 移植性 |
| 述語を増やすこと（ビット幅の導出なしに） | 上界超過 |
| **計測の費用を本番に持ち込むこと** | **2 度やりました**（レイキャストの計数器、分裂の検証） |
