### 0.1 きっかけ — CSG ツリーを要件に加えたこと

**ブール演算は複数回連鎖して使われるのが常態**であり、$n$ 項演算として一度に評価できる
必要があります（二項は $n{=}2$ の特殊ケース）。

現在の API は型が閉じていません。

```cpp
mesh::TriMesh A;                                    // 入力は整数
csg::BoolMesh r = csg::boolean_op(A, B, ...);       // 出力は構成点（有理数）
```

$(A \cup B) \setminus C$ を計算するには中間結果を整数へ丸める必要があり、
**そこで厳密性が切れます。**

そして**符号ベクトル分類は本質的に二項なので $n$ 項に拡張できません。**
$n$ 個に広げると符号ベクトルの長さが $n$ 倍になり、WNV の $\mathbb{Z}^n$
（整数 $n$ 個）とは比較になりません。

**要件が分類方式を決めました。**

### 0.2 Phase 3 が変えないもの

- **公開出力は三角メッシュ**（多様体・非多様体の両方）。相互運用の要求
- Phase 0 の算術基盤
- 八分木、適応分割、early-out、半開区間割り当て
- 検証体系の大半（位相・体積・変異・Manifold 比較）

### 0.3 単スレッドで作る理由

**中核が純関数になってから並列化します。** 逆順だと非決定的な破損が出て、原因が
構造にあるのか実装にあるのか切り分けられません。Phase 1 で継ぎ目を先に潰したのと
同じ順序です。

## 1. 確定した契約

```
from_mesh : TriMesh(整数) ──────→ PolySoup      入口。量子化・凸分割・辺平面の構成
boolean   : PolySoup × … × PolySoup → PolySoup   ★ CSG について閉じる。n 項
to_mesh   : PolySoup ──────────→ TriMesh        出口。縫合・T 解決・再併合・三角形化
```

```cpp
// n 項。中間結果を経由しない
csg::PolySoup r = csg::boolean_nary({A, B, C}, indicator);

// 連鎖。丸めが入らない
csg::PolySoup r2 = csg::boolean_nary({r, D}, other_indicator);

// 消費用
mesh::TriMesh out = csg::to_mesh(r2);
```

**平面の枚数は増えますが、各平面の係数は入力のまま**なのでビット幅が伸びません
（OEBSP §3.1「CSG 演算は新しい平面を導入できないので、あり得るすべての位置は
入力平面の組合せで表現可能」）。

### 1.1 入力の前提

| | 対象 |
|---|---|
| **PWN**（区分定数な**整数**一般化巻き数） | **受け入れる。** 自己交差・非多様体・退化を含む |
| 開曲面 | **対象外。** 実数値 GWN と閾値が要る（点群フェーズ） |

**自己交差を受け入れることには直接の価値があります。** 自己交差の修復は
「自分自身との和集合」で実現できます（EMBER §1）。

### 1.2 中核から `cmp_h` が消えます

頂点の併合は**縫合するときにしか要りません。** 連鎖では各演算が多角形を切り直すだけで、
頂点は平面3つ組のままで足ります。共平面重複は多角形の**全順序**で扱えます（§5.5）。

| | 最大ビット幅 |
|---|---|
| **中核** | **$9b{+}20$**（現状と同じ。§3.1） |
| `to_mesh` | $13b{+}27$（`cmp_h`） |

## 2. 先行実施 — 段 0 と段 1

**この 2 つは Phase 3 の本体と独立です。判断を待たずに入れて構いません。**
現在の実装にもそのまま効きます。

### 2.1 段 0 — 代表点の構成を平面ベースに戻す

現状のフォールバック連鎖（`IMPL-phase2.md` §2.5）は 3 段で、2 度破れました。
2 段目（中点）と 3 段目（重心）は**点を組み合わせる**操作で、これが 348 / 487 bit の
述語を生んでいます。

#### 2.1.1 主経路 — float をヒントに、厳密演算で検証する

EMBER §4.4:

```
1. 多角形 t の重心を【通常の浮動小数点】で計算し、最近傍の整数座標 c に丸める
2. c から、t の法線に最も近い軸に沿った【軸平行な直線】を定義する
3. その直線と t の交点を【厳密演算】で求める
4. 交点が t の内部にあれば代表点として使う
```

**厳密性は失われません。** float は候補を提案するだけで、判定はすべて厳密です。

**副次的な利得が大きい。** 軸平行な直線は 2 枚の軸平行平面で表せます。
これと支持平面の交点は、一般の 3 平面交点よりはるかに小さいビット幅になります
（軸平行平面は $N$ が単位ベクトル）。**§7 の手順で導出して `widths.hpp` に足してください。**

#### 2.1.2 予備経路 — 点ではなく【平面を動かす】

EMBER §4.4 の第 2 の方法。**概念的にこちらが重要です。**

```
1. t の頂点を 1 つ取る。支持平面 s_t と辺平面 s_e0, s_e1 の交点
2. s'_e0 = (a0,b0,c0, d0+i0),  s'_e1 = (a1,b1,c1, d1+i1)   （i0,i1 ≥ 1 の乱択オフセット）
3. x = intersect(s_t, s'_e0, s'_e1)
4. x が t の内部でなければ 1 へ戻る
```

辺平面は内部が負側なので、$d$ に正の値を足すと平面が内側へ動き、交点がその角の
近傍の内部に入ります。**ビット幅は一般の 3 平面交点と同じです。**

刻みを細かくしたければ平面係数を精度限界近くまでスケールアップします。実際には
$i_0 = i_1 = 1$ で足りるとされています（EMBER §4.4）。

#### 2.1.3 効果

| 項目 | 変化 |
|---|---|
| `widths.hpp` | 中点系・重心系 4 本を**削除**。軸平行 2 枚を含む交点の型を**追加** |
| 最大ビット幅 | **512 → 320**（`cmp_h` が最大になる） |
| フォールバック連鎖 | 3 段 → **2 段**。2 段目で幅が増えない |

**意味論を変えないので、既存の検査体系がそのまま網になります。**

### 2.2 段 1 — 測るべき 2 つの数値

**(a) 葉の閾値。** EMBER §4.5.3 は 25 多角形で最適としています。
「分割を増やすと葉が安くなるが、全葉の多角形数の合計が増える」という相反する 2 傾向の
釣り合いです。**Krisite の最適値は測っていません。**

**(b) 八分木が 3 軸を同時に切る代償。★**

八分木は 1 段で 3 軸を切るので、分割面をまたぐ多角形が最大 8 セルに入ります。
kd-tree なら 2 つ。**同じ実効解像度に対する断片の重複が多い。**

**八分木を維持する現在の根拠は、点群フェーズの Morton 線形八分木との結合と
OEBSP の先例であって、断片数を測った結果ではありません。** 代償が大きければ
空間分割の再検討材料になります。

## 3. 数学的基盤の拡張

### 3.1 辺平面の構成 ★ 最初に決める項目

#### 3.1.1 なぜ必要か

`SPEC-phase1.md` §3.5 は、対角辺が 2 平面の交線として表せないことを理由に
**面併合を必須**とし、非凸パッチでは停止する設計でした。**併合には隣接情報が要ります。**

| 入力 | 併合できるか |
|---|---|
| 閉多様体 | できる |
| **PWN な polygon soup** | **できない**（位相情報がない） |
| **自己交差・非多様体** | **できない** |

**§1.1 で入力制約を緩めた瞬間に、併合戦略が使えなくなります。**
辺平面を構成すれば、併合そのものが不要になります。

#### 3.1.2 構成方式 — 軸方向との外積を使ってください ★

辺 $(p_1, p_2)$ の辺平面には自由度があります。**支持平面上の点しか分類しないので、
「辺の直線を含み、支持平面と一致しない平面」なら何でも構いません。**

| 案 | $N_e$ | $d_e$ |
|---|---|---|
| A | $N_s \times (p_2 - p_1)$ | $-N_e \cdot p_1$ |
| **B** | $(p_2 - p_1) \times e_k$（$e_k$ は軸方向の単位ベクトル） | 同上 |

**ビット幅が桁違いです。**

| 案 | $N_e$ | $d_e$ | 構成点 $w$ | 構成点 $xyz$ | `side` | $b{=}21$ | $b{=}26$ |
|---|---|---|---|---|---|---|---|
| 支持平面（比較） | $2b{+}3$ | $3b{+}5$ | $6b{+}12$ | $7b{+}14$ | $9b{+}20$ | 209（4） | 254（4） |
| A | $3b{+}5$ | $4b{+}7$ | $9b{+}18$ | $10b{+}20$ | $13b{+}28$ | 301（**5**） | 366（**6**） |
| **B** | $\mathbf{b{+}1}$ | $\mathbf{2b{+}2}$ | $3b{+}6$ | $4b{+}7$ | $5b{+}11$ | 116（**2**） | 141（**3**） |

**案 B なら辺平面が支持平面より小さくなります。** 最悪ケースは 3 枚の支持平面が
交わる場合のままで、**$9b{+}20$ から変わりません。**

> **$b{=}26$ が成立します。** 案 A なら 6 リムに増えて $b$ の上限を下げる必要が
> ありましたが、案 B では現状のリム数を維持できます。

#### 3.1.3 案 B が正しいことの確認

$e_z = (0,0,1)$ を取ると $N = (\Delta_y, -\Delta_x, 0)$（$\Delta = p_2 - p_1$）。

- $N \cdot \Delta = \Delta_y \Delta_x - \Delta_x \Delta_y = 0$ なので **$N \perp \Delta$**
- $d = -N \cdot p_1$ で $p_1$ を通り、$N \perp \Delta$ なので $p_2$ も通る
  → **辺の直線を含む**
- 支持平面と一致しなければ、両者の交わりは直線であり、$p_1, p_2$ を含むので
  **辺の直線そのもの**。支持平面上の点に対する分類が正しく働く

**軸の選び方。** 以下を満たす $k$ を選びます。どちらも厳密な整数演算で判定できます。

1. $N \neq 0$（$\Delta \parallel e_k$ のとき退化）
2. $N \not\parallel N_s$（支持平面と一致してはいけない）

**3 通りのうち少なくとも 1 つは成立します。** ただし論証には補いが要ります。

$$(\Delta \times e_i) \times (\Delta \times e_j) = \bigl(\Delta \cdot (e_i \times e_j)\bigr)\,\Delta
 = (\Delta \cdot e_k)\,\Delta$$

なので、**$\Delta$ の第 $k$ 成分が 0 のとき、$i$ と $j$ の 2 通りが平行になります。**
候補の方向は実質 2 つに減ります。

それでも結論は保たれます。$\{\Delta \times e_k\}$ はいずれも $\Delta$ に垂直で、
$N_s$ も $\Delta$ に垂直（辺が支持平面上にあるため）。**相異なる 2 方向のうち
$N_s$ に平行になり得るのは高々 1 つ**なので、少なくとも 1 つが残ります。

$\Delta \parallel e_k$ の場合も同様です。$N_k = 0$ になりますが、残る 2 つは
互いに非平行なので少なくとも 1 つが使えます。

**選択規則を正準に決めてください**（例: 条件を満たす最小の $k$）。
実行ごとに違う $k$ を選ぶと、出力が非決定的になります。

#### 3.1.4 面併合は「必須」から「任意の最適化」へ

| | `SPEC-phase1.md` §3.5 | Phase 3 |
|---|---|---|
| 位置づけ | **必須** | **任意の最適化** |
| 隣接情報 | 必須 | 取れるときだけ使う |
| 非凸パッチ | **停止する** | 併合をやめるだけ |
| 対角辺 | 表現できない（併合の理由） | **辺平面を構成するので問題ない** |

`IMPL-phase1.md` の申し送り「CDT を入れるか仮想平面を与えるかの 2 択」は、
**辺平面の構成という第 3 の解で決着します。**

### 3.2 セグメント・線・光線

EMBER §3.1 の階層です。**平面の組で表します。**

| 対象 | 平面 | 内容 |
|---|---|---|
| 点 | 3 | 3 平面の交点 |
| 線 | 2 | $(l_0, l_1)$。**計算は要らない。組そのものが線** |
| 光線 | 3 | 線 + 始端 |
| **線分** | **4** | 線 + 両端 $(l_0, l_1, r_0, r_1)$ |
| 凸多角形 | $1 + n$ | 支持平面 + 辺平面 $n$ 枚 |

**セグメントと多角形の交差**は `intersect(l0, l1, s)` で交点を作り、
辺平面と両端平面に対する `classify` で有効性を判定します（EMBER §3.1）。
新しい機構は小さいですが、**述語のビット幅導出が要ります**（§7）。

### 3.3 3 セグメント経路 — これは【予備】です

> **訂正（2026-08-28）**: 初版は本節を主要な機構として書いていましたが、
> **EMBER では予備の構成です**（§4.4「この構成が失敗したら、より複雑な構成を使う」）。
> **主経路は §3.3.0 です。** 予備を主経路として実装すると、経路が長くなって
> 退化に当たり続けます。

#### 3.3.0 主経路 — 整数の参照点 + 軸平行のセグメント ★

EMBER §4.2.2:

> 最初の推測は常に、以前の参照点を新しい部分問題の AABB へ射影することである。
> 実用上の大多数の場合、これは**整数位置で終わる有効な経路**を与え、
> **単一の軸平行セグメントのトレース**で到達できる。

**参照点は整数点です。** だから

- 経路が**軸平行のセグメント**で済む
- `classify` が $\langle N, p \rangle + d$ に簡約される（EMBER §3 の式 4 の注記）
- 経路が短いので、退化構成に当たる確率が低い

**§5.3.1 の参照点の伝播が、この主経路を成立させます。**

#### 3.3.1 予備 — 平面を 1 枚ずつ置き換える

主経路が失敗したときだけ使います。

2 つの同次点の間に**直接の線分は作れません**（$x_4 x'_4$ が幅を倍にする。EMBER §3.2）。
**しかし経路なら作れます。**

$x = (s_0, s_1, s_2)$、$x_{ref} = (r_0, r_1, r_2)$ とすると、

- $x_1 = (s_0, s_1, r_2)$ は $x$ と平面 $s_0, s_1$ を共有 → **同じ線 $(s_0,s_1)$ 上**
- $x_2 = (s_0, r_1, r_2)$ も同様
- 経路 $x \to x_1 \to x_2 \to x_{ref}$ の**各セグメントが表現可能**

**「$x$ を定義する平面を 1 枚ずつ $x_{ref}$ のものに置き換えていく」**操作です。
**順序は任意なので、経路が無効なら別の順序を試せます**（EMBER §4.4）。

## 4. 入口 — `from_mesh`

```
0. 【PWN の検査】∂S = 0 を確かめる（§4.0）
1. 量子化（整数座標へ）
2. 各面が非凸・穴あきなら【凸分割】する
3. 各凸片の辺平面を【構成】する（§3.1）
4. 隣接が取れるなら、共平面の隣接片を凸性が保たれる限り【併合】する（任意）
5. 由来のタグを付ける
```

### 4.0 PWN の検査 — $\partial S = 0$ ★

**入力が PWN であることを、入口で検査してください。**

$$\text{すべての有向辺について、接する面の向き付き係数の和が } 0$$

**これは PWN の必要十分条件で、しかも安い**（$O(F)$、整数の数え上げのみ）。

| 例 | $\partial S$ | 扱い |
|---|---|---|
| 閉多様体 | 0 | 受け入れ |
| **自己交差した閉曲面** | **0** | **受け入れ**（§1.1。self-union で修復できます） |
| **辺を共有して貼り合わせた 2 つの閉曲面** | **0** | **受け入れ**（非多様体だが PWN） |
| **1 辺に 3 枚** | **$\ne 0$** | **拒否**（奇数個の $\pm 1$ の和） |
| 開曲面 | $\ne 0$（境界辺が残る） | **拒否**（§1.1） |

> **検査されていない前提は、いずれ静かに破られます。** §1.1 は「入力は PWN」と
> 書いているだけで、破られたときに何が起きるかを定義していませんでした。
>
> **ケース 20b（1 辺に 3 枚）がこの検査のテストです。**

**非凸は入口で消え、中核には凸片しか入りません。**

### 4.1 凸分割 — まず三角形化、次に凸分割

**三角形化を先に実装してください。凸分割は後から足し、実行時に選択できるようにします。**

凸分割は「三角形化してから、凸性が保たれる限り貪欲に併合する」形なので、
**併合の上限を 0 にすれば三角形化**になります。コードは一本化できます。

| | 片の数 | 平面の数 |
|---|---|---|
| 三角形化 | $n-2$ | $2n-3$ |
| **凸分割** | $k \le n-2$ | $n + k - 1$ |

**入口では頂点が整数座標なので、通常の手法が使えます。** 同次座標では三角形分割が
一般に不可能ですが（EMBER §3.2）、それは中間表現の話です。

#### 4.1.1 比較で答え合わせができます

| 量 | 一致するか |
|---|---|
| 体積、$(C, \chi)$ | **厳密に一致** |
| 三角形の集合、断片数、平面数 | **一致しない**（凸分割のほうが少ない。それが目的） |

**一致しないものを明示しておいてください。** 三角形集合の一致を期待すると、
正しい実装が落ちます。

#### 4.1.2 規律

- **切り替えは実行時に。** コンパイル時定数だと同一プロセスで比較できません
- **決定性を保つ。** 貪欲な併合は走査順に依存します。**正準な順序**（頂点 ID 順など）を
  決めないと、同じ入力で違う結果が出ます

### 4.2 面の自己交差 — 【拒否】します（2026-08-28 決定）

**多角形の頂点列自体が交差している場合**、凸分割が定義できません。
面の非凸性とは別の問題です。

> **決定: 拒否します。ただし実装は多角形入力を受け入れる段階です。**
>
> **現在の `from_mesh` は `TriMesh` を受けるので、この場合に到達できません。**
> いま実装すると**死んだコード**になります。頂点列の自己交差判定は 2D の問題で、
> 整数座標なので厳密にできますが、**判定対象が存在しない間は書かないでください。**

理由は 2 つです。

**(1) 現在の `from_mesh` は `TriMesh` を受けるので、この場合が発生しません。**
三角形の頂点列は自己交差できません。多角形入力を受け入れるようになって初めて
問題になります。

**(2) 自己交差する面の分解は「入力の修復」であって `from_mesh` の責務ではありません。**
メッシュ全体の自己交差は self-union で扱えますが（§1.1）、**面そのものが壊れているのは
別の問題**です。2D の arrangement を入口に持ち込むことになり、機構が増えます。

**多角形入力を受け入れる段階で再検討してください。**

> **面の自己交差**（頂点列が交差）と**メッシュの自己交差**（面どうしが貫入）は
> 別物です。後者は §1.1 で受け入れます。

### 4.3 由来のタグ

各凸片に「元の多角形の ID」を持たせ、クリップで生まれた子は親のタグを継ぎます。
整数 1 個です。

用途は 2 つ。

- **`to_mesh` での再併合**（§5.4）
- **属性の転送。** 各結果多角形は入力多角形の部分集合なので、重心座標で
  テクスチャ座標などを移せます（EMBER §5.4）

**元の多角形は復元できません。** CSG を通ると、同じ元多角形から来た片は相手メッシュと
セル境界で切られて散らばります。再併合できるのは隣接が残ったものだけです。

## 5. 中核 — `boolean`

### 5.1 WNV と WNTV

- **WNV** $w = (w_1, \ldots, w_n) \in \mathbb{Z}^n$。空間中の各点（表面上を除く）に定義され、
  $w_i$ は「メッシュ $i$ に何回入ったか」
- **WNTV** $\Delta w$。各入力多角形に付き、その面を**表から裏へ**通過したときの WNV の変化

各断片は $(w_F, w_B)$ を持ちます。

$$w^y = w^x + \sum_{t \in T} \mathrm{sign}\langle n_t, x - y \rangle \cdot \Delta w^t$$

$T$ は線分 $(x,y)$ と交差する多角形の集合（EMBER §3.4）。

#### 5.1.1 WNV の次元はメッシュ数ではありません ★

**次元は「インジケータ関数が区別する必要のある情報の次元」です。**

EMBER Fig. 21 のとおり、$z \in \mathbb{Z}$ を WNV とし WNTV を 1 にすれば
「いくつの曲面の内側か」が数えられ、「少なくとも $k$ 個に含まれる立体」が
一度に取り出せます。**メッシュ 100 個でも、演算が個数しか見ないなら 1 次元で足ります。**

**設計時から、次元をインジケータ関数から決める形にしてください。**

### 5.2 演算はインジケータ関数で与えます

$$f_{op} : \text{WNV} \to \{\text{in}, \text{out}\}$$

| 演算 | $f_{op}$ |
|---|---|
| $\bigcup_i A_i$ | いずれかの $w_i \neq 0$ |
| $\bigcap_i A_i$ | すべての $w_i \neq 0$ |
| $A \setminus B$ | $w_A \neq 0$ かつ $w_B = 0$ |
| $W - T_1 - \cdots - T_n$ | $w_W \neq 0$ かつ すべての $w_{T_i} = 0$ |

出力の規則（EMBER §3.4）:

| $(f_{op}(w_F), f_{op}(w_B))$ | 扱い |
|---|---|
| $(\text{out}, \text{in})$ | **そのまま出力** |
| $(\text{in}, \text{out})$ | **向きを反転して出力** |
| $(\text{in},\text{in})$ / $(\text{out},\text{out})$ | 捨てる |

**正則化ブールが自然に出ます。** `SPEC-phase2.md` §2.3 の意味論はこの系になります。

### 5.3 適応分割と参照点の伝播

```
部分問題（AABB、多角形の集合、参照点 x_ref とその WNV）を受け取る
  ├ 分割の判定（§5.6）
  │   AABB を分割し、各子について:
  │     ・多角形をクリップ（半開区間。§5.3.2）
  │     ・x_ref が子に入らなければ、新しい参照点を選びセグメントトレースで WNV を更新
  │     ・再帰
  └ 葉なら §5.4（局所 BSP）→ §5.5（分類）
```

#### 5.3.1 参照点の更新 — これは【最適化ではなく堅牢性の要件】です ★

**既存の $x_{ref}$ を新しい AABB へ射影するのが第一候補です**（EMBER §4.2.2）。
射影先は整数座標になり、**軸平行の 1 セグメント**で到達できることが多い。

無効な場合（表面上を通る、辺に当たる）は別の点を選びます。
EMBER §5.2 の実測では、参照点の更新はプロファイルにほとんど現れません。

> **実装順序の指示（2026-08-28 追記）**: **参照点の伝播を、セグメントトレースより
> 先に実装してください。**
>
> EMBER は伝播を**局所化（速度）**の文脈で説明していますが、**実際には成功率の前提です。**
> §4.2.2 は「経路が現在の AABB を出ない限り、選ぶ自由がある。経路が無効になるのは
> 退化構成に当たったときだけなので、**大多数の場合で最初の経路が既に有効**」と
> 書いていますが、**この主張は経路が局所であることを前提にしています。**
>
> 大域の参照点（外接箱の外）から辿ると経路が全域を横切り、**軸平行なコーパスでは
> 途中で必ず辺や頂点に当たります。** 内部点 6 通り × 経路 6 順序をすべて試しても
> 退化する、という実測があります。
>
> **正しさではなく成功率の問題です。** 退化した経路は棄却されるので誤答は出ませんが、
> **有効な経路が 1 つも見つからないと止まります。**

#### 5.3.2 測ること

**「伝播を入れたら動いた」だけでは、局所化が原因だったことを示せません。**

| 指標 | なぜ |
|---|---|
| **経路の棄却率**（伝播の前後） | 局所化が原因だったことの証拠 |
| **試行回数の分布**（何番目の内部点・順序で成功したか） | EMBER の「大多数で最初の経路が有効」と一致するか |
| **軸平行の単一セグメントで済んだ割合** | §3.3.0 の主経路が主経路として機能しているか |
| 経路が跨いだ多角形数（伝播の前後） | 経路長の実測 |

#### 5.3.3 半開区間割り当て（`SPEC-phase2.md` §3.4 を維持）

**各セルは各軸で $[\text{lo}, \text{hi})$ を占めます。**
分割平面に完全に乗る多角形は片側にだけ割り当てます。

**EMBER §4.2.1 と一致しています。**

> 分割平面にちょうど乗る多角形は「左」の部分問題に割り当てる

### 5.4 局所 BSP — 過剰分割を置き換えます ★

**交差線分のみで切ります。全平面では切りません。**

```
葉の各多角形 t について:
  ・t と、その葉の他のすべての多角形との交差を計算する
  ・交差線分を t の局所 BSP に「追加」する
```

BSP は**加速構造ではなく幾何の表現**です（EMBER §4.3）。結果の BSP は $t$ の
互いに素な分割で、どの葉多角形も内部に交差を持ちません。

**保守的に切って凸性を保ちます**（EMBER Fig. 7「必要以上に長く切ることでセルを凸に保ち、
単純で速い手法にする」）。

> **`SPEC-phase1.md` §4.3 の過剰分割はここで置き換わります。**
> 過剰分割の根拠だった符号ベクトル分類（§4.3.2）が WNV に変わるので、
> **利得ゼロで断片数だけ増える機構になります。**
>
> あわせて「どの平面で切るか」（`SPEC-phase2.md` §2.3 / §2.6）の問いも消えます。
> 局所 BSP には選択の余地がありません。

#### 5.4.1 共平面重複は全順序で扱います

多角形に全順序（入力インデックスなど）を入れ、**重なり領域では最小のものだけが
出力を出します。** 他方の BSP 葉は「無効化」します（EMBER §4.3、Fig. 8）。

> **仕様と実装が食い違っています**（2026-08-28 報告）。実装は Phase 2 からの
> 「互いの辺平面で切って揃える + `region_key` で潰す」方式のままです。
> **結果は正しいものの、機構が違います。**
>
> **私が本節を EMBER から書き写したとき、Phase 2 の既存機構で足りるかを
> 確かめていませんでした。**

##### 判定結果（2026-08-28）— 現行機構で成立します ★

**ケース 23 が固定深度 0〜3 + 適応分割のすべてで通りました。**

> **本節を「全順序**でもよい**」に緩めます。** 現行機構（互いの辺平面で切って揃える +

### 5.5 分類 — セグメントトレース

```
1. 葉多角形 t の内部点 x を求める（§2.1 の技術）
2. x から x_ref への経路を構成する
     主経路: 軸平行のセグメント（x_ref が整数点なので短く済む。§3.3.0）
     予備  : 平面を 1 枚ずつ置き換える 3 セグメント経路（§3.3.1）
   いずれも AABB へクリップする
3. 経路が交差する多角形の Δw を符号付きで足し、(w_F, w_B) を得る
4. f_op を適用して出力を決める
```

> **経路の始点は分類する面の上にあります。** その面は「跨がない」扱いが要ります。
> 忘れると全経路が退化します。
>
> **同じ入力多角形の断片を二重に数えないこと。** 真偽値では代入なので無害ですが、
> **巻き数では足し算なので効きます。**

**分類が局所問題になります**（EMBER §3.4）。

> レイトレーシングを使うと分類は大域的な問題になり効率的な計算が難しい。
> セグメントトレースなら、既知の WNV を持つ参照点があれば分類を局所問題に保てる。

### 5.6 early-out

WNV があると、`SPEC-phase2.md` §3.2 より強い early-out が書けます（EMBER §4.5.2）。

> $A - B$ で参照 WNV が $(0, b)$ の形、部分問題に $B$ の多角形しか無いなら**即座に破棄**。
> 分類は $(0,b)$ から始まり $B$ しか無いので WNV は $(0, b+z)$ の形にしかならず、
> $A-B$ が in になるのは $(a, 0)$ の形だけだから。

**$n$ 項では演算ごとに手で規則を書くのは現実的でありません。**

> **導出を機構にしてください。** EMBER §4.5.2 は「有限オートマトンの到達可能性解析に
> 似た形で機械的に計算できる」としています。インジケータ関数と、部分問題に存在する
> WNTV の集合から、到達可能な WNV を求めて判定します。

加えて NSI（自己交差なし）/ NNC（入れ子成分なし）のフラグ（EMBER §4.5.1）。
**Krisite の現在の early-out は、閉多様体入力に対して実質これを使っています。**
入力制約が緩むので、**フラグとして明示的に持つ形に変えてください。**

> **未実装でした**（Phase 5 で判明、2026-09-01）。**そして影響が大きい。**
>

>

## 10. 検証

### 10.1 二項実装が正解器になります ★

**現在の実装（符号ベクトル + 領域ごとレイキャスト）を残してください。**

> **$n$ 項演算を $n{=}2$ で呼んだ結果が、現在の二項実装と一致すること**

が全コーパスで使えます。**外部依存ゼロで検証が閉じます。**
Phase 1 の固定深度、Phase 2 の分割戦略不変性と同じ構造です。

一致すべきもの・しないもの:

| 量 | 一致するか |
|---|---|
| 体積、$(C, \chi)$ | **厳密に一致** |
| 三角形の集合 | **一致しない**（局所 BSP と過剰分割で分割が違う） |
| 断片数 | **一致しない**（局所 BSP のほうが少ないはず。それが目的） |

### 10.2 $n$ 項と二項の連鎖の一致

> $(A \cup B) \setminus C$ を $n{=}3$ で 1 回評価した結果と、
> 二項を 2 回連鎖した結果が、**体積と $(C, \chi)$ で一致すること**

**三角形集合は一致しません**（$n$ 項は中間結果を持たないので分割が違う）。

### 10.3 連鎖の厳密性

> **`boolean` を $k$ 回連鎖しても、丸めが 1 回も発生しないこと**

型が閉じていることの検査です。**`to_mesh` を経由していないことを機械的に確認してください**
（例: 連鎖の途中で `TriMesh` が生成されないことをテストで固定）。

#### 10.3.1 連鎖でビット幅が伸びないこと ★

> **$k$ 段連鎖したときの実測ビット幅が、1 段目と一致すること**

**これが契約の成立条件です。**

CSG は新しい平面を作りません（OEBSP §3.1）。したがって何段連鎖しても、構成点は
**元の入力メッシュの支持平面・辺平面とセル面**という固定された集合から 3 枚を選んだ
交点です。**プールが増えないので、ビット幅も増えません。**

**伸びていたら、どこかで平面を構成しています。** 平面を構成する操作は
入口（辺平面、§3.1）だけであるべきです。

| | EMBER | Krisite |
|---|---|---|
| 評価データ | 実データ | **退化を狙って構成** |
| 前提 | 退化は例外 | **退化は常態**（`SPEC-phase1.md`） |

**「退化したら別の経路を試す」は前者の戦略です。**

> **判断を分けてください。** 「Krisite のコーパスで動かない」ことは
> **「実データで動かない」ことを意味しません。** Phase 5 で Thingi10K を当てたとき、
> トレースは EMBER の報告に近い成功率を出す可能性が高い。

#### item 2 に進む場合の前提条件

**記号的摂動が要ります。** レイキャストには既にあります（`SPEC-phase1.md` §6.1）が、
トレースには無く、「退化したら別の経路を試す」だけです。

**摂動は合成できます。** 端点が厳密にどの面上にもなければ、**WNV の差は経路に依りません**
（面の外では WNV が well-defined）。各トレースが内部で一貫していれば足ります。

**したがって要件は「両端点が厳密にどの面上にもないこと」です。**

| 端点 | 保証 |
|---|---|
| 断片の内部点 | **相対内部なので面上にない**（`IMPL-phase3.md` §1.2.2） |
| 参照点 $x_{ref}$ | **保証が要る。要検証** |

**新しい述語のビット幅を導出する前に、この条件を確かめてください。**
$x_{ref}$ が面上に載ると、そこでの WNV が定義されません。

#### 2 の中での順序 ★

> **参照点の伝播を、セグメントトレースより先に実装してください**（§5.3.1）。

大域の参照点から辿ると経路が長くなり、**退化を避けられません。**
伝播は速度のためではなく、**主経路（§3.3.0）を成立させるため**の前提です。

**局所 BSP はまだ入れず、過剰分割のままで構いません。**

- §10.1 の二項正解器との一致
- §10.2 の $n$ 項と二項連鎖の一致

**分類だけを差し替えて検証できるので、失敗の切り分けが楽になります。**

#### CP3 の判定結果（2026-08-28）★

> **item 2 は Phase 4 の前提ではありません。Phase 5 へ降格します。**

| 根拠 | 内容 |
|---|---|
| 監査 | 葉の分類が触るデータはすべて不変。可変はメモ化・カウンタ・出力バッファのみ |
| **機構** | **領域を逆順に分類して幾何の多重集合が一致（264 / 264）** |

詳細は `IMPL-phase3.md` §5。

**したがって CP3 は item 1 の完了をもって閉じます。次は CP4 です。**

##### Phase 4 への前提条件 — 可変な部分はスレッド局所に保つこと ★

**順序非依存の検査は「論理的な依存の不在」を示すもので、データ競合は見ません。**

| 対象 | Phase 4 での扱い |
|---|---|
| `PointCache` / `wcache` | **スレッド局所。** 命中率のために共有した瞬間に競合が入ります |
| `BoolStats` | スレッド局所に貯めて集約 |
| 出力バッファ | スレッドごとに貯めて結合 |

**「スレッド局所で足りる」は保証ではなく設計方針です。** 保つこと自体を Phase 4 の
検査項目にしてください。

#### CP3 の完了判定（判定手順、記録として残します）

**item 1 の完了で CP3 を閉じられます。** item 2 の扱いは下記の検証で決めます。

```
1. item 1（Z^n 化、n 項）が全ケースで通る          → CP3 item 1 完了
2. 「葉の分類が可変な共有状態に触れずに書けるか」を検証
     書ける  → item 2 を Phase 5（性能目標）へ降格。CP4 へ進む
     書けない → item 2 が Phase 4 の前提。§14 の前提条件を先に確かめてから着手
```

**§15 の退避条件 2 が該当する場合は、そこで報告してください。**

### CP4 — 局所 BSP

過剰分割を局所 BSP に置き換える。**断片数の比を報告。**

### CP5 — 全域

全ケース × 全演算 × 固定深度 0〜3 + 適応分割 × 分裂 on/off。

## 15. 退避条件

**Phase 3 に中止条件はありません**（Phase 1 のような分岐ではないため）。
ただし想定が破れたときの退避先を決めておきます。

| # | 想定が破れた場合 | 退避 |
|---|---|---|
| 1 | **§3.1.2 の導出が誤りで、$b{=}26$ が 4 リムに収まらない** | $b$ の上限を 21 にする。または辺平面の構成を見直す |
| 2 | WNV の実装が想定より大きく、CP3 が長期化 | **CP1 / CP2 を先に閉じて別 PR にする。** 段 0 と分離は独立に価値がある |
| 3 | 局所 BSP で凸性が保てない | **CP4 を見送り、過剰分割のまま Phase 4 へ。** 断片数の代償を受け入れる |
| 5 | **セグメントトレースが退化コーパスで成立しない** | **大域レイキャストのまま Phase 4 へ。** 並列化の障害でないことを確認したうえで、item 2 を Phase 5 へ降格 |
| 4 | 面の自己交差の分解が難しい | **拒否**（§4.2）。コーパスから外し、入口の検査項目として記録 |

**1 が最も影響が大きい**ので、CP1 で最初に確かめてください。
