## 2. 設計判断と根拠

### 2.1 絞り込みを実行時パラメータにした ★

`boolean_op` の `cull_planes` を**実行時引数**にしました。既定は有効です。

**理由は検証の構造です。** §0.1 が言うとおり「Phase 1 の実装がそのまま Phase 2 の
正解器」なので、絞り込みを無効にした側と有効にした側を**同一プロセス内で突き合わせれば、
§9.1 の分割戦略不変性がそのまま検査になります。**

- **代案**: コンパイル時のフラグにする
  → 1 回の実行で両者を比較できません。**深度を実行時パラメータにした理由
    （`SPEC-phase1.md` §2.2）とまったく同じ構図**です。同じ罠を 2 度踏まないために、
    最初から実行時にしました
- **代案**: 絞り込みなしの経路を消す
  → 正解器を失います。**固定深度モードと同じく、消してはいけない資産**です

### 2.2 判定は 8 隅ではなく「符号で `lo`/`hi` を選ぶ」

`N・x + d` の最小値と最大値は、$N$ の各成分の符号に応じて `lo` / `hi` を選べば
**内積 2 回**で出ます。8 隅を回る必要はありません。

- **代案**: 8 隅すべてを評価する
  → 4 倍の計算量。しかも**この経路を正解器に回せます。** 実際 `test_plane_box.cpp` の
    正解器は 8 隅版で、被検体と**選択の論理を共有していません**。
    「同じ変形を使う正解器は正解器ではない」（`CLAUDE.md`）を満たすために、
    速い側を本体・素朴な側をテストに置く形にしました

**成分が 0 の軸はどちらを選んでも同じ**なので、`sign >= 0` の一括判定で足ります。
場合分けを増やすと、その分岐自体がテストの対象になります。

### 2.3 深度 0 でも絞り込みを走らせる

深度 0 はセル 1 個なので、絞り込みは何も落とさないはずです。**それでも通します。**

落ちないことが**番人**になるからです。入力座標は必ず座標範囲内にあり、そこから作った
平面は深度 0 のセル（座標範囲全体）と必ず交わります。**深度 0 で 1 枚でも落ちたら、
それは判定が壊れている証拠**です（実測は 540/540 = 100%）。

分岐で深度 0 を素通りさせると、この検査を失います。

### 2.4 CP1 では $(C, \chi)$ より強く $(V, E, F)$ の一致を要求した ★

§9.1 が要求するのは体積と $(C, \chi)$ の一致ですが、**CP1 に限ってはもっと強い形が
成り立つはずです。**

§2.3 の絞り込みが落とすのは「セルの閉包と交わらない平面」だけです。断片はセルの閉包に
含まれるので、そういう平面では**そもそも切れません**。つまり絞り込みは **no-op な分割を
省いているだけ**で、断片の集合は完全に同一になります。

したがって $(V, E, F)$ と断片数まで一致するはずで、実際に一致しました（§4）。

> **CP2 で緩めるのは「三角形分割が変わったとき」だけです。** 適応分割は断片の切り方
> そのものを変えるので、そこでは $(C, \chi)$ と体積に緩めます。
> **CP1 の段階で強い形が落ちたら、それは「緩めるべき」ではなく
> 「絞り込みが no-op でないものを落とした」の合図**です。この区別を先に決めておかないと、
> 失敗したときに検査のほうを弱めて通してしまいます。

### 2.5 「絞り込みが実際に効いている」ことを検査する

**何も落とさなくても §9.1 は通ります。** そのとき検査は「常に同じ結果」を確かめている
だけで、§2.3 の正しさを一切検証していません。

これは `SPEC-phase1.md` §9.0 の番人（深度を上げても断片が増えないと検査が空回りする）と
**同型の罠**です。Phase 1 で実際に踏んでいるので、今回は最初から番人を置きました。

- 深度 0 では 1 枚も落ちないこと（2.3）
- 深度 1 以上では必ず落ちること
- 残存率が深度とともに**単調に下がる**こと（セルが小さくなるので下がるはず）

### 2.6 (b) セル面平面 — 案 D を採った ★

**仕様の初版は案 A（2:1 バランス八分木）から試すことを勧めていましたが、
成立しないと判断しました。** 仕様担当がこれを受けて §2.4 を改稿し、
**案 D（縫合後に T 頂点を解決する）が採択されました。**

#### なぜ案 A が成立しないか

**共有面 $F$ は正の面積を持つので、十分細かいレベルのグリッド平面は必ず $F$ を
横切ります。** ここから 2 つの経路のどちらもふさがります。

| 経路 | 帰結 |
|---|---|
| §2.3 の基準をセル面平面にそのまま当てる | 整合はする。**しかし平面は無限に延びる。** 木のどこかに深い領域があれば、そのレベルのグリッド平面は遠方の粗いセルも貫く。節約が消えて一様グリッドと同じになる |
| 「レベル $L(C)$ 以下」に弱める | $L(C) \ne L(C')$ なら差のレベルの平面が片側にしか無く $F$ 上で不整合。よって隣接する葉すべてで $L$ が等しく、**葉の隣接グラフは連結なので $L$ は大域定数** |

**2:1 バランスは救いになりません。** バランスが縛るのは**隣接セルの深さの差**であって、
**木の大域的な深さの幅**ではないからです。深度 1 の葉と深度 8 の葉が同じ木に共存する
ことは 2:1 バランスと矛盾しません（間に段階的な遷移が入るだけ）。そして深度 8 の
グリッド平面は、その遠方の深度 1 の葉も貫きます。

**具体的な反例**（2:1 バランスを満たす配置）。深度 $d$ の葉を「自分の中央面 3 枚」で
切る規則にすると、同深度の隣接とは整合します（両者の中央面が同一平面のため）。
しかし深度 $d-1$ の粗い隣接とは整合しません。粗い側を合わせるにはレベル $d+1$、
つまり**そこから見て 2 段細かい平面**が要り、要求が伝播します。

#### 案 C の懸念は正確ではありませんでした

仕様の初版は案 C（共有面の上だけ局所的に合わせる）を「凸性が崩れる」としていましたが、
**崩れるのは凸性ではありません。** 辺の途中に頂点を入れても多角形は弱く凸のままで、
扇分割も使えます。

**実際に壊れるのは `Fragment` の辺平面列の表現です。** 辺 $P$ の途中に $G$ との交点を
入れようとすると辺列が `[…, P, G, P, …]` になり、$P \cap G$ と $G \cap P$ が同一点に
なって長さ 0 の辺ができます。

**この制約は縫合後の頂点 ID 列には効きません。** そこが案 D の入口です。

#### 案 D を採る理由

| 理由 | 内容 |
|---|---|
| 節約が残る | グリッド平面を共有しないので、適応分割の利得がそのまま出ます |
| 新しい幾何を作らない | 挿入する頂点は**細かい側が既に作ったもの**。3つ組 $\{P,Q,G\}$ が一致するので §5.3 の第1段で既に同じ ID です。「挿入」は既存 ID を並べ直すだけ |
| 新しい述語が要らない | 索引と `cmp_h` だけ。ビット幅の再導出が不要 |
| **失敗が静かにならない** | 入れ損ねれば辺の次数が 1 になり `edge_manifold` が落ちます。**これが主要な理由です** |

**案 B は退避先として残します**（§2.5）。確実に成立し、しかも §2.3 のメッシュ平面の
絞り込みは残るので、大域平面集合に戻す退避を支配します。

#### 2.6.1 順序の決定 — 正準化を先、T 解決を後 ★ 確定

§2.4.4 (1) と §12 が求めている決定です。**この順序で実装しました。**

```
4 縫合 → 5 正準化（重複・共平面の対応付け） → 6 分類・選択 → 7 T 解決 → 三角形化
```

**正準化を先にする理由。** `region_key` は縫合後の頂点 ID 集合です。適応分割では、
同一領域が 2 つのセルに重複割り当てされたとき、**隣接の細かさが違えば入る T 頂点が
違い得ます。** T 解決を先にすると、その 2 つのキーが食い違って重複が併合されず、
同じ面を二重に出力します。正準化を先にすれば、キーは元の頂点集合で決まるので
この経路が塞がります。

**T 解決は出力多角形すべてに一律に適用します。** 「隣が持っているから入れる」ではなく
**「線分の内部に載る大域頂点はすべて入れる」**という形にすること。片側だけに入れると
**T 字接合を直すどころか作ります**（辺 $(a,b)$ が片側で $(a,m),(m,b)$ になり、次数 1 の
辺が 3 本できます）。一律なら、同じ辺を共有する多角形は必ず同じ頂点を得ます。

### 2.7 扇分割の退化判定を【組合せ】で行う ★

§2.4.4 (2) は「面積 0 の三角形を捨てること」「判定は投影面での `orient2d` で厳密にできます」
と書いていますが、**`orient2d` では足りません。**

既存の `orient2d_h` は `(IPoint, IPoint, HPointD)` の形で、**同次点を 3 つ**取れません。
T 頂点を含む多角形の 3 頂点はすべて構成点なので、素直にやると
**同次点 3 つの 2D 向き**という新しい述語が要り、ビット幅の導出が必要になります。
§2.4.3 の「新しい述語は要りません」と衝突します。

**幾何を見ずに済みます。** 扇の起点は元の角なので、起点と共線になり得るのは
**起点に接する 2 本の元の辺の上にある頂点だけ**です。そこで各頂点に

- 角なら「元の頂点添字 $i$」（辺 $i-1$ と辺 $i$ の上にある）
- T 頂点なら「載っている元の辺の添字 $j$」

を持たせ、「三角形の後ろ 2 頂点が同じ元の辺の上にあるか」で判定します。**厳密で、
述語を 1 本も足しません。**

- **代案**: 同次点 3 つの `orient2d` を新設する
  → ビット幅の導出が要る。しかも構成点 3 つの行列式は幅が大きく、`kTriOrient2dH`
    （$20b{+}43$）規模になります。**捨てる三角形を見つけるためだけに、Phase 0 最大級の
    述語を足すことになります**
- **代案**: 退化を捨てずに出す
  → §10.1 の位相検査に面積 0 の面が残ります。§2.4.5 が「退化三角形を残した」を
    検出対象に挙げているので、捨てるのが仕様の要求です

> **仕様への指摘**（§7.2 の #3）。§2.4.4 (2) の「投影面での `orient2d` で厳密にできます」は、
> 同次点を 3 つ取る述語が既存に無いため、そのままでは実装できません。
> **組合せで判定できるので、新しい述語は不要です。**

## 3. 新規述語のビット幅

§7 の手順どおり、**先に導出して `geom/widths.hpp` に定数を足してから**実装しました。

| 述語 | 上界 | b=21 実測 | b=26 実測 | リム |
|---|---|---:|---:|---:|
| 平面とセルの閉領域の交差 `3b+7` | $3b+7$ | 65 / 70 | 80 / 85 | 2 |

**上界超過はゼロです。** 実測は乱択の到達値なので、リム数は減らしません
（`SPEC-phase0.md` §3.4）。

**セル座標が `b+1` ビットであることが導出の要点**です。深度 $k$ の境界
$-2^{b-1} + m \cdot 2^{b-k}$ は $m = 2^k$ で $+2^{b-1}$ に達し、
`kCoordMax` $= 2^{b-1}-1$ を超えます。`side(plane, IPoint)`（$3b+6$）を流用できないのは
このためで、**受ける座標の範囲が違う別の述語**として立てました。

| テスト | 期待 | 実測 |
|---|---|---|
| `split_strategy` | FAIL | **118 / 1303** |
| `cp1` | FAIL | 6 / 28 |
| `cp2` | FAIL | 10 / 526 |

冪等性が素通りするのは Phase 1 の 3 変異とまったく同じ理由です
（比較の両側に同じ変異がかかるので差が出ない。`IMPL-phase1.md` §5.7）。
**構造的な盲点なので、記録して固定します。**

### 5.1 変異 3 と変異 4 は、5 つのコーパスで失敗件数が完全に一致します

| テスト | 変異 3 | 変異 4 |
|---|---|---|
| `cp1` | 6 / 28 | **6 / 28** |
| `cp2` | 10 / 526 | **10 / 526** |
| `cp25` | 12 / 290 | **12 / 290** |
| `cp3` | 96 / 1719 | **96 / 1719** |
| `depth_monotonic` | 4 / 219 | **4 / 219** |

偶然ではありません。既定（絞り込み有効）では**両者の分割平面集合が一致する**ためです。

- 変異 3 は大域集合を割り当て集合に置き換え、その上に §2.3 の絞り込みがかかる
- 変異 4 は絞り込みの基準を割り当て集合に差し替える（§2.3 は通らない）

差は「割り当て集合のうちセルの閉包と交わらない平面」だけで、それは **no-op なので
出力に影響しません**（2.4 と同じ理屈）。仕様が「Phase 1 の変異 3 と同型」と書いている
とおりの結果です。

**したがって、この 5 つは 2 つの変異を区別していません。** 区別しているのは
`split_strategy` だけで、これは絞り込み無効側を正解器として直接突き合わせるためです。
**変異 4 を別立てにする価値は `split_strategy` の 118 件にあります。**

> **仕様担当への確認事項**（§7.2）。`split_strategy` を変異 3 にも登録すべきか、
> あるいは 5.1 の同一性を記録したうえで現状のままとするか。
> **「変異が 2 件ある」ことと「2 件が別の誤りを捕まえている」ことは別です。**

### 6.1 開発コンテナが空になっている前提で始めること

コンテナを作り直すと、`IMPL-phase0.md` §8 の構成（cmake / ninja / clang / GMP）は
**すべて消えます。** 今回は次の形で立て直しました。`sudo` / `apt-get install` /
`pip install` はいずれも `settings.json` の deny 対象なので、**deny は緩めていません。**

| 要素 | 手段 |
|---|---|
| cmake / ninja / clang | `uv` で venv を作り、`cmake` / `ninja` / `ziglang` を入れる |
| GMP（テスト専用） | **`apt-get download`**（`install` ではない）→ `dpkg-deb -x` でホームに展開 |
| 永続化 | `/etc/sandbox-persistent.sh` に `export` だけを追記。**補完スクリプトは絶対に足さない** |

### 6.2 `zig c++` の共有キャッシュが cold のとき、並列ビルドが固まって見える ★

**前回のセッションはここで応答が止まり、3 回の再起動に至りました。** 原因を実測で
切り分けたので記録します。

| 仮説 | 実測 | 判定 |
|---|---|---|
| メモリ枯渇 | コンパイル 1 本の最大 RSS **38 MB** | ❌ |
| ソースが virtiofs マウントで遅い | configure + 1 ターゲットで 3.7 秒（overlay は 2.9 秒） | ❌ 差は小さい |
| テストが重い | 変異 22 件で **1.08 秒** | ❌ |
| **zig の共有キャッシュが cold** | **リンク 1 本で 実時間 8.6 秒 / CPU 35.5 秒、キャッシュ 85 MB を生成** | ✅ |

`zig c++` はリンク時に libc++ と compiler-rt を**自前でビルドして共有キャッシュに
入れます。** しかもその内部で 4〜6 スレッドを使います。`cmake --build` の既定並列度は
コア数（この環境では 16）なので、cold cache から 22 ターゲットを一気にビルドすると
**16 個のリンクがそれぞれ内部で libc++ を並列ビルドし、同一キャッシュのロックで
直列化します。** CPU は 100% のまま ninja の進捗が長時間止まります。

**手順（この形で全工程が 2 分未満になりました）:**

1. **ウォームアップを 1 本だけ単独で通す**（`--target <1 つ> -j 1`）。ここで libc++ が
   1 回だけ焼かれ、以後は共有されます。**これが最重要**
2. **`-j` を明示して絞る**（4 程度）。既定のコア数を使わない
3. **ビルドもテストもバックグラウンド実行 + ログファイル。** 前面で待たない。
   止まったときにどこで止まったかが残ります
4. **テストは 1 件ずつ時間制限つきで回す。** 22 件を 1 コマンドにまとめない
5. ビルドツリーは overlay 上に置く（`-B ~/kb/...`）。速度差は小さいものの、
   **`CLAUDE.md` の「ninja が再ビルドを取りこぼす」（マウントの mtime 粒度）を
   構造的に避けられます**

> **キャッシュはコンテナと一緒に消えます。** 次にゼロから立ち上げるときも
> 手順 1 から始めてください。

**(1) B は A の面を【またがせる】。内部に浮かせない ★**

#### 判定点は `lo` 隅 — 契約が満たされる理由

**セルの `lo` 隅（整数点）で判定します。** `hi` 隅は $+2^{b-1}$ になり得て `IPoint` に
入りませんが、`lo` 隅は必ず範囲内です。

**`lo` 隅が $\partial B$ の上に無いことは、割り当てが保証します。** $\partial B$ が
隅を含むなら、その面の AABB は隅を含むので割り当てられ $n_B > 0$ になり、early-out は
発火しません。したがって `point_inside` の契約（判定点が境界上に無い）が満たされます。

**半開区間（§3.4）でも成り立ちます。** 面が交わるのが `hi` 側の境界だけなら
$n_B = 0$ になり得ますが、そのとき `lo` 隅は反対側の角なので $\partial B$ に載りません。

| `adaptive` / `cp3` / `depth_monotonic` | PASS（素通り） | early-out 無効なので変異が発火しない |

**役割が違います**（`SPEC-phase1.md` §10.2 の但し書き）。位相は「割れているか」しか見ず、
体積は「別の立体を作っていないか」しか見ません。**early-out の誤りは分類の誤りなので、
体積が本来の担当です。**

> GMP OFF なので、そちらの件数は決定的です（46 件）。

### 7.10 §4 — 構成点の保持。**Phase 1 の前提を作り直しました** ★

#### 昇順に正規化してから `intersect3` を呼ぶ ★

`intersect3` は引数の順序で符号が変わります（行列式の置換）。$V$ と $-V$ は同じ射影点で、
**すべての述語が `sign(w)` を掛ける形になっているので符号は結果に影響しません。**

それでも**キャッシュの有無にかかわらず常に昇順で評価**します。そうすれば
**出力が 1 ビットも変わらず**、§9.1 の比較を**値の完全一致**まで強められます。

**$(C,\chi)$ で緩めてはいけません。** 緩めると §9.3 の変異 7（キーから 1 平面を落とす）が
「別の三角形分割になっただけ」に見えて素通りし得ます。

> **既存の 30 テストは昇順化だけでは 1 件も落ちませんでした。** 符号が変わり得る値を
> 返すようになりましたが、述語がすべて不変だからです。**測って確かめています。**
