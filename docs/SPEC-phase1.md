## 0. この文書の位置づけ

**Phase 1 は機能を作るフェーズではありません。判断を下すフェーズです。**

問うのはただ一つ。

> **セルごとに独立に解いた局所 arrangement を、割れのない単一の多様体メッシュに
> 縫い合わせられるか。**

できるなら EMBER 系を続行します。できないなら **EMBER を断念し、`csg/` を
Manifold（Apache-2.0）のラッパとして実装します。**

この判断を **最小のコストで、できるだけ早く** 下すことが本フェーズの唯一の目的です。
機能の完成度、性能、汎用性はすべて二の次です。

前提として `SPEC-phase0.md` の算術基盤と述語が使えることを想定します。
`IMPL-phase0.md` §7「Phase 1 への申し送り」も先に読んでください。

## 1. なぜ出力抽出を先にやるのか

EMBER の実装で先行事例が一つあります。Blender が採用を検討し、**断念しました。**

> 論文のアルゴリズムが終わった後に、まともな連結メッシュを得るのがかなり難しいことが
> 分かってきたので、Ember ソルバーは保留にした。代わりに Manifold ライブラリベースの、
> 非厳密だが非常にロバストなソルバーに切り替えた。

書いたのは Blender のブール演算を長年担当してきた開発者です。**論文の中核部分ではなく、
その後の出力抽出で詰まっています。**

第三者からも同じ箇所への指摘があります。

> 並列化のために入力メッシュを小ブロックに分割する結果、継ぎ目でトポロジー不整合が生じる。

**既知の失敗モードは「セル境界の継ぎ目」に集中しています。**

通常の実装順序（算術 → 分割 → 局所演算 → 出力抽出）だと、この一番危険な部分が最後に来ます。
数ヶ月かけて土台を作ってから撤退判断、が最悪のシナリオです。

**だから順序を逆にします。** Phase 1 は、他をすべて最小構成に固定したうえで、
継ぎ目だけを変数として残します。

### 1.1 「EMBER の再現」ではありません

EMBER / OEBSP の論文 PDF は現時点で入手できていません。したがって Phase 1 で作るのは
**「EMBER 的な手法」** であって EMBER そのものではありません。

それでも判断材料としては有効です。問い（セル分割した局所解を割れずに縫えるか）は
論文の細部に依らないためです。**論文が入手できたら Phase 2 の冒頭で照合してください。**

## 2. スコープ

### 2.1 やること

| 項目 | 内容 |
|---|---|
| 入力 | 閉じた多様体三角メッシュ 2 つ。整数格子上 |
| 規模 | 三角形数 100 未満を想定（立方体 = 12） |
| 空間分割 | **固定深度**の八分木。適応分割なし |
| 演算 | union / intersection / difference |
| 意味論 | **正則化ブール**（§2.3） |
| 分類 | 厳密。浮動小数点を使わない |
| 出力 | 連結・多様体・watertight・正しく向き付けされた三角メッシュ（例外は §9.3） |
| 実行 | 単スレッド |

### 2.2 分割深度

適応分割と early-out は**最適化**です。これらを入れると、失敗したときに原因が
「分割の判断」なのか「抽出」なのか切り分けられません。**分割を定数に固定して、
抽出だけを変数にします。**

**深度は実行時パラメータです。** `KRISITE_P1_DEPTH`（CMake、既定 2）が既定値を与え、
実行時引数で上書きできること。

コンパイル時定数にしてはいけません。本フェーズの中心的な診断は
**「深度 0 の出力と深度 2 の出力を同一プロセス内で比較する」** ことであり、
これは実行時パラメータでなければ成立しません。

深度 0（セル 1 個、分割なし）でも動くこと。**深度 0 で通り深度 2 で割れるなら、
原因は確実に縫合です。** この対照が Phase 1 の診断能力の中心です。

**検証範囲は深度 0〜3。** 深度 4 は動けばよい、程度の扱いで構いません。

### 2.3 意味論 — 正則化ブール

**測度 0 の結果は空とします。**

面接触・辺接触・点接触のみの $A \cap B$ は、**空メッシュを返してください。**
2 次元パッチや線分を出力してはいけません。

理由:

1. **多様体出力が絶対条件です。** 2 次元パッチは立体境界として多様体になりません。
   §10.1 の検査体系が丸ごと崩れます
2. EMBER も Manifold も立体を出します
3. **非正則の結果は次のブール演算に入力できません。** CSG ツリーが組めなくなります
4. 体積恒等式（§10.3）は正則化でも成立します（測度 0 は体積 0）

**注意: $A \cup B$ の面接触は空ではありません。** 単一の立体になり、
**接触していた面は内部になるので除去されなければなりません。**
これは共平面重複の処理そのもので、ケース 5 と並ぶ重要な検査対象です。

## 3. 平面ベース表現

### 3.1 平面 ID — 正規化しません

入力の全三角形から支持平面を作り、`PlaneId`（`uint32`）を振ります。
**同一平面は必ず同一 ID に統合してください。**

**GCD による正準化は行いません。** 除算・剰余・GCD は `arith/` に存在せず、
Phase 1 のために算術基盤へ新しい演算を追加するのは割に合いません。

代わりに、**比例判定と交差乗算による全順序**で ID を割り当てます。

**比例判定** — $[a,b,c,d]$ と $[a',b',c',d']$ が同一平面 $\iff$ 2×2 小行列式 6 本がすべて 0:

$$ab' - a'b,\quad ac' - a'c,\quad ad' - a'd,\quad bc' - b'c,\quad bd' - b'd,\quad cd' - c'd$$

最大幅は $ad' - a'd$ 系で $(2b{+}3) + (3b{+}5) + 1 = \mathbf{5b+9}$（$b{=}21$ で 114 ビット、2 リム）。

**全順序** — 符号を正規化（最初の非零成分を正に）したうえで、最初の非零成分の位置で比較し、
同じなら比 $a_j / a_i$ を交差乗算 $a_j a'_i$ vs $a'_j a_i$ で比較。
最大幅 $\mathbf{6b+11}$（$b{=}21$ で 137 ビット、3 リム）。

**ID 割り当て**は全平面を整列して隣接併合。三角形 100 未満なら $O(n \log n)$ 回の比較で終わります。

> **Phase 2 以降への申し送り**: 正規化しないため、ID 割り当てが「ハッシュ」ではなく
> 「整列＋併合」になります。平面数が増えると比較コストが効いてきます。
> GCD 正準化の再検討点として記録してください。

**向きの扱い**: 符号正規化で平面から向きの情報が消えるので、
**三角形側に「平面に対して表か裏か」のフラグを持たせてください。**

### 3.2 セル面も平面である

八分木のセル境界は軸平行平面です。**セル面を `PlaneId` 空間の一員として扱ってください。**
そうするとセル境界上の点も「3 平面の交点」という同じ枠組みに収まり、特別扱いが不要になります。

**軸平行平面の直接構成関数が必須です。**

深度 $k$ の境界座標は $-2^{b-1} + m \cdot 2^{b-k}$（$m = 0 \ldots 2^k$）で、
**最大値 $+2^{b-1}$ は `kCoordMax` $= 2^{b-1}-1$ を超えます。**
`plane_from_triangle` では作れません（`IPoint` に置けないため、検査ビルドで停止します）。

したがって:

- セル境界の座標は **`IPoint` ではありません。** `std::int64_t` 等、$2^{b-1}$ を表現できる型で持つこと
- `geom/` に軸平行平面の直接構成関数を追加すること。
  $N = (\pm 1, 0, 0)$ 等、$d = \mp c$。**ビット幅は $b+1$ で既存の `kOffset` に自明に収まります**

軸平行平面は述語のビット幅が劇的に小さくなります。Phase 1 では最適化しませんが、
**この性質は記録しておいてください**（Phase 2 で効きます）。

### 3.3 頂点

```cpp
enum class VertexKind { Input, Constructed };

struct Vertex {
    VertexKind kind;
    IPoint     ip;              // Input のとき
    PlaneId    tri[3];          // Constructed のとき（昇順に正規化）
    HPoint<..> hp;              // 遅延評価してよい
};
```

入力頂点は**整数座標のまま保持してください。** 述語のビット幅が段違いに小さくなります
（`side(plane, IPoint)` は 2.35 ns、`side(plane, HPoint)` は 7.80 ns。BENCH.md）。

### 3.4 向き付けの規約

**入力メッシュは「外から見て CCW」= 外向き法線とします。**

$N = (p_2 - p_1) \times (p_3 - p_1)$、平面は $N \cdot x + d = 0$、$d = -N \cdot p_1$。
外側の点 $p = p_1 + tN$（$t > 0$）について

$$N \cdot p + d = N \cdot p_1 + t|N|^2 - N \cdot p_1 = t|N|^2 > 0$$

したがって **`side(plane, p) > 0` が外側**です。これは取り決めではなく導出結果です。

入力がこの規約を満たすことを、パイプライン先頭で検査してください
（符号付き体積が正であること）。満たさない入力はエラーにします。

### 3.5 入力を「平面ごとの多角形」に併合すること

**§3.1 の平面 ID 統合だけでは足りません。同一平面上の隣接三角形を 1 枚の多角形に
併合し、三角形分割の産物である辺を消してください。**

理由は性能ではなく**表現上の必然**です。

立方体の 1 面を 2 三角形のまま扱うと、その**対角辺**は両側が同一平面なので
**2 平面の交線として表せません。** したがって対角辺上に生まれる交点は
「3 平面の交点」の枠に収まらず、**§3.3 の頂点表現が破綻します。**

併合すれば多角形の各辺は必ず別の平面を持つ隣接面と共有されるので、

- 辺 = 2 平面の交線
- 頂点 = 3 平面の交点
- クリップで生まれる頂点 = (支持平面, 辺の平面, 切断平面)

となり、**表現がクリップについて閉じます。**

成立しない代案:

| 代案 | 破綻する理由 |
|---|---|
| 三角形のまま、入力辺を特別な辺種として持つ | クリップで生まれる頂点が 3 平面の交点にならず `intersect3` が使えない |
| 対角辺の両側に同一平面を割り当てて交線を退化させる | `intersect3` の前提（3 平面が一点で交わる）が破れる |

**Phase 1 の制約: 併合後の多角形が凸であることを要求します。** §4.3 の「凸なので扇でよい」
はこの前提です。コーパス（立方体・四面体・量子化した回転立方体）はすべて凸面なので成立します。

一般のメッシュでは非凸の平面パッチや穴あきパッチがあり得ます。**Phase 1 では停止させ、
黙って間違えないようにしてください。** Phase 2 の解法は 2 択です。

| 解法 | 代償 |
|---|---|
| 非凸パッチに CDT を入れる | 実装量。Cherchi / Levy が論文を費やしている部分 |
| 対角辺に正準な仮想平面を与える（面法線 × 辺方向） | ビット幅が $4b+6$ に伸び、下流の再導出が要る |

CP2 で非凸が実際に出てから決めてください。

> **併合は入力の三角形分割を保存しません。** 多角形の扇分割は入力の対角線と一致するとは
> 限らないので、**§10.2.2 の深度 0 の比較対象に注意してください。**

## 4. パイプライン

### 4.1 全体の流れ

```
1. 平面抽出・ID 付与（§3.1）
2. 固定深度で八分木を構築。各セルに三角形を割り当てる（§4.2）
3. セルごとに局所 arrangement を計算
4. 頂点の同一性を解決して大域メッシュに縫合  ← ★ Phase 1 の本丸（§5）
5. 領域に分割し、内外を分類（§6）
6. 演算に応じて選択・向き付けして出力
```

**手順 4 と 5 の順序に注意してください。** 縫合を先に済ませてから分類します。
分類を先にやるとセルごとに独立した判断が入り、継ぎ目で矛盾する可能性があります。

### 4.2 セル割り当ては閉領域で行う

**三角形をセルに割り当てる判定は、セルの「閉領域」との交差でなければなりません。**

「セルの内部と交差」で判定すると、**幾何が丸ごと消えます。**

境界 $x = m$ にちょうど載る三角形は、下側セルの開領域（$x < m$）とも上側セルの
開領域（$x > m$）とも交わりません。**どちらのセルにも割り当てられず、出力から消滅します。**

> **訂正（第6版）**: 第5版は「片側のセルから漏れる」と書いていましたが、これは
> より軽い別の状況の記述でした。実際には両側から落ちます。
> **ケース 5（面がセル境界と完全一致）が正面から作るのはこの配置です。**

より軽い形として、$F$ 上で接するだけの三角形が片側から漏れ、反対側でその点が別の
平面3つ組から生まれる経路もあります。こちらは §5.2 とは独立に、第1段が取りこぼす
経路がもう 1 本増えることを意味します。

閉領域で割り当てる副作用として、**セル面上にある三角形は複数のセルに重複して割り当てられます**
（面上なら 2 セル、辺上なら 4、頂点上なら 8）。**この重複が生む断片の併合も §5 の対象です。**
ケース 5 で正面から効くので、§5.4 で計数してください。

### 4.3 局所 arrangement の構成方式

各セルについて:

```
1. 割り当てられた三角形を、セルの 6 面（軸平行平面）でクリップ
2. 【両メッシュの全平面】で分割する          ← §4.3.1
3. 断片を三角形化（凸なので扇でよい）
```

**3 次元の領域分解（BSP）は作りません。** §6.1 の「領域」は面断片の話であって
3 次元の区画ではありません。全頂点が「3 平面の交点」か入力頂点に収まるので、
§3.3 の枠組みがそのまま使えます。

**交差線分ではなく平面全体で分割します。** 相手の三角形が実際には届かない場所でも
切るので断片は増えますが、

- 凸多角形を半平面で切ると凸のままなので、**制約付き三角形分割（CDT）が不要**になり、
  扇状三角形化で済みます
- 断片が完全に内側か外側かに決まるので分類が単純になります（§4.3.2）
- 平面ベース表現の枠から出ません

#### 4.3.1 分割平面は【大域集合】でなければなりません ★

**手順 2 で使う平面は、セルに割り当てられた三角形の平面ではなく、両メッシュの全平面です。**

割り当てられた三角形の平面だけを使うと、**継ぎ目に T 字接合が生じます。**

$C_1$ と $C_2$ が面 $F$ を共有し、$B$ の三角形 $T$ が $C_1$ には割り当てられ
$C_2$ には割り当てられないとします（$T$ が $C_2$ の閉領域に届かない）。
$\mathrm{plane}(T)$ は無限に延びるので $F$ を横切り得ます。すると

- $C_1$ は $\mathrm{plane}(T)$ で切る → $F$ 上に頂点が生まれる
- $C_2$ は $T$ を持たないので切らない → $F$ 上に頂点が無い

$F$ 上で **$C_2$ の 1 本の辺が $C_1$ の 2 本の辺に対応**します。幾何的に隙間が無くても、
**辺が 1 面にしか接しない**ので §10.1 の多様体検査に落ちます。

**そしてこの失敗の原因は 4 平面同時交差ではありません。** CP2 が本来問いたいものと
別の理由で失敗し、実験が交絡します。

大域集合を使えば非対称性が消えます。$C_1$ と $C_2$ は同じ平面集合を見るので、
$F$ を横切る平面は必ず両方で切られ、$F$ 上の頂点集合が一致します。

**断片は割り当て集合より増えます。** 「$\mathrm{plane}(T)$ はセルを横切るが $T$ 自体は
届かない」場合がまさに追加分で、これは T 字接合を生んでいた状況そのものです。
つまり**増分は継ぎ目の整合性の対価**であり、避けようがありません。

セルを横切らない平面でのクリップは no-op なので、遠方の平面はコストになりません。
グリッド平面（他セルの面）は同深度ではセル内部を横切らないので、含めても no-op です。

増分の実測は §4.3.3 で行います。**想定を超えるなら Phase 2 の設計情報です**
（適応分割と early-out は、まさにこの無駄を削るための機構です）。

#### 4.3.2 符号ベクトルが内外を決定する

大域平面集合で分割することの副産物です。

**$\partial B$ は $B$ の平面の和集合に含まれます。** したがって $B$ の全平面による空間分割の
各凸領域は、丸ごと $B$ の内側か外側です。そして分割の過程で、各断片は $B$ の各平面に
対する符号を自然に持ちます。

**符号ベクトルが内外を完全に決定します。**

- §6.1 の「領域」= **符号ベクトルが等しい断片の同値類。** 分割の副産物として無料で得られます
- レイキャストは**相異なる符号ベクトルにつき 1 回**だけ
- 断片ごとの重心（$18b{+}36$ ビット規模）も、領域の連結性判定も不要

$\partial B$ 上に載る断片は符号 0 になります。**共平面重複の処理はここで分岐する**ので、
明示的に扱ってください。

#### 4.3.3 断片数を計数すること

Phase 1 に性能要件はありませんが、**断片数は計数して報告してください。**

深度 0 では全平面が単一セルを横切るので断片数が最大になります。三角形 $n$、
相手平面 $k$ で $O(nk^2)$ 規模です。立方体（相異なる平面 6 枚）なら些細ですが、
コーパス上限（三角形 100）では効きます。

とくに §5.4 の総当たり計測は $V \times P$ なので、$V$ が跳ねると計測自体が重くなります。
**想定を超えて増えるなら、それ自体が Phase 2 の設計情報です。**

## 5. 構成点の同一性 — Phase 1 の核心

**この章が Phase 1 のすべてです。他は全部この検証のための足場です。**

### 5.1 問題

セル $C_1$ と $C_2$ が面 $F$ を共有するとき、$F$ 上の頂点は両方のセルで独立に計算されます。
これが同一の頂点だと認識されないと、**継ぎ目が割れます。**

多くの場合、その点は平面3つ組 $\{P, F, Q\}$ の交点として両セルで同じ組から生まれます。
だから**平面 ID の3つ組を昇順に正規化したものをキーにすれば、大半は一致します。**
（これが成り立つ前提が §4.2 の閉領域割り当てです。）

### 5.2 それでは足りない理由

**4 枚以上の平面が一点で交わると破綻します。**

その点は $\{P, F, Q\}$ からも $\{P, F, R\}$ からも生まれ得ます。キーが違うので別頂点と
判定され、そこで割れるか、非多様体になります。

そして **量子化された整数格子では、4 平面同時交差は例外ではなく常態です。**
浮動小数点なら確率 0 の事象が、整数格子では日常的に起きます。CAD 由来のデータでは
軸平行面が多いのでなおさらです。

**ここが Blender の撤退地点だと私は見ています。** 確証はありませんが、症状
（「まともな連結メッシュを得るのが難しい」）と整合します。

### 5.3 二段構えにする

```
第1段（高速路）: 正規化した平面3つ組をキーにハッシュ表で引く
第2段（厳密路）: 全構成点を lex_less で整列し、値が厳密に等しいものを併合。
                 その後 ID を再写像する
```

第2段は `cmp_h` を使うので Phase 0 で最も重い述語（11.25 ns）ですが、
**Phase 1 では性能を問いません。** 素朴に全体を整列して構いません。

### 5.4 必ず実測してほしい数値

| 測る値 | なぜ要るか |
|---|---|
| 構成点の総数 | 分母 |
| 平面3つ組が相異なるのに値が一致した頂点の数 | 第2段の必要性の証拠 |
| **1 点に集まる平面の最大枚数** | 5 枚、6 枚が出るなら設計を見直す必要がある |
| §4.2 の重複割り当てが生んだ重複断片の数 | もう 1 本の取りこぼし経路の寄与 |
| **併合グループの空間的な広がり** | 1 セルとその隣接に収まるか。Phase 3 の並列化構造を決める |
| 上記のテストケース別・深度別の内訳 | 退化配置と深度でどう悪化するか |

**「1 点に集まる平面の最大枚数」は総当たりで測ってください。**
併合された頂点の生成3つ組の和集合を取るだけでは**過小評価になります**
（その点を通るのに、どのセルでも生成に使われなかった平面があり得るため）。
併合後の各頂点について**全平面に対し `side` を評価**すること。
Phase 1 の規模（平面 100 + セル面、頂点 $10^4$ 程度）なら数十 ms で終わり、しかも厳密です。

**この数値が Phase 3（並列化）の設計を決めます。**

> **訂正（第8版）**: 第7版までは「発生率が数 % なら第2段を局所化でき、数十 % なら
> 大域整列が避けられない」と書いていましたが、**基準が誤っていました。**
>
> 並列化で問題になるのは頻度ではなく**局所性**です。値が一致する構成点は幾何的に
> 同一の点なので、**同じセルか、その点を共有するセル（面で 2、辺で 4、頂点で 8）に
> しか存在し得ません。併合は常に局所的に閉じます。**
>
> したがって発生率が 44% でも、セル内 + 境界共有セルとの併合パスで済み、
> 大域整列は不要です。Phase 3 は「セル並列 + 境界併合」の構造で組めます。
>
> **測るべきは併合グループの空間的な広がりです。** すべての併合グループが
> 1 セルとその面・辺・頂点隣接に収まることを確認してください。収まらないものが
> 出たら、それは併合の誤り（本来別の点を同一視した）を疑うべき兆候です。

なお発生率は §4.3.1 の過剰分割によって**上振れします。** Phase 2 の適応分割と
early-out で平面数が減れば下がるので、**悲観側の見積もり**として扱ってください。

### 5.5 やってはいけないこと

- **浮動小数点の近似比較で併合しない。** 許容誤差を導入した瞬間、厳密性という
  このプロジェクトの存在理由が消えます
- **ハッシュで値を比較しない。** 同次座標の有理数を正準形にするには GCD が要り、
  それは併合そのものより高くつきます
- **割れを後段の修復で塞がない。** 割れないことを示すのが Phase 1 の目的です。
  塞いだら何も分かりません

## 6. 分類

### 6.1 方針 — 領域ごとに独立したレイキャスト

**分類は単純に保ちます。** 分類を単純にするほど、失敗したときに縫合が原因だと
言い切れるためです。これは Phase 1 の目的に直結します。

```
1. 面断片を「領域」に分類する
   = B の全平面に対する符号ベクトルが等しいものの同値類（§4.3.2）
   分割の副産物として得られるので、追加の計算は不要
2. 各領域につき 1 回、レイキャストで内外を厳密に判定する
3. 同じ領域内の断片はその判定を共有する
```

**領域は連結である必要はありません。** 符号ベクトルが同じなら $B$ の平面配置の同一の
凸領域に属し、$\partial B$ が $B$ の平面に含まれる以上、内外は一致するためです。

**領域境界を越えるときに反転させる伝播規則は使いません。**

> 第2版はこれを書いていましたが**誤りです。** 反転規則は交差が**横断的**であることを
> 前提にします。$\partial B$ が $\partial A$ に接するだけで貫かない曲線では、
> **その曲線の両側はどちらも $B$ の外側**であり、反転すると間違えます。
> そしてケース 2・3・5・11 はまさにこの配置を正面から作ります。
> 退化を主役に据えたコーパスに対して、分類方式が退化で壊れる設計でした。

領域数は Phase 1 の規模なら高々数十なので、独立にキャストしても性能上の問題はありません。

**断片ごとに毎回キャストしないでください。** 構成点の重心は
$18b+36$ ビット規模（$b{=}21$ で約 414 ビット、7 リム）になり、無駄に重くなります。
判定は領域につき 1 回です。

**キャスト元の断片は、入力頂点（`IPoint`）を含むものを優先してください。**
そうすればレイキャストが整数演算だけで済みます。含む断片が無い領域だけ、
有理数の点にフォールバックすること。

退化（レイが辺や頂点を通る）には記号的摂動で対処してください。

### 6.2 Phase 2 への申し送り

**伝播による高速化は Phase 2 の課題です。** ただし単純な反転規則では成立せず、
**接する交差（非横断）を局所 arrangement から判別できることが前提**になります。

EMBER 本来の分類方式（セル頂点は整数点なので、大域的に効く計算を整数座標で完結させ、
セル内部へ伝播させる）が使える可能性がありますが、**論文が入手できていないため
Phase 1 では採りません。** 論文を入手したら Phase 2 で照合してください。

### 6.3 記録すること

採った方式、種の選び方、摂動の規則を `IMPL-phase1.md` に残してください。

## 9. テストコーパス

### 9.0 サイズの規律 ★ これを外すと検査が空回りします

**八分木は座標範囲全体を分割します。** 深度 $k$ の境界は $-2^{b-1} + m \cdot 2^{b-k}$ で、
$b{=}21$ の深度 2 なら $\{-2^{20}, -2^{19}, 0, 2^{19}, 2^{20}\}$ です。

入力が座標範囲に比して小さいと、**すべてが 1 セルに収まり、深度を上げても断片が増えません。**
このとき §10.2.1 の深度不変性は**通ります。しかし何も検証していません。**

> 実際に踏みました。立方体を 0〜633 に置いたコーパスで、深度 0 と深度 2 の断片数が
> ともに 48。検査は緑。気づかなければ「空回りしている緑」を CP2 まで持ち込むところでした。
> （`IMPL-phase1.md` §6.1）

規律は 2 段構えにします。

**(1) サイズ規律** — 両入力の AABB の和が、**各軸で座標範囲の半分以上**を占めること。
$b{=}21$ なら幅 $2^{20}$ 以上。長さ $2^{20}$ の区間は深度 2 の境界間隔 $2^{19}$ の倍数を
必ず内部に含むので、境界をまたぐことが保証されます。

実データでは量子化がモデルのバウンディングボックスを格子全体に写すので、
**この規律のほうが現実に近い**という点も付け加えておきます。

**(1) は数値的に自動検査してください。** コーパス構築子で assert すること。
座標ビット幅 `b` が変わっても成立するよう、**絶対値ではなく座標範囲相対**で
定義してください（$b{=}26$ の CI で入力が範囲の 1/32 になり空回りした事例があります）。

**(2) 機械的な番人** — こちらが本命です。

> **重複除去後の断片数が、深度 0→1→2→3 で非減少、かつ深度 0→3 で狭義増加すること。**

各段での狭義増加は**要求しません。** 面がセル境界に乗るケース（5・8）では、
その境界平面を §4.3.1 の大域分割が既に使っているため新しい切断が入らず、
$48 \to 48 \to 48 \to 192$ のようになります。ケースの定義そのものから来る性質です。

**判定は必ず重複除去後の断片数で行ってください。** 生の断片数だと、規律違反の配置でも
面がたまたま境界に乗っていれば重複だけで増え、番人が機能しません
（立方体を 0〜633 に置いた配置は $x=0$ に面が乗るため、生の数では $48 \to 60$ と増えます）。

**番人自身が偽陽性・偽陰性を出さないことを検証してください。** 既知の空回り配置を
テストに入れ、番人がそれを検出することを確認すること。

CP の報告には以下を含めてください。

| 指標 | 節 |
|---|---|
| 深度別の断片数（重複除去後） | §4.3.3 |
| 深度別の重複断片数 | §4.2 |
| **深度別の有効セル数**（幾何を含むセルの数） | 分割が働いているかの直接的な指標 |

### 9.1 ケース一覧

**退化配置を主役にしてください。** 一般位置は簡単で、通っても何も証明しません。

> **★ 軸平行な立方体だけでは §5.2（4 平面同時交差）を突けません。**
>
> 1 点を通れる平面は 1 軸につき高々 1 枚（平行な 2 平面は交わらない）で、軸は 3 本だけ。
> セル面が立方体の面と一致しても枚数は増えません。**両者は同一の幾何平面なので
> `PlaneTable` が同じ ID に併合するためです。**
>
> ケース 4（頂点一致）も同じ理由で 3 枚止まりです。軸平行立方体の頂点が一致するなら、
> その 3 平面も一致して併合されます。
>
> **§5.2 を突くには斜面が要ります。** 下表の T 付きケースがそれです。
> これらが通らない限り、Phase 1 の判断材料は得られません。

| # | 構成 | 何を突くか |
|---|---|---|
| 1 | 立方体 2 個、一般位置 | 基本動作。ここで落ちるなら根本的 |
| 2 | 立方体 2 個、面が完全共平面 | 共平面。量子化データの典型 |
| 3 | 立方体 2 個、辺が一致 | 共線 |
| 4 | 立方体 2 個、頂点が一致 | 点の一致 |
| 5 | **面がセル境界と完全一致** | **§5.2 の 4 平面同時交差 + §4.2 の重複割り当て。最重要** |
| 6 | 面がセル境界から 1 格子だけずれる | 5 との対照。ずらしただけで挙動が変わるなら危険 |
| 7 | 格子に量子化した回転立方体 | 軸非平行な平面 |
| 8 | 同一の立方体 2 個 | $A \cap A = A$、$A \setminus A = \emptyset$ |
| 9 | 四面体 2 個 | 鋭角。三角形数が最小 |
| 10 | 一方が他方を完全に含む | **境界どうしの交差曲線が空**。$A \setminus B$ は 2 シェル |
| 11a | **面**接触のみ | 正則化（§2.3）。$\cap$ は空、$\cup$ は接触面の除去 |
| 11b | **辺・点**接触のみ | $\cup$ が非多様体になる。§9.3 参照 |
| 12 | セル境界をまたぐ大きな立方体 | 継ぎ目の本数を増やす |
| **2T** | 共平面接触を斜面で | 共平面重複 × 斜面 |
| **4T** | 四面体 2 個が頂点を共有 | **頂点に 6 平面** |
| **5T** | 立方体 ∪ 四面体、斜面 $x{+}y{+}z{=}0$ をセル角に通す | **4 平面同時交差 + セル境界。§5.2 の本丸** |

**$\cup$ だけが高多重度の同時交差を通りません。** 4T′ では共有頂点が和集合の内部に
入るので $\cup$ が多様体になり、この穴が塞がります。

**T 付きの 3 ケースが §5.2 を突く唯一の手段です**（ケース 7・9 も斜面を持ちますが、
4 平面同時交差が生じるかは配置依存です）。

**5T は計測器の番人でもあります。** 4 枚を検出できることを示さない限り、
他ケースでの「最大 3 枚」という報告は何も言っていないことになります。

**ケース 5 を最優先で通してください。**

各ケースを深度 0 / 1 / 2 / 3 で回すこと。

### 9.2 ケース 10 の期待値

「交差が空」は**境界どうしの交差曲線**の話です。$A \cap B$ 自体は空ではありません。
$B$ が $A$ の内部に完全に含まれるとき:

| 演算 | 結果 | シェル数 | 備考 |
|---|---|---|---|
| $A \cup B$ | $A$ | 1 | |
| $A \cap B$ | $B$ | 1 | **空ではありません** |
| $A \setminus B$ | $A$ の内部に空洞 | **2** | 外殻は外向き、**内殻は内向き** |
| $B \setminus A$ | 空 | 0 | |

$A \setminus B$ が $\chi = 4$ になるケースです（§10.1）。

### 9.3 頂点・辺接触の $\cup$ は合否判定から除外します

**対象: ケース 11b（立方体の辺・点接触）および 4T（四面体 2 個の頂点共有）。**

**2 つの立体が辺または点だけを共有するとき、$\cup$ の出力は非多様体です。** 単一の立体では
ありますが、その辺で 4 枚の面が接します。点接触なら頂点まわりに 2 つの扇ができます。

**正則化（§2.3）では解決しません。** 測度 0 なのは交差であって和集合ではないためです。
これは §2.1「出力は多様体」と §10.1 の多様体検査に正面から矛盾します。

| 演算 | 扱い |
|---|---|
| $A \cap B$ | 空。**通常どおり検証** |
| $A \setminus B$ | $A$。**通常どおり検証** |
| $A \cup B$ | **合否判定に使いません** |

ただし**実行して結果を記録してください。** 何が出るかを知らないまま Phase 2 に
持ち越すと、そこで同じ議論を一からやることになります。落ちたか、非多様体を出したか、
何らかの処理をしたか、`IMPL-phase1.md` に残すこと。

> **$\cup$ を除外しても、これらのケースは価値を失いません。** §5.4 の最大枚数は
> arrangement の性質なので演算に依らず測れます（4T は $\cup$ を除外しても
> 6 枚 / 9 枚を提供します）。

> **Phase 2 への申し送り**: 標準的な解法は**辺・頂点の分裂**（共有辺を 2 本に複製して
> 多様体化する）です。Manifold は多様体出力を保証しているので何らかの処理をしている
> はずで、意味論を決める際の比較対象になります。
>
> **Phase 1 の目的は縫合の可否判定であって、非多様体出力の設計ではありません。**

## 10. 検証

### 10.1 位相（厳密。許容誤差なし）

- すべての辺がちょうど 2 枚の面に接する（watertight かつ辺多様体）
  - **落ちたときは次数を記録してください。** 次数 1 なら**面が欠けている**、
    3 以上なら**面が余分**。$\chi$ が区別しないものをそのまま区別できます。
    これは恒久的な診断として残すこと
- すべての頂点まわりの面が単一の扇をなす（頂点多様体）
- 向きが大域的に整合する
- $$\chi = V - E + F = 2\,(C - g_{\text{total}})$$
  $C$ は連結成分（シェル）数、$g_{\text{total}}$ は各成分の種数の総和。
  **単一シェルの $2-2g$ ではありません。** ケース 10 の $A \setminus B$ は
  外殻と内殻の 2 成分で $\chi = 4$ です
- **出力が空のとき $\chi$ は未定義です。** $V = E = F = 0$ を代わりに検査すること
- 多シェルの場合、**内殻は内向きに向き付けされていること**（符号付き体積の総和が正）

### 10.2 GMP 不要で常時走る検査

**既定のテスト実行（GMP なし）でも走る検査を必ず用意してください。**

#### 10.2.1 深度不変性 ★ 最重要

> **同一ケース・同一演算を深度 0 / 1 / 2 / 3 で実行したとき、連結成分数 $C$ と
> 種数の総和 $g_{\text{total}}$ が一致すること。**

**これが Phase 1 で最も価値のある検査です。** 継ぎ目が割れると位相が変わります
（種数が増える、成分が分裂する）。つまり**縫合の失敗を直接検出します。**
しかも GMP も外部正解器も不要で、深度をまたいだ比較なので分割の粒度に依存しません。

一致しない深度の組が見つかったら、それが §11 の CP2 における failure の証拠です。
**どの深度から崩れるかも記録してください。**

これが成立するのは、深度が意味論に影響してはならないからです。分割は実装の都合であって、
$A \cup B$ の答えが深度で変わるなら、それは定義上の誤りです。

#### 10.2.2 冪等性（深度によって検査を変える）

分割で三角形数が変わるため、**「$A \cap A$ が $A$ と三角形単位で一致」は深度 0 でしか
成り立ちません。**

| 深度 | 検査 |
|---|---|
| 0 | $A \cap A$、$A \cup A$ が **`retriangulate(A)`** と三角形単位で一致 |
| ≥ 1 | $A \cap A$ と $A \cup A$ が**互いに**三角形単位で一致（頂点キーで整列して順序差を吸収） |

> **`retriangulate(A)` は生の入力 $A$ ではありません。** §3.5 の面併合と扇分割だけを通し、
> ブール演算を経ていない $A$ です。
>
> 面併合は入力の三角形分割を保存しません（多角形の扇分割が入力の対角線と一致するとは
> 限らない）。生の $A$ と比較すると、**再分割の差で落ちます。**
> 冪等性の検査としての価値は `retriangulate(A)` との比較で保たれます。

深度 ≥ 1 の比較が成立する根拠は、どちらも同じセル分割を通り、どちらも
「$A$ の全断片を向きそのままで 1 枚ずつ残す」はずだからです。
両者は共平面重複の処理で**逆向きの選択規則**を通るので、規則の食い違いを検出できます。

#### 10.2.3 分割不変な軽い検査

- $A \setminus A$ が空（$V = E = F = 0$）
- **出力面の平面 ID がすべて入力側の平面に属すること**（$A \cap A$ なら $A$ の平面のみ）。
  余計な幾何が混入していないことを安く確かめられます
- §10.1 の位相検査すべて

> **位相検査と体積検査は役割が違います。両方が要ります。**
>
> | 検査 | 捕まえるもの | §10.5 の変異 1 |
> |---|---|---|
> | §10.1 位相 | 縫合の失敗、面の過不足 | **検出** |
> | §10.3 体積 | 断片の選択の誤り（別の立体を作っている） | **素通り** |
>
> 第2段（値ベースの併合）を止めると継ぎ目で頂点が割れますが、**幾何は変わらないので
> 体積は同じです。** 逆に断片の選択を間違えると、位相が整った別の立体ができます。

### 10.3 体積の恒等式（GMP）

符号付き体積を**厳密な有理数**で計算し、以下を検証してください。

$$\mathrm{vol}(A \cup B) + \mathrm{vol}(A \cap B) = \mathrm{vol}(A) + \mathrm{vol}(B)$$
$$\mathrm{vol}(A \setminus B) + \mathrm{vol}(A \cap B) = \mathrm{vol}(A)$$

**共通分母が三角形数に比例して伸びるため、固定幅では計算できません。GMP（`mpq`）を
使ってください。** これは **中止条件 2 には該当しません** — 中止条件はライブラリ本体の
機構についてのもので、テスト正解器には適用されません。正解器が被検体より強い道具を
使うのは正常です（Phase 0 の GMP 差分テストと同じ構図）。

`KRISITE_BUILD_TESTS_WITH_GMP` の既定は OFF のままにします（新規 clone が依存ゼロで
ビルドできるようにするため）が、

- **Phase 1 の開発中は `ON` を既定運用**としてください
- **CI の GMP ジョブはブロッキング**にしてください

#### 解析的な期待体積との比較

**恒等式だけでは足りません。** 恒等式は自己整合の検査なので、系統的な誤りが相関して
入ると素通りし得ます。

コーパスは立方体・四面体なので、$\cup$ / $\cap$ / $\setminus$ の**厳密体積は手で導けます。**
期待値をコーパス定義に書き、比較してください。**答えのレベルで独立した検証**になり、
外部ライブラリもネットワークも要りません。

導出が煩雑なケース（5T など）は恒等式のみで構いませんが、
**導出できるケースには必ず期待値を付けてください。**

### 10.4 外部正解器（Manifold）

> **開発コンテナでは実施できません。** 外部ネットワークが遮断されており、
> `git clone` は `settings.json` の deny 対象です。**deny を緩めないでください。**
>
> **§10.6 の CI ジョブで実施します。** GitHub Actions にはネットワークがあるため、
> 開発コンテナの制約は CI をブロックしません。
> **CI の構築が Manifold 統合の前提条件です。**
>
> CI が整うまでの代替として、§10.1 の**非多様体辺の次数**と §10.3 の
> **解析的期待体積**が同じ問いに答えます。

`KRISITE_BUILD_TESTS_WITH_MANIFOLD=ON`（既定 OFF）でのみ有効化。

- 取得は **CMake FetchContent で特定コミットに固定**（vendoring しない。自前コードとの
  境界を曖昧にしないため。`git submodule add` は `settings.json` の deny 対象です）
- `MANIFOLD_PAR=OFF` / `MANIFOLD_TEST=OFF` / `MANIFOLD_PYBIND=OFF` / `MANIFOLD_DOWNLOADS=OFF`
- **テスト専用。ライブラリ本体から絶対に呼ばない**

浮動小数点なので体積は許容誤差付きの比較になりますが、**種数と連結成分数は厳密に
一致すべき**です。位相が食い違ったら、どちらが正しいか必ず突き止めてください。

### 10.5 変異テスト

**テストが本当に効いているかは、壊してみないと分かりません。** 意図的に誤りを埋め、
検出されることを確認してください。Phase 1 では以下 3 件を必須とします。

> **★ 変異テストはコーパスに依存します。必ず「どのコーパスで検出されるか」を
> 指定してください。**
>
> 実測: 変異 1 を軸平行コーパス（`cp2`）にかけると **382 検証すべて通過**、
> 斜面コーパス（`cp25`）にかけると **98/219 件が失敗**。軸平行では値併合が 0 件
> （第1段が全頂点を捕まえる）なので、第2段を消しても何も変わりません。
>
> **「変異テストがある」ことと「変異テストが効いている」ことは別です。**

| # | 埋める誤り | 検出されなければ |
|---|---|---|
| 1 | §5.3 の第2段（値ベースの併合）を無効化 | コーパスが 4 平面同時交差を突けていない。**斜面コーパス（2T / 4T / 5T）で実施すること。軸平行では素通りします** |
| 2 | §4.2 の割り当てを開領域に変える | セル境界に接する三角形の欠落を検査できていない |
| 3 | **§4.3.1 の分割平面を割り当て集合に変える** | §10.1 の辺検査が甘い。T 字接合は幾何的に隙間が無いため、緩い検査だと素通りします |

3 件目が特に重要です。**Phase 1 が測りたい失敗（継ぎ目の位相不整合）を、
検査体系が実際に検出できることの証明**になります。

各件について、落ちたテストと失敗件数を記録してください。
**複数のテストが独立に検出すること**を確認します（単一テスト依存は脆い）。

### 10.6 CI ジョブの要件

任意フラグの検査は既定ビルドでは走りません。**CI で必ず走らせてください。**

| ジョブ | 構成 | 合否 |
|---|---|---|
| 既定 × プラットフォーム | Linux(GCC) / Linux(Clang) / macOS(Apple Silicon) / Windows(MSVC)。`b=21` と `b=26` | **ブロッキング** |
| GMP | Linux、`KRISITE_BUILD_TESTS_WITH_GMP=ON`（§10.3 の体積恒等式） | **ブロッキング** |
| Manifold | Linux、`KRISITE_BUILD_TESTS_WITH_MANIFOLD=ON`（§10.4） | **ブロッキング** |
| 変異テスト | §10.5 | **ブロッキング** |
| ベンチ | Release | 傾向監視のみ。**合否に使わない** |

**プラットフォーム検証は CI が唯一の根拠です**（SPEC-phase0 §9）。
開発コンテナに GCC / MSVC を入れて代用しないこと。

## 11. チェックポイントと中止条件

### CP1 — 基礎

ケース 1（一般位置）、union のみ、深度 0 と 2。

- 通れば: パイプラインの骨格は成立
- 落ちれば: 縫合以前の問題。設計を見直す

### CP2 — 継ぎ目（軸平行）

ケース 5（面がセル境界と一致）、**3 演算すべて**、深度 0〜3。
**あわせて §5.4 の数値と §9.0 の指標を報告してください。**

> **訂正（第7版）**: 第6版までは「union のみ」「通れば EMBER 続行の判断が立つ」と
> 書いていましたが、**どちらも誤りでした。**
>
> ケース 5 は §9.1 の構造的理由により **§5.2 を突けません。** 突いているのは
> §4.2 の重複割り当てのほうです。したがって CP2 の通過は続行判断の根拠になりません。
>
> また「union のみ」に絞ったことが、選択規則と向き付けのバグ 2 件
> （owner 欠落による断片の黙った破棄、difference の頂点順反転）を隠していました。
> **単一演算だけでは、選択と向き付けのバグが構造的に露出しません。**

### CP2.5 — 斜面 ★ ここが実際の分岐点

**ケース 2T / 4T / 5T、3 演算、深度 0〜3。**

- **深度 0 が通ること**が先決です。深度 0 には継ぎ目がないので、ここで落ちるなら
  arrangement / 分類 / 抽出の中核が壊れています。**§11 の分類では CP1 クラスの失敗**であり、
  縫合の問題ではありません
- 深度 0 が通ったら深度 0〜3 で §10.2.1 の深度不変性を見ます
- **通れば: EMBER 続行の判断が立ちます**
- 落ちれば: §5.3 の第2段を確認して再挑戦

**Phase 1 の判断材料はここでしか得られません。** CP2 を通過しても、
CP2.5 が読めるようになるまでは続行 / 断念のいずれも決められません。

### CP3 — 退化の全域

ケース 1〜12（11a / 11b を含む）+ 2T / 4T / 5T、3 演算、深度 0〜3。
**ケース 11b の $\cup$ は合否に含めず、結果を記録**（§9.3）。

### 深度 0 で落ちたときの切り分け

深度 0 の失敗は継ぎ目の問題ではありません。原因を素早く絞るために、以下の順で試してください。

| # | 試すこと | 落ちたら分かること |
|---|---|---|
| a | **単一メッシュの冪等性**（§10.2.2 を四面体だけで） | ブール演算以前の単一メッシュ処理の問題。**問題空間が半分になります** |
| b | **完全に分離した 2 メッシュ**（期待値 $C=2$、各 $g=0$） | 分類ではなく断片の選択・向き付けの問題 |
| c | **Manifold との差分**（§10.4） | $\chi$ の数字だけでは「余分な面を残した」のか「面が欠けた」のか分かりません |

**c を先に済ませることを勧めます。** §10.4 は完了条件に入っていますが後回しにされがちで、
実際には**この局面で最も投資対効果が高い**道具です。

### 中止条件

以下のいずれかに該当したら、**そこで止めて報告してください。**

1. §5.3 の二段構えを実装しても CP2 の割れが解消しない
2. 同一性の解決に、**ビット幅や反復回数の上界が定まらない機構**が必要になった
3. 4 平面同時交差の発生率が深度とともに発散し、大域整列が避けられないうえに
   その計算量が実用的でない
4. 記号的摂動を入れないと分類が決まらず、かつその摂動が縫合と矛盾する

**2 が最も危険です。** 上界が定まらない機構は、固定幅整数という設計の前提を壊します。
そうなったら EMBER の利点そのものが消えるので、続ける意味がありません。

**この条件はライブラリ本体にのみ適用されます。** テスト正解器が GMP を使うことは
該当しません（§10.3）。

中止した場合、Phase 0 の算術基盤は無駄になりません。GWN の分類器や点群コーデックで
そのまま使えます。**撤退は失敗ではなく、想定された分岐の一方です。**
