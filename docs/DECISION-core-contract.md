EMBER §4.5.4 はこう書いています。

> 各分割ステップが**本質的に純関数**になるよう慎重に設計した。部分問題の結果の多角形は
> 局所データのみに依存する。…この再帰手続きは work-stealing に完璧に適している。

## 2. 軸 1 — 出力契約

### 2.1 現状の帰結

Phase 1・2 で作った機構の大半は、**多様体三角メッシュを出すという契約から派生しています。**

| 機構 | EMBER に無い理由 |
|---|---|
| 頂点の同一性判定（第2段、44% 発火） | 縫合しないので不要 |
| T 頂点解決（案 D） | **T 字接合を出力に残すので不要** |
| 接触の分裂（辺・頂点） | 多様体を要求しないので不要 |
| 三角形化と退化三角形 | **三角形化しないので不要** |
| 位相検査 | soup を出すので検査対象がない |

EMBER §6:

> **出力は三角形化されておらず、T 字接合を含む。** 我々の手法は厳密なので、位相情報は
> **後処理で復元できる。**

**Phase 2 §2.4 で中心課題として解いた T 字接合は、この契約から生じた問題でした。**

### 2.2 ビット幅への影響

EMBER §3.2 が「不可能」と書いている操作を、Krisite は 3 つとも行っています。

| Krisite | EMBER の判断 | ビット幅 |
|---|---|---|
| `cmp_h`（同次点 2 つの比較） | 差は $x_4 x'_4$ を要し固定幅に矛盾 | **300**（5 リム） |
| 中点・重心の述語 | 中点は固定精度で計算できない | **348 / 487**（最大 8 リム） |
| 扇分割による三角形化 | **一般に不可能** | — |

**EMBER は全体で 256 bit に収まります**（入力 26 bit）。Krisite は b=21 で 512 bit まで使います。

> **ただし訂正**: スープ化しても `cmp_h` は消えません。**後処理での頂点併合に必要**です。
> 消えるのは「中核のホットパスから」であって、ライブラリ全体からではありません。
> 中点・重心の述語は §3.4 の手法で不要になりますが、これは軸 2 の話です。

### 2.3 未検証の点 ★

**「スープ → 多様体メッシュ」の後処理は、EMBER も OEBSP も実装していません。**

- EMBER は「後処理で復元できる」と述べるだけで、実装も評価もしていません
- OEBSP はメッシュ抽出を持ちますが、**出発点が BSP であってスープではありません**

つまり **Krisite が後処理を書くなら、先例がありません。** 難度は不明です。
「後処理に回せば楽になる」は、**証明されていない仮定**として扱ってください。

一方で、後処理には有利な点があります。

- 幾何が確定しているので、切断が発生しない
- **Phase 5 のメッシュ化・GWN・非多様体修復と道具が重なる**
- 並列の外側なので、大域状態を持ってよい

## 3. 軸 2 — 分類方式 ★ 影響が最も広い

### 3.1 EMBER の方式

**WNTV（winding number transition vector）と参照点の伝播。**

- 各入力多角形に $\Delta w$（その面を通過したとき巻き数がどう変わるか）を持たせる
- 分割のたびに、**既知の WNV を持つ参照点**を部分問題へ伝播させる
- 葉では、参照点から対象多角形の内部へ**短いセグメントを辿る**だけで分類が決まる

EMBER §3.4:

> レイトレーシングを使うと**分類は大域的な問題**になり効率的な計算が難しい。
> セグメントトレースなら、既知の WNV を持つ参照点が与えられていれば
> **分類を局所問題に保てる。**

### 3.2 これが解く問題は 3 つあります

**(a) 入力制約が緩みます。**

EMBER §3.4 は PWN（区分定数な整数一般化巻き数）メッシュを要求します。

> PWN メッシュは、**明確に定義されたブール演算をもたらす最も制約の緩いメッシュ類**の一つ。
> **自己交差・非多様体・退化した構成の多くが、曖昧さなく扱える。**

**Krisite が閉多様体を要求するのは、符号ベクトルとレイキャストが「内外が定義できる閉曲面」を
前提にしているからです。**

> **「外れる」ではなく「緩む」です。開曲面は開きません**（§4.5 の訂正）。
> PWN は**整数**の巻き数を要求するので、境界を持つ曲面は対象外です。

**(b) 分類が局所化し、並列化が素直になります。**

参照点の伝播により各部分問題が純関数になります。EMBER の work-stealing はこの上に立っています。

**(c) 点群フェーズの GWN と機構が近くなります。**

> **訂正（§4.5 / §8 と整合）**: 当初「GWN モジュールがほぼ同時に手に入る」と書きましたが、
> **言い過ぎでした。**
>
> 段 2 の WNV は**整数**の巻き数で、PWN メッシュに対して定義されます。
> 点群フェーズの GWN は**実数値**で、開曲面や点群のために閾値を伴います。
> **同じ対象ではありません。** 機構は近いので実装は流用できますが、
> **「手に入る」わけではありません。**
>
> そして**メッシュ主体の前提では、この根拠は主要なものではありません**（§8）。

### 3.3 実測が示す優先度

EMBER §5.2:

> 葉の計算では、**分類のセグメントトレースが、対交差の計算と解決のほぼ 2 倍のコスト。**

アブレーション（Fig. 17）でも、最大の 2 つは「分類の高速経路」と「分割の early-out」。

**Krisite が Phase 1 §6.1 で「単純さのため」に選んだレイキャストは、最大のホットスポットに
あたる部分で、EMBER が明示的に避けたものです。**

### 3.4 いますぐ使える技術（軸の選択と独立）

**浮動小数点をヒントに使い、厳密演算で検証する。** EMBER §4.4:

> 通常の浮動小数点数を使って $t$ の重心を計算し、最も近い整数座標 $c$ に丸める。
> …厳密演算を用いてその直線と $t$ を交差させる。

**これで 487 bit の重心述語が不要になります。厳密性は失われません**（検証が厳密なので）。
§2.5 のフォールバック連鎖が 2 度破れた問題も起きません。

**もう一つ**、代表点の構成（EMBER §4.4 の第2の方法）。点を動かすのではなく
**辺平面のオフセットを $d + i$ とずらして交点を取り直す。** 平面ベース表現の中で完結します。

**どちらも軸の選択に関係なく採用できます。** 現状維持を選んでも効きます。

### 3.5 代償

- **新しい機構が大きい。** WNV / WNTV、セグメント表現（4 平面）、3 セグメント経路の構成、
  参照点の伝播
- **新しい述語のビット幅導出が要る**（セグメント–多角形の交差など）
- 符号ベクトルによる分類（§4.3.2）と、それに依存する検査を作り直す

## 4.5 前提の確定 — メッシュ主体

**Krisite の主目的はメッシュ処理であり、出力は三角メッシュ（非多様体も含む）です。**
点群は後から作るもので、メッシュ処理とは独立に扱います。

これで**軸 1 は確定します。スープ出力は採りません。**
ただし §5.4 で段 3 を別の形に読み替えられます。

### 訂正 — 開曲面は段 2 では開きません

前節までで「段 2 で非多様体・開曲面・自己交差が開く」と書きましたが、**誤りです。**

EMBER が要求する PWN は「区分定数な**整数**一般化巻き数」です。開曲面の GWN は
整数になりません（境界付近で連続的に変化する）。**開曲面は PWN ではないので対象外です。**

| 入力 | 段 2 で開くか |
|---|---|
| **自己交差** | **開く** |
| **非多様体**（PWN な範囲で） | **開く** |
| **退化した構成** | **開く** |
| **開曲面** | **開かない。** 実数値 GWN と閾値が要る別の機構（Phase 5） |

**自己交差が開くのはメッシュ処理として直接の価値があります。** EMBER 序文のとおり、
自己交差の修復は「自分自身との和集合」で実現できます。

## 5. 各段の詳細

### 5.1 段 0 — 代表点の構成を平面ベースに戻す

**現状の何が問題か。**

代表点のフォールバック連鎖（`IMPL-phase2.md` §2.5）は 3 段で、2 度破れました。

| 段 | 手法 | ビット幅 |
|---|---|---|
| 1 | 全平面に対して符号が非零の断片頂点 | 既存 |
| 2 | 対角線の**中点** | **348** |
| 3 | 3 頂点の**重心** | **487** |

**2 と 3 は「点を組み合わせる」操作です。** EMBER §3.2 が固定幅で不可能と書いているものに
正面から当たっており、ビット幅の膨張はその代償でした。

#### 5.1.1 主経路 — float をヒントに、厳密演算で検証する

EMBER §4.4 の手順です。

```
1. 多角形 t の重心を【通常の浮動小数点】で計算し、最近傍の整数座標 c に丸める
2. c から、t の法線に最も近い軸に沿った【軸平行な直線】を定義する
3. その直線と t の交点を【厳密演算】で求める
4. 交点が t の内部にあれば、それを代表点として使う
```

**厳密性は失われません。** float は候補を提案するだけで、判定はすべて厳密です。

**そして副次的な利得が大きい。** 軸平行な直線は 2 枚の軸平行平面 $(x{=}c_x,\ y{=}c_y)$ で
表せます。これと支持平面の交点は、**一般の 3 平面交点よりはるかに小さいビット幅**になります。

法線が $(\pm 1, 0, 0)$ の平面は係数が 1 とオフセットだけなので、

$$w = \det(N_p, N_q, N_r)\ \text{の 2 枚が単位ベクトル} \Rightarrow w \text{は支持平面の 1 成分}$$

**$6b{+}12$ ではなく $2b{+}3$ 程度になります。** その先の `side` も同様に縮みます。
**§7 の手順で導出して `widths.hpp` に足してください。** 現状の `kHomoW` / `kHomoXyz` とは
別の、軸平行 2 枚を含む場合の型を用意する形になります。

**失敗するのは、薄い多角形で軸平行の直線が貫かない場合です。** そのときだけ次へ。

#### 5.1.2 予備経路 — 点ではなく【平面を動かす】

EMBER §4.4 の第 2 の方法です。**これが概念的に重要です。**

```
1. t の頂点を 1 つ取る。支持平面 s_t と辺平面 s_e0=(a0,b0,c0,d0), s_e1=(a1,b1,c1,d1) の交点
2. s'_e0 = (a0,b0,c0, d0+i0),  s'_e1 = (a1,b1,c1, d1+i1)   （i0, i1 は 1 以上の乱択オフセット）
3. x = intersect(s_t, s'_e0, s'_e1)
4. x が t の内部でなければ 1 へ戻る
```

辺平面は内部が負側になるよう向き付けられているので、$d$ に正の値を足すと平面が**内側へ動き**、
交点がその角の近傍の内部に入ります。

**ビット幅は一般の 3 平面交点と同じです。** $d$ に小さい値を足すだけなので、
`kHomoXyz` / `kHomoW` は変わりません。**中点や重心のような新しい幅が発生しません。**

刻みを細かくしたければ、EMBER §4.4 のとおり平面係数を精度限界近くまでスケールアップします。
実際には $i_0 = i_1 = 1$ で足り、追加の反復が要るのは特別に構成した角の場合だけ、とあります。

> **概念的な教訓**: **点を組み合わせるのではなく、平面を動かす。**
> 平面ベース表現の中で完結する操作を選べば、固定幅から出る必要がありません。
> Krisite が中点・重心に進んだのは、**表現の外に出る操作を選んだ**からでした。

#### 5.1.3 段 0 で動くもの

| 項目 | 変化 |
|---|---|
| `widths.hpp` | 中点系・重心系の 4 本を**削除**。軸平行 2 枚を含む交点の型を**追加** |
| 最大ビット幅 | **512 → 320**（`cmp_h` が最大になる） |
| `IMPL-phase2.md` §2.5 の連鎖 | 3 段 → **2 段**。しかも 2 段目は幅が増えない |
| 変異テスト | 代表点選択の変異を更新（主検出器の再確認） |
| 検証 | 既存の位相検査・体積検査がそのまま網になる |

**リスクは低い。** 意味論を変えず、既存の検査体系が全部そのまま効きます。

### 5.2 段 1 — 分割の調整

**正直に言うと、段 1 は私が §5 の表で示唆したより小さい**です。八分木を維持する以上、
EMBER §4.5.3 の分割位置選択がそのまま移せないためです。

#### 5.2.1 移せるもの

**(a) 葉の閾値の実測。** EMBER は 25 多角形で最適としています（§4.5.3 の図）。
「分割を増やすと葉が安くなるが、全葉の多角形数の合計が増える」という相反する 2 傾向の
釣り合いです。**Krisite の閾値は実行時パラメータですが、最適値を測っていません。**

**(b) 分割するセルの選択基準。** 現状は「A と B の両方の三角形を含むか」。
EMBER §4.5.3 の思想は「**early-out が効きやすくなるように切る**」で、
八分木でも「どのセルを掘るか」の優先順位として一部移せます。

#### 5.2.2 移せないもの — WNV が要る early-out

EMBER §4.5.2 の early-out は Krisite のものより強い。

> $A - B$ で、参照 WNV が $(0, b)$ の形で、部分問題に $B$ の多角形しか無いなら、
> **即座に破棄できる。** 分類は $(0, b)$ から始まり、$B$ しか無いので WNV は
> $(0, b+z)$ の形にしかならず、$A-B$ が in になるのは $(a, 0)$ の形だけだから。

**これは WNV を持っていて初めて言えます。** 段 2 の後です。

なお EMBER §4.5.1 の NSI / NNC の最適化は、**Krisite では既に効いています。**
入力が自己交差なしと分かっているので、片方しか含まないセルで arrangement を省く処理
（§3.2 の early-out）が同じことをしています。

#### 5.2.3 段 1 で測るべきこと ★

**八分木が 1 段で 3 軸を同時に切る代償を実測してください。**

kd-tree は 1 段で 1 軸なので、分割面をまたぐ多角形は 2 つの部分問題に入ります。
八分木は最大 8 つに入ります。**同じ実効解像度に対して、断片の重複が多くなります。**

`SPEC-phase2.md` §4.3.3 の断片数がこの代償を含んでいます。**もし大きければ、
軸 3（空間分割）の再検討材料になります。** いまは八分木を維持する判断ですが、
その根拠は Phase 5 との結合と OEBSP の先例であって、**断片数を測った結果ではありません。**

### 5.3 段 2 — WNV / WNTV による分類 ★

#### 5.3.1 何を作るか

**(a) WNV と WNTV**

- **WNV** $w = (w_1, \ldots, w_n) \in \mathbb{Z}^n$。$n$ は入力メッシュ数（通常 2）。
  空間中の各点（表面上を除く）に定義され、$w_i$ は「メッシュ $i$ に何回入ったか」
- **WNTV** $\Delta w$。各入力多角形に付き、その面を**表から裏へ**通過したときの WNV の変化。
  通常は $(0,\ldots,1,\ldots,0)$
- 演算は WNV 上の**インジケータ関数** $f_{op}: \text{WNV} \to \{\text{in}, \text{out}\}$

| 演算 | $f_{op}$ |
|---|---|
| $A \cup B$ | いずれかの $w_i \neq 0$ |
| $A \cap B$ | すべての $w_i \neq 0$ |
| $A \setminus B$ | $w_A \neq 0$ かつ $w_B = 0$ |

各断片は $(w_F, w_B)$ を持ち、$(\text{out}, \text{in})$ ならそのまま出力、
$(\text{in}, \text{out})$ なら**向きを反転して**出力、$(\text{in},\text{in})$ と
$(\text{out},\text{out})$ は捨てる。

> **正則化ブールが自然に出ます。** 現在の §2.3 の意味論は、この定式化の系になります。

**(b) セグメントの平面ベース表現**

EMBER §3.1 の階層です。

| 対象 | 平面の数 |
|---|---|
| 点 | 3 |
| 線 | 2 |
| 光線 | 3（線 2 + 始端 1） |
| **線分** | **4**（線 2 + 両端 2） |

セグメントと多角形の交差は `intersect(l0, l1, s)` で交点を作り、
**辺平面と両端平面に対する `classify` で有効性を判定**します。新しい機構は小さい。

**新しい述語のビット幅導出が要ります**（§7 の手順）。

**(c) 3 セグメント経路の構成**（EMBER §3.2、Fig. 9）

2 つの同次点の間に直接の線分は作れません（$x_4 x'_4$ が幅を倍にする）。
しかし**経路なら作れます。**

$x = (s_0, s_1, s_2)$、$x_{ref} = (r_0, r_1, r_2)$ とすると、

- $x_1 = (s_0, s_1, r_2)$ は $x$ と平面 $s_0, s_1$ を共有 → **同じ線 $(s_0,s_1)$ 上** → 線分が作れる
- $x_2 = (s_0, r_1, r_2)$ も同様
- 経路 $x \to x_1 \to x_2 \to x_{ref}$ の**各セグメントが表現可能**

**「$x$ を定義する平面を 1 枚ずつ $x_{ref}$ のものに置き換えていく」**という操作です。
置き換える順序は任意なので、**経路が無効なら別の順序を試せます。**

**(d) 参照点の伝播**（EMBER §4.2.2）

```
分割で 2 つの部分問題ができる
  片方には既存の x_ref がある
  もう片方には新しい x_ref が要る
    → 既存の x_ref を新しい AABB へ【射影】するのが第一候補
    → 射影先は整数座標になり、軸平行の 1 セグメントで到達できることが多い
    → そのセグメントを辿って WNV を更新する
    → 無効なら（表面上を通る、辺に当たる）別の点を選ぶ
```

EMBER は「**大多数の実用的な場合で最初の候補が有効**」「無効でも数回の反復で見つかる」
としています。§5.2 の実測でも、参照点の更新はプロファイルにほとんど現れません
（軸平行で AABB の境界付近を通るため）。

#### 5.3.2 何が解けるか

**(a) 入力制約が緩む。** 自己交差・非多様体・退化した構成（PWN の範囲で）。
**開曲面は開きません**（§4.5 の訂正）。

**(b) 分類が局所化する。** 大域的なレイキャストが不要になります。
EMBER §5.2 では葉の計算の最大の項目がここです。

**(c) 純関数になり、work-stealing が素直になる。** Phase 3 の核心。

**(d) §4 の順序制約が消える ★**

`SPEC-phase2.md` §4 はこう書いています。

> 手順 4 と 5 の順序に注意してください。縫合を先に済ませてから分類します。
> 分類を先にやるとセルごとに独立した判断が入り、継ぎ目で矛盾する可能性があります。

**WNV なら、この心配が消えます。** 参照点が大域的な情報（WNV）を運んでいるので、
セルごとに分類しても**構成上一貫します。**

**これが段 3 の再定義を可能にします**（§5.4）。

#### 5.3.2.1 段 2 は過剰分割も引き連れます ★

**これは見落としやすい帰結です。**

`SPEC-phase1.md` §4.3.2 が過剰分割（全平面で切る）を採った根拠はこうでした。

> 符号ベクトルが内外を完全に決定します。分割の副産物として無料で得られます。

**WNV ではセグメントトレースで分類するので、この利得が消えます。**
断片がどう切られていようと関係なく辿るだけです。

残る利得は「凸多角形を半平面で切ると凸のまま」ですが、**EMBER の局所 BSP も
凸性を保ちます**（Fig. 7「保守的な分割でセルを凸に保ち、単純で速い手法にする」）。

つまり **段 2 を採ると、過剰分割は利得ゼロで断片数だけ増える機構になります。**
交差線分のみで切る局所 BSP（EMBER §4.3）へ移るのが筋です。

**そして §2 の中心問題（分割平面の絞り込み）も消えます。** 「どの平面で切るか」は
過剰分割を前提にした問いで、局所 BSP には選択の余地がありません。
`SPEC-phase2.md` §2.3 の証明とビット幅は正しいままですが、**適用場面がなくなります。**

> **Phase 2 の中心的な設計問題が、Phase 3 で消滅します。**
> Phase 2 が確立したもの（適応分割、early-out、構成点の保持、接触の分裂、検証体系）は
> 残りますが、**§2 の議論は過剰分割という設計選択の産物でした。**

#### 5.3.3 代償

| 項目 | 内容 |
|---|---|
| 新規機構 | WNV / WNTV、セグメント表現、3 セグメント経路、参照点の伝播、**局所 BSP** |
| 新規述語 | セグメント–多角形の交差など。**ビット幅の導出が要る** |
| 作り直し | 符号ベクトル分類（`SPEC-phase1.md` §4.3.2）、**過剰分割（§4.3.1）**、それらに依存する検査 |
| コーパス | 自己交差・非多様体の入力を追加する必要がある |

**符号ベクトルを捨てるのは惜しい面もあります。** 「$\partial B$ が $B$ の平面の和集合に
含まれるから符号ベクトルが内外を決める」という論法は正しく、実装も動いています。
**捨てる理由は正しくないからではなく、上記 (a)〜(d) が得られないからです。**

#### 5.3.4 検証の設計

**既存の検証体系がそのまま正解器になります。**

| 検査 | 段 2 後も使えるか |
|---|---|
| 分割戦略不変性 | **使える。** 意味論が変わらないので |
| 体積の恒等式・解析的期待値 | **使える** |
| 位相検査 | **使える** |
| Manifold との $(C,\chi)$ 一致 | **使える** |
| 変異テスト | 分類系は作り直し。他はそのまま |

**そして最強の検査があります。**

> **符号ベクトル分類と WNV 分類が、全コーパスで同じ結果を出すこと。**

現在の実装を残しておけば、**段 2 の実装が独立した正解器を持って始められます。**
Phase 2 で固定深度モードが正解器になったのと同じ構造です。

**現在の分類を消さないでください。**

### 5.4 段 3 — 「出力契約の変更」ではなく「中核と後処理の分離」

**スープ出力は採りません**（§4.5）。しかし段 3 は別の形で読み替えられます。

#### 5.4.1 読み替え

段 2 で §4 の順序制約が消えるので（§5.3.2 (d)）、構造をこう分けられます。

```
【中核】セル並列・純関数
  分割 → 局所 BSP（交差線分のみ）→ 分類（WNV）
  出力: (w_F, w_B) を持つ凸多角形の断片

【後処理】大域・逐次または領域並列
  頂点の併合 → T 頂点解決 → 接触の分裂 → 三角形化
  出力: 三角メッシュ
```

**出力契約は変わりません。** 変わるのは**どこで縫合するか**だけです。

#### 5.4.2 これが「新規実装」ではない理由

前節（§2.3）で「スープ → 多様体メッシュの後処理は先例がない」と書きましたが、
**この読み替えなら Krisite が既に全部持っています。**

| 後処理の要素 | 現状 |
|---|---|
| 頂点の併合（第2段） | **実装済み** |
| T 頂点解決（案 D） | **実装済み** |
| 接触の分裂 | **実装済み** |
| 三角形化 | **実装済み** |

**新しく書くのではなく、並列パスの外へ移すだけです。** リスクは §2.3 で書いたより
はるかに低い。

#### 5.4.3 なぜ保留か

**段 2 を入れると、段 3 の利得が目減りする可能性があります。**

段 2 で分類が局所化し純関数になれば、並列化の主な障害は消えます。
残るのは頂点の併合（大域状態）だけで、これは Phase 1 §5.4 のとおり
**広がりが 1 以下なので境界併合で扱えます。**

**段 2 の後に、並列化の利得がまだ足りなければ検討する**、という順序が正しい。
先にやると、必要のない再構成をすることになります。

## 6. 「変えない」を選ぶ場合

**正当な選択です。** 以下を受け入れることになります。

| 受け入れるもの | 根拠 |
|---|---|
| 並列化に境界併合の同期が要る | Phase 1 §5.4。広がりが 1 以下なので**実装可能**。EMBER より複雑になるだけ |
| 入力は閉多様体のみ | 非多様体・開曲面・自己交差は Phase 5 の GWN モジュールで別途扱う |
| ビット幅 320 / 512 | 上界は導出済みで、実測は上界内。**壊れてはいません** |
| 分類がホットスポットのまま | Phase 4 の性能目標で問題になるかは未知 |

**Phase 0〜2 の成果は一切損なわれません。** 検証体系（変異 67 件、分割戦略不変性、
体積恒等式、Manifold 比較）は自己整合で組まれており、外部の正解を必要としません。

**そして、現状で Phase 3 に進むことは可能です。**

## 8. 見立て（メッシュ主体の前提を反映）

**段 0・1 は即実施。段 2 を採用。段 3 は段 2 の後に判断。** これで合意しています。

前節までの分析を踏まえて、根拠を整理し直します。

### 段 2 を推す根拠（メッシュ主体の場合）

当初は「Phase 5 の GWN が付いてくる」を主な根拠に挙げましたが、**点群が後回しなら
この論拠は弱まります。** メッシュ主体の前提では、根拠は次の 3 つです。

| # | 根拠 | 重み |
|---|---|---|
| 1 | **Phase 3 の並列化が素直になる**（純関数、局所分類） | **最大**。Phase 3 の直前 |
| 2 | **自己交差入力が開く。** 自己交差の修復が「自分自身との和集合」で実現できる | **大**。メッシュ処理の中核機能 |
| 3 | 分類がホットスポットから外れる | 中。Phase 4 の性能目標で効く |

**2 が特にメッシュ主体と噛み合います。** EMBER の序文が指摘するとおり、メッシュ修復
アルゴリズムとブール演算は強い類似があり、自己交差の修復は self-union です。
**入力の前処理を外部に頼らずに済むようになります。**

### 段 3 は「保留」から「段 2 の後で測って判断」へ

§5.4 の読み替えにより、段 3 は**新規実装ではなく既存機構の移動**になりました。
リスクが下がったので、保留の理由も変わります。

- **旧**: 後処理に先例がないので危険
- **新**: 段 2 で並列化の障害が消えるなら、移動する必要がないかもしれない

**段 2 の後に並列化の利得を測って決めてください。**

### 順序

```
段 0  代表点の構成を平面ベースに戻す        ← 判断を待たずに実施可
段 1  葉の閾値の実測、八分木の代償の実測    ← 同上
─────────────────────────────
段 2  WNV / WNTV による分類                ← Phase 3 の仕様に含める
      現在の符号ベクトル分類は残す（正解器）
─────────────────────────────
Phase 3  並列化
─────────────────────────────
段 3  中核と後処理の分離                    ← 並列化の利得を測ってから
```

**段 2 を Phase 3 の仕様に含めるか、Phase 3 の前に別フェーズとして切るかは、
規模を見て判断してください。** §5.3.3 の代償は小さくありません。

分けるなら、Phase 1 と同じ構造が使えます。**現在の符号ベクトル分類を正解器として、
「両者が全コーパスで一致すること」を完了条件にする。** 外部依存なしで検証が閉じます。
