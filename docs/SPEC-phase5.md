## 0. この文書の位置づけ

**Phase 5 は 2 つのことをします。順序が重要です。**

```
CP1     実データでの【正しさ】              ← 先
CP1.5   【最適化】超線形の解消              ← CP2/CP3 の前提条件（2026-08-30 追加）
CP2〜3  範囲を広げて【正しさ】
```

> 「正しさの検証が現実的な時間で終わる」ことを前提にしていましたが、

逆順なら、**最適化の前後で比較できる正しい基準**が手に入ります。

前提として `SPEC-phase0.md` 〜 `SPEC-phase4.md` と各 `IMPL`、`BENCH.md` を使います。

## 1. 入力の分類 ★ 完了条件の書き方を決めます

**「全件成功」は要求しません。** PWN でない入力は**仕様上受け付けない**ので、
弾くのは正しい動作です。

### 1.0 選択はメタデータで、分類は量子化後で ★

**Krisite の入口は整数座標なので、float を $b$ ビットに量子化してから渡します。**
量子化は入力の性質を変えます。

| 量 | 量子化で | 理由 |
|---|---|---|
| $\partial S$ | **変わらない** | 組合せ的な量 |
| 面積 0 の三角形 | **生まれ得る** | 3 頂点が同一格子点に落ちる |
| 自己交差 | **生まれ得る** | 動かせば交わり得る |

**「メタデータで自己交差なし」は「量子化後に自己交差なし」を意味しません。**

**答える問いが 2 つあるので、分けてください。**

| 問い | 何で決めるか | 理由 |
|---|---|---|
| **どの 1,000 件か** | **メタデータ（float 水準）** | **EMBER と揃えるため。** EMBER も float のメタデータで選び、そのあと 26 ビットに量子化しています（§3.3） |
| **拒否 / 失敗 / 停止のどれか** | **量子化後の実際の挙動** | Krisite が実際に受け取るのは量子化後だから |

**混ぜると CP1 の目的が崩れます。** 量子化後の性質で選び直すと EMBER の集合と違うものを
測ることになり、**比較の土台という役割が失われます。**

#### 両者のずれ自体が測定対象です ★

> **メタデータで「自己交差なし」だった何件が、量子化後に自己交差を持つか。**
> **$b = 21$ と $b = 26$ で、拒否の件数がどう変わるか。**

**これは $b$ についての知見です。** いまは合成コーパスの上界計算しか根拠がありません。
**実データの数字が出れば、$b$ の選択に根拠が付きます。**

**3 つを分けて数えてください。**

| 分類 | 内容 | 扱い |
|---|---|---|
| **拒否** | 入口の検査（$\partial S \ne 0$ など、§4.0）で弾いた | **正しい動作。件数を記録** |
| **失敗** | 受け入れたのに、位相・体積・不変量が壊れた | **1 件でも欠陥。完了条件** |
| **停止** | `KRISITE_CHECK` で止まった | **失敗と同じ扱い。前提が破れている** |
| **実行不能** | **資源の上限に達した**（OOM、時間） | **拒否でも失敗でも停止でもありません。規模の限界という情報**（2026-08-31 追加） |

> **混ぜると数字が意味を失います。** 「99% 成功」が「1% は入力が悪い」なのか
> 「1% は実装が壊れている」なのかで、まったく違う話になります。

#### 拒否理由の分類 ★ 性質の違うものを混ぜないこと

| 事象 | 拒否か | 扱い |
|---|---|---|
| **量子化後に自己交差** | **拒否ではありません** | **PWN の範囲**（`SPEC-phase3.md` §1.1）。そのまま受け入れます |
| **面積 0 の三角形** | 拒否ではありません | **除去してから $\partial S$ を検査**（FARMA §3 と同じ）。**除去した枚数を記録** |
| $\partial S \ne 0$（元から） | **拒否** | 入力の性質 |
| **$\partial S \ne 0$（量子化 + 除去の結果）** | **拒否** | **理由が違います。$b$ の設計に直結** |
| 開曲面 | 拒否 | $\partial S \ne 0$ の一種だが、理由を分けて記録 |
| 座標範囲 | 拒否 | — |

**自己交差を拒否にしないでください。** Krisite は PWN を受け入れる設計で、
**self-union による修復が看板の用途です。** 量子化で自己交差が生まれても正常な入力です。

**面積 0 の三角形は除去が要ります**（支持平面が定義できない、$N = 0$）。
**除去が $\partial S$ を壊す場合があるので、除去後に再検査してください。**

**最後の 2 つを分けるのが要点です。** 「$b=21$ では $n$ 件が拒否、$b=26$ では $m$ 件」
という数字が、$b$ の選択の根拠になります。

### 1.1 拒否率そのものが情報です

**Thingi10K の何割が PWN でないかは、Krisite の入力制約が実務でどれだけ厳しいかを
示します。**

**高ければ、入力の前処理（修復）が Phase 6 の課題として浮上します。**
低ければ、制約は実用上ほぼ問題にならないという根拠になります。

**拒否の理由を分類して記録してください**（$\partial S \ne 0$ / 開曲面 / 座標範囲 / その他）。

## 2. データセットの範囲 — 段階的に広げます

**いきなり全 10K を当てないでください。** 失敗の原因が「実装の欠陥」か
「入力が PWN でない」かの切り分けに時間を取られます。**制約の緩い側から広げるほうが速い。**

| CP | 範囲 | 件数 | 狙い |
|---|---|---|---|
| **CP1** | **solid・多様体・自己交差なし、1,000〜100,000 面** | **約 1,000** | **比較の土台。** EMBER・FARMA の両方が報告している範囲 |
| **CP2** | **交差のあるモデル** | 約 4,408 | **自己交差入力。** self-union が実際に効くか |
| **CP3** | **全 10K** | 10,000 | **PWN でないもの、退化したもの。** 入口の検査が試される |

**CP1 の範囲を EMBER と揃えるのが要点です。** 数値の比較が成立します。

> EMBER §5.1 は「1,000 個の solid, manifold, 自己交差なしのメッシュ、1,000〜100,000 面。
> 下限は自明なものを除き、上限は比較対象が時間とメモリの限界に当たるため」としています。
> **同じ制限を使ってください。**

### 2.1 入力の作り方

EMBER §5.1 の手順を使います。

```
1. データセットから 2 つのメッシュを引く
2. 両方に、外接箱が大きく重なるようランダムな変換を掛ける
3. ブール演算を 1 つ実行して計測する
```

> **自分自身をわずかに回転させたものとの交差は使わないでください。** EMBER §5.1 が
> 「実世界の CSG から遠い」として避けています。**交差する部分としない部分が
> 混ざること**が、実データの性質です。

**変換とメッシュ ID の組を記録してください。** 再現できないと、失敗の追跡ができません。

### 2.2 面数の分布を EMBER と突き合わせてください ★

EMBER §5.1:

> 幾何平均は 1 メッシュブールあたり **1.6 ms**。**対応する入力サイズはおよそ 20,000 面**である。

**EMBER の代表的な対は約 20,000 面です。** 抽出したモデルの中央値が 5,000 面なら、
2 つ組んでも約 10,000 面で**倍の開きがあります。**

**面数が違えば時間も違うので、そのままでは比較になりません。**
§4.2 で「同じものを測っていない」ことを注意しましたが、**入力の規模も揃える必要があります。**

**面数の分布（中央値・幾何平均・四分位）を記録し、EMBER の 20,000 面と
突き合わせてください。** ずれていれば、比較の際に明記するか、抽出を調整します。

## 3. CP1〜CP3 — 正しさ

### 3.1 検査は Phase 1〜4 のものをそのまま使います

**緩めないでください。** 実データはコーパスより過酷です。

| 検査 | 節 |
|---|---|
| 位相（辺・頂点多様体、向き、$\chi$） | Phase 1 §10.1 |
| 体積の恒等式 | Phase 1 §10.3 |
| 分割戦略不変性、深度不変性 | Phase 2 §9.1 / Phase 1 §10.2.1 |
| 二項正解器との一致、$n$ 項と二項の一致 | Phase 3 §10.1 / §10.2 |
| 連鎖の厳密性、ビット幅が伸びないこと | Phase 3 §10.3 / §10.3.1 |
| **決定性**（スレッド数に依らずバイト一致） | Phase 4 §7.1 |
| Manifold との $(C, \chi)$ 一致 | Phase 1 §10.4 |

**解析的期待体積は使えません**（実データなので手で導けない）。**恒等式で見てください。**

### 3.2 検算は ON で回してください ★

> **`SPEC-phase2.md` §5.5 の検算を、Phase 5 の実データ検証では ON にしてください。**

**未知のデータを入れるときこそ検査が要ります。**

対応付けの誤りを捕まえるのは **$C$ の不変性と $\Delta E$ の予測だけ**です。
**体積は 1 件も検出しません**（Phase 2 の実測 0 / 29,945）。コーパスに無い配置が
実データにはあります。

**遅くなりますが、CP1〜CP3 は正しさのフェーズなので構いません。**

### 3.3 失敗したときの手順

**実データの失敗は、原因の切り分けが難しい**（入力が大きく、退化の種類が未知）。

```
1. 失敗したモデル ID と変換を記録する
2. 【最小化】する。面を減らして失敗が再現する最小の構成を作る
3. その構成を【コーパスに追加】する
4. 直す
```

**最小化してコーパスに入れるまでを 1 セットにしてください。** 直すだけだと、
**同じ配置が二度と検査されません。** Phase 1〜4 で追加したケースは、
すべてこの形で残っています。

## 4. CP4 — 性能目標の設定 ★

### 4.1 立て方

| 対象 | 基準 |
|---|---|
| **中核だけ** | **EMBER の報告値と比較**（スープを出すまでという点で揃う） |
| 中核 + 出口 | **自分の基準線からの改善率** |

**絶対値（○ ms 以内）は採りません。** ハードウェアと入力に依存しすぎて、
目標として機能しません。

### 4.2 中核だけを比較する理由

**EMBER の 1.6 ms は「スープを出すまで」の時間です。** Krisite は縫合・T 解決・
接触の分裂・三角形化まで含みます。**同じものを測っていません。**

**Phase 3 の分離（`from_mesh` / `boolean` / `to_mesh`）がここで効きます。**
中核の時間だけを取り出せます。

> **比較の条件も揃えてください。** EMBER は Intel i9-9900K（8 コア）、clang-12、`-O3`、
> 並列実装。**CPU が違えば数値は動きます。** 揃えられない部分は明記してください。

### 4.3 目標として置く数値

**CP4 で決めてください。** いま数値を置く材料がありません。**CP1〜CP3 の実測が出てから**
立てるのが正しい順序です。

**ただし基準線は既にあります。**

| | 実測 |
|---|---|
| 全体（規模コーパス、16 スレッド） | **5.52 倍**（Phase 4） |
| 分類が中核に占める割合 | **92.9%**（規模コーパス） |
| 入口 / 中核 / 出口 | 0.7% / 64.6% / 34.8%（Phase 3、単スレッド） |

## 5. CP5 以降 — 最適化

**優先度は CP4 の実測で決めてください。** 以下は現時点の見込みです。

### 5.1 セグメントトレース ★ 最有力

**規模コーパスで分類が 92.9%。** $O(\text{シーン}) \to O(\text{局所})$ が直撃します。

**ただし実データで測ってから判断してください。**

- 92.9% は**合成コーパス**（細分球・格子）の値です。実データは分布が違います
- **退化への耐性が実データで決まります。** Krisite のコーパスでは経路の 32.9% が
  退化しました（`SPEC-phase3.md`「コーパスの性質が EMBER と逆です」）。
  **退化コーパスで成立しないことは、実データで成立しないことを意味しません**

**着手する場合の前提は `SPEC-phase3.md` §14 です。**

| # | 前提 |
|---|---|
| 1 | **参照点が面上に載らないことの保証**（実測では 32.5% が退化し再試行で凌いでいる） |
| 2 | **記号的摂動**（トレースの述語に、レイキャストと同じものを入れる） |

**新しい述語のビット幅を導出する前に、1 を確かめてください。**
満たせないなら、摂動を入れても解決しません。

**出発点は `wip/phase3-cp3b-segment-trace`。** ただし主経路と予備を取り違えた前提で
書かれており（`LOG-phase3-design.md` の訂正 13）、摂動もありません。**書き直しになる
可能性が高い。**

### 5.2 §5.5 の検算を検査ビルドのみにする ★

**出口の分裂の 69%**（Phase 4 §2.3）。`check_topology` を 2 回呼んでいます。

> **`KRISITE_CHECK` の下に置いてください。** 検証は出荷ビルドの経路に置くものではありません。

**CP1〜CP3 では ON のまま回します**（§3.2）。**CP3 が全件通ってから外してください。**
実データで裏づけが取れた後なら、Release で切る根拠になります。

**全体の何 % かを記録してください。** 「出口の分裂の 69%」だけでは規模が分かりません。

### 5.3 到達可能性による early-out

EMBER §4.5.2。**$n$ 項で特に効きます**（ミリングのように工具を 20 個引く場合）。

**インジケータ関数と、部分問題に存在する WNTV の集合から、到達可能な WNV を求めて
判定します。** 演算ごとに手で規則を書くのは現実的でないので、**導出を機構にしてください。**

**対応する変異（「到達可能性判定を緩める」）も一緒に入れてください。**

### 5.4 切断候補の絞り込み

**採用には ①証明 か ②専用のコーパスケース が要ります。**

残る経路は「共平面に載る別々の多角形が違う切り方をして `region_key` が潰せなくなる」で、
**「コーパスに配置が無い」だけでは否定できません**（`SPEC-phase2.md` §2.6）。

**8,169 回多く省ける**という実測はあります。コードはマクロの後ろにあります。

### 5.5 `to_float_mesh`（snap rounding）

**位相の完成とは別の関心事**として Phase 3 §6.5 で分離しました。

FARMA §5.6 の実測と手法が出発点です。

| 手法 | 成功率 |
|---|---|
| 素朴に double へ丸める | 85.2% |
| 失敗時に double → single へキャストして再実行 | 96% |
| 反復 | 99.95% |

**完全解は未解決問題です**（FARMA §7.1「パイプラインの最終段が鎖の弱い環」）。
**目標は「失敗を検出して報告できること」**です。**黙って壊れたメッシュを出さないこと。**

**成功率を実データで測ってください。** 85.2% は FARMA の値であって Krisite の値ではありません。

### 5.6 `BENCH.md` から移管した項目

- `side()` の分岐予測が外れる条件
- キャッシュミスを含む現実的なアクセスパターン

## 6. 記録する数値

### 正しさ（CP1〜CP3）

- **拒否 / 失敗 / 停止の件数**（§1。混ぜないこと）
- **拒否の理由の内訳**（§1 の表の分類で。**元から $\partial S \ne 0$ と、量子化 + 除去の結果を分ける**）
- **$b = 21$ / $b = 26$ での拒否件数の差**（$b$ の設計の根拠）
- **量子化で生まれた自己交差の件数**（拒否ではないが、$b$ の知見）
- **除去した面積 0 の三角形の枚数**
- **面数の分布**（中央値・幾何平均・四分位）と、EMBER の 20,000 面との差
- **$n$ に対する指数**（全体および段ごと）★ CP1.5 の対象を決めます
- **検算 ON / OFF の比**（代表的な 1 対で）
- **三角形あたりの処理速度**（EMBER の 1,500 万個/秒との差。条件差を明記して）
- 大きい対でのメモリ
- 最小化してコーパスに追加したケースの一覧

### 性能（CP4 以降）

- **中核だけの時間**（EMBER と比較可能な形で）
- 入口 / 中核 / 出口の内訳（実データでの分布）
- **分類が中核に占める割合**（92.9% は合成コーパスの値。実データでいくつか）
- スケーリング（スレッド数 1 / 2 / 4 / 8 / 16）
- メモリ（Krisite と比較対象）
- 面数に対する時間の分布（EMBER Fig. 13 のような形）

### 最適化ごと

- 導入前後の時間と、**その最適化が発火した回数**
- 出力が変わっていないこと（決定性の検査）

##### 参考 — 当時の論証（記録として残します）

**「平面がセルを横切るか」で絞る基準は、過剰分割が前提でした**（`SPEC-phase2.md` §2.3）。
あの頃は平面集合が切断を決めていたので、割り当て集合に絞ると T 字接合が出ました。

**Phase 3 で局所 BSP に置き換えた時点で、その前提が消えています。**

> 葉の各多角形 $t$ について、**その葉の他のすべての多角形**との交差を計算する
> （`SPEC-phase3.md` §5.4）

**局所 BSP が要るのは「セル内の多角形どうしの交差」だけです。**
三角形がセルに届かないなら、その多角形はセル内の断片と交わりません。**除外は健全です。**

> **T 字接合の懸念は当たりません。** 局所 BSP は交差線分だけで切るので、
> 遠くの平面は切断に関与しません。
>
> **`cull_planes` が「セルを横切る平面」で集合を作っているなら、過剰分割の時代の機構が
> 残っている可能性があります。** `SPEC-phase3.md` の置換一覧は §4.3.1（大域平面集合）を
> 挙げましたが、**実装上の依存先まで追っていませんでした。**

##### 3 について — 有効性を測ってください

**Phase 4 §7.3 は「項目数がスレッド数で増えること」を検査しました。**
それは**スレッド局所である証拠**であって、**その設計が有効かどうかは測っていません。**

**16 スレッドでキャッシュ有無の時間を測ってください。** 差が小さければ、やめるのが正解です。

| 案 | 見込み |
|---|---|
| **やめる** | 1.5% なら純粋な負担。349 MB が浮く |
| **葉ごと**（タスク局所） | 葉内の再利用だけ回収。小さく高命中 |
| 隣接セル間で共有 | 併合の広がりが 1 以下（Phase 1 §5.4）と同じ発想 |
| 全体で共有 | 63% を回収できるが同期が要る。決定性は保てる（メモ化なので結果は同じ） |

#### 最適化の前に測ってください ★

**「セグメントトレースが原因」はまだ仮説です。** 対象を決める前に 2 つ測ること。

**① 検算の寄与。** 代表的な 1 対を検算 ON / OFF で測る。§3.2 で ON を要求しましたが、
**時間のうち何割かが分かっていません。** 検算は $O(V+E+F)$ のはずなので指数には
効かないはずですが、**定数は大きい可能性があります。**

**②′ メモリの指数。** 時間だけでなく**メモリの $n$ に対する指数**も出してください。
30.7 GB は素朴な見積もり（237 MB）の 130 倍でした。

**② 段ごとの指数。** 入口 / 中核 / 出口、さらに中核の中で分類 / BSP / 分割について、
$n$ に対する指数を出す。**超線形なのがどこかを特定してから対象を決めてください。**

| 超線形の場所 | 対応 |
|---|---|
| **分類**（大域レイキャスト。$O(\text{シーン})$ / 領域） | **セグメントトレース**（§5.1） |
| 局所 BSP の対交差（$O(m^2)$ / 葉） | 葉の閾値、切断候補の絞り込み（§5.4） |
| 頂点の併合 | 大域整列は $O(n \log n)$ なので 1.66 の説明にはなりません |

**「効いたから使う」の原則です。** 92.9% は合成コーパスの値で、実データでも同じとは
限りません。

#### CP1 を 400 対で閉じる根拠

**小さい順に 400 対（80%）で失敗 0 なら、正しさの根拠として十分です。**
残り 100 対は同じ経路を大きい入力で通るだけで、**正しさの証拠としては限界効用が小さい。**

**ただし記録は「妥協した」ではなく「$n^{1.66}$ を発見したので順序を変えた」と
書いてください。** 数字が出ていることと、出なかったことは違います。

> **大きい対ではメモリも見てください。** 24,878 三角形で 1.9 GB でした。
> 100,000 三角形では別の限界に当たる可能性があります。

### CP1.6 — 既存バグの修正 ★（2026-08-31 新設。最優先）

**細分した立方体 2 つの Union で `intersect3: w == 0` が出ます。**

| 条件 | 結果 |
|---|---|
| $k=1$（細分なし、12 三角形） | 通る |
| **$k=2$（48 三角形）** | **落ちる** |
| 斜めにせん断（行列式 1）しても | 落ちる |
| 索引 OFF でも | 落ちる |
| **CP1.5 着手前（`72f5917`）でも** | **落ちる → 既存のバグ** |

**深度 0 で落ちるので、中核の問題です**（`SPEC-phase1.md` §11 の切り分け）。
入力は `check_topology().ok()`、`is_outward_oriented()` ともに真。

#### なぜ最優先か

> **CAD 由来のメッシュでは、平坦面の規則的な三角形分割は例外ではなく常態です。
> 実データで出ていないことは、出ないことの根拠になりません。**

Thingi10K の 336 対で出なかったのは**抽出されたモデルの性質**であって、
**実装が正しい証拠ではありません。**

**CP1 の残りを流す前に直してください。** 踏んだまま流すことになります。

#### 切り分けの入口 — 符号と幾何の整合

**クリップは端点の符号が $-1$ と $+1$ の辺だけを切ります**（`SPEC-phase1.md`）。
符号が異なるなら**辺は平面を横切っているので、交点は存在するはず**です。

> **符号が $-1$ / $+1$ なのに $w = 0$ なら、符号か平面のどちらかが壊れています。**

| どちらが壊れているか | 意味 |
|---|---|
| **符号** | `side` の結果と幾何が食い違っている |
| **平面** | 辺平面がその辺を正しく表していない（構成か向きの問題） |

**まず「どの呼び出し箇所で $w=0$ が出たか」と「そのときの端点の符号」を取ってください。**
**仕様の判断はそこが分かってからです。** 「どの平面の組を選ぶか」の問題なのか
「符号と幾何の食い違い」なのかで、答えがまったく違います。

**推測して書かないでください。** §8 で 6 回失敗し、当たったのは
**段を刻んで測った 1 回**でした。同じ形で進めてください。

## 10. 退避条件

| # | 想定が破れた場合 | 退避 |
|---|---|---|
| 1 | **拒否率が高すぎる**（実務で使えない水準） | 入力の前処理（修復）を **Phase 6 の課題として記録。** Phase 5 は受け入れた分で閉じる |
| 2 | **CP1 で失敗が多く、原因が構造的** | **そこで止まる。** 最適化に進まない。設計の見直しが要る可能性 |
| 5 | **CP1.5 の最適化後、CP1 の再実行で出力が変わった** | **最適化が意味論を変えています。そこで止まる。** Phase 4 の決定性の要求により、変わってはいけません |
| 6 | **CP1.5 で超線形が解消しない** | **CP2 / CP3 の範囲を縮小して閉じる。** 「全件」を諦め、**代表的な部分集合で正しさを言う**。理由と見積もりを記録 |
| 3 | セグメントトレースが実データでも退化する | **大域レイキャストのまま。** §5.3 / §5.4 で別の改善を取る |
| 4 | 性能目標に届かない | **目標と実測の差を記録して閉じる。** 目標は Phase 5 で初めて立てるものなので、**外れたこと自体は失敗ではありません。** なぜ届かないかが分かっていることが要件 |

**2 が最も重要です。** 実データで構造的に失敗するなら、**最適化しても意味がありません。**
