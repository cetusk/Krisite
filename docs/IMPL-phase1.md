## 2. 設計判断と根拠

### 2.1 入力三角形を「平面ごとの多角形」に併合した ★

**これが Phase 1 で最初に必要になった、仕様に明示されていない構造上の判断です。**

立方体の 1 面を 2 三角形のまま扱うと、その**対角辺**が問題になります。対角辺は三角形分割の
産物であって幾何的な特徴ではなく、**2 平面の交線として表せません**（両側の三角形が同一平面
なので交線が定まらない）。したがって対角辺上に生まれる交点は「3 平面の交点」の枠に収まらず、
§3.3 の頂点表現から外れます。

併合すれば多角形の各辺は必ず**別の平面を持つ隣接面**と共有されるので、

- 辺 = 2 平面の交線
- 頂点 = 3 平面の交点
- クリップで生まれる頂点 = （支持平面, 辺の平面, 切断平面）

となり、**表現がクリップについて閉じます。**§3.1 の「立方体の 1 面は 2 三角形ですが、
平面は 1 枚です。統合しないと、後段で同じ点が別の平面3つ組から生まれ、§5 の同一性判定に
不要な負荷がかかります」は、この話だと読みました。

- **代案 A**: 三角形のまま扱い、入力辺を特別な辺種として持つ
  → クリップで生まれる頂点が 3 平面の交点にならず、`intersect3` が使えない。
    §3.3 の `Vertex` 表現も破綻する
- **代案 B**: 対角辺の両側に「同一平面」を割り当てて交線を退化させる
  → `intersect3` の前提（3 平面が一点で交わる）が破れる

**Phase 1 の制約**: 併合後の多角形が**凸**であることを要求します。§4.3 が「凸なので扇でよい」
と書いているのはこの前提です。コーパス（立方体・四面体・量子化した回転立方体）はすべて凸面
なので成立しますが、**一般のメッシュでは非凸の平面パッチがあり得ます**（§7 に申し送り）。

### 2.2 断片は「支持平面 + 辺の平面」で持つ

頂点を明示的に持たず、`edge[i]` だけを持ちます。頂点は必要になったときに `intersect3` で
復元します。

- **利点**: クリップが**平面 ID の列の操作**になる。頂点の同一性が平面3つ組で自然に決まり、
  §5.3 の第1段のキーがそのまま得られる
- **代償**: 頂点を使うたびに `intersect3`（262 ns、`IMPL-phase0` §5.2）が走る。
  Phase 1 は性能を問わないので許容。キャッシュは Phase 2 の候補

### 2.3 クリップの辺保持規則

保持する辺の判定を「端点の少なくとも一方が**真に**内側」にしています。

素朴に「端点の一方が 0 以上」とすると、頂点がちょうど切断平面に乗るときに**面積 0 の辺**を
拾い、頂点が重複した退化多角形ができます。凸多角形では保持される辺が巡回的に連続するので、
その連続区間の末尾に切断平面を 1 枚足せば閉じます。

この規則は 4 通りの符号配置（両端内側 / 出る / 入る / 両端外側）と、頂点が平面に乗る場合を
手で検算してから実装しました。テストの `test_split_through_vertex` がこの境界を突きます。

### 2.4 セル割り当ては AABB による保守的判定

三角形の AABB とセルの**閉領域**が重なるかだけを見ます。

- **取りこぼさない**（AABB は三角形を含むため）。取りこぼすと §4.2 の破綻が起きる
- **過剰割り当てはある**が、クリップ結果が空になるだけで無害
- 厳密な三角形-箱交差（分離軸定理）は Phase 2 の最適化候補

「取りこぼさないこと」が正しさに効き、「過剰でないこと」は性能にしか効かない、という
非対称性があるので、Phase 1 では安全側に倒しました。

### 2.5 分類の代表点は「相手の**境界上**に無い断片の頂点」★ CP2 で改めた

§6.1 は「キャスト元の断片は入力頂点を含むものを優先」「断片ごとの重心は $18b{+}36$ ビット
規模になるので避けよ」と言っています。実装では**断片の頂点そのもの**を使います。

**CP1 では条件を「相手の全平面に対して符号が非零」としていました。これは強すぎました。**

断片の頂点は、その断片を切り出した平面の上に必ず載ります。相手の平面が切断に使われて
いれば、頂点は必ずその平面の上にあります。ケース 2 では**四角形の 4 辺のうち 3 辺が
相手の平面上**という断片が現れ、4 頂点すべてが条件を落として停止しました。

必要なのは「$\partial B$ の外にあること」だけです。**平面上にあることと境界上にあることは
別です。** 相手の平面上でも、その平面上の面の外側なら境界からは外れています。
そこで `csg/raycast.hpp` に `point_on_boundary` を足し、条件をこれに置き換えました。

判定は厳密です。三角形の平面上にあるかを `side` で見て、載っていれば**法線成分が非零の
軸**へ投影して `orient2d_h` 3 本で内外を見ます。新しい述語は要りません。

**頂点の分類が断片全体の分類と一致することは保証されます。** $\partial B$ は $B$ の平面の
和集合に含まれ、断片は $B$ の平面配置のセルなので、$\partial B$ は断片の**内部を横切りません**。
頂点から内部へ引いた線分は途中で $\partial B$ を跨がないので、頂点が境界上に無ければ
断片と同じ側です。

- **代案**: 重心（7 リム規模）→ §6.1 が明示的に避けよと言っている
- **代案**: 入力頂点だけを使う → 入力頂点を持たない断片が classification できない

### 2.5.1 それでも足りず、対角線の中点に落とした

条件を緩めてもなお、**4 頂点すべてが $\partial B$ 上**という断片が残りました。ケース 2 の

    A = [-2^{b-1}, 0]^3、B の面 x = -2^{b-2} 上の断片（y \in [-2^{b-2}, 0], z \in [-2^{b-1}, 0]）

がそれです。この断片は A の内部にありますが、4 辺のうち 3 辺が A の面に載るため、
4 頂点すべてが $\partial A$ 上になります。相対内部の点が要ります。

**凸多角形の対角線の中点は相対内部にあります。** 相対内部は相手の平面配置のセルの内側
なので、$\partial B$ から必ず外れます。したがって**頂点数 4 以上なら必ず決まります。**

問題は幅です。$v_i = (X_i : W_i)$ の中点は

$$ m = (X_0 W_1 + X_1 W_0 \;:\; 2 W_0 W_1) $$

で、これを `HPointD` に詰めるには `kHomoXyz` / `kHomoW` を広げることになり、
**構成点の表現そのものが太ります**（すべての述語に波及）。

そこで **$m$ を構成しません。** `side_value` も `orient2d_h_value` も同次座標について
**線形**なので、被符号値 $F$ について

$$ F(m) = W_1 F(v_0) + W_0 F(v_1) $$

が厳密に成り立ちます。$m$ の $w = 2W_0W_1$ の符号は $\mathrm{sign}(W_0)\mathrm{sign}(W_1)$ です。
`geom::HMidPointD` は両端点を持つだけで、述語 2 本だけを新しい幅で足しました（§4）。

**三角形の断片（頂点数 3）には対角線がありません。** 現状は停止します。実際に起きるかは
CP3 で分かります（§7.2）。

### 2.6 レイキャストの記号的摂動を投影だけに限定できる理由

2.5 により**判定点は必ず $\partial B$ の外**にあります（`point_on_boundary` で確かめます）。したがって

$$N \cdot p + d \ne 0$$

が保証され、**前方交差の判定は退化しません。**摂動が要るのは投影後の内外判定だけです。

摂動はレイ原点を実座標で $(0, \varepsilon, \varepsilon^2)$ ずらしたものとして扱います。
投影の向きが 0 になったとき、

$$\mathrm{orient2d} \to O + (b_y - a_y)\varepsilon^2 - (b_z - a_z)\varepsilon$$

なので、$\varepsilon$ の項 $-(b_z - a_z)$、それも 0 なら $\varepsilon^2$ の項 $(b_y - a_y)$ で
符号が決まります。両方 0 なら投影された辺が退化していて、それは三角形の法線の $x$ 成分が
0（レイが平面に平行）の場合なので、先に弾いています。

**記号的摂動の適用範囲を狭めたのは意図的です。** 摂動は正しさの検証が難しいので、
必要な箇所を構造的に減らしました。

### 2.7 位相検査器を出力より先に作った

`mesh/topology.hpp` を `csg/` より前に実装しました。検査器が無いと CP1 の合否を判定できず、
§10.5 の変異テストも検出力を持ちません。

そして**検査器自身を、位相が既知の構成で検証**しました。とくに次の 2 つが重要です。

| 構成 | 何を保証するか |
|---|---|
| 頂点だけを共有する 2 立方体 | 辺は壊れず向きも整合するが**頂点多様体が落ちる**（ケース 11b の $\cup$） |
| **T 字接合** | 幾何的に隙間ゼロでも**辺多様体が落ちる** |

後者が成り立たないと §10.5 の**変異 3 が素通り**します。§4.3.1 が「T 字接合は幾何的に
隙間が無いため、緩い検査だと素通りします」と警告しているのはこの点です。

検査器は幾何を一切見ません。純粋に組合せ的なので、頂点座標の表現（`IPoint` か構成点か）に
依存せず、§10.2.1 の深度不変性がそのまま乗ります。

### 2.8 出力メッシュは `TriMesh` ではない

出力の頂点は構成点（有理数）なので `mesh::TriMesh`（`IPoint` 頂点）には入りません。
`csg::BoolMesh`（`HPointD` 頂点）を別に定義しました。

位相検査は三角形の添字だけで行えるので、`check_topology(BoolMesh::triangles)` がそのまま
使えます。2.7 で検査器を幾何非依存にしておいたことがここで効いています。

### 2.9 断片の同一性は「辺の平面 ID」では決まらない ★ CP2 で改めた

CP1 では断片の正準キーを **(支持平面, 辺の平面 ID 列の正準回転)** にしていました。
**これは誤りです。**

支持平面 $p$ に対し、**相異なる 2 平面が $p$ と同一の交線を持ち得ます。**
例えば $p: z=0$ に対して $q_1: x=0$ と $q_2: x+z=0$ はどちらも $p$ 上で直線 $x=0$ を与えます。
同じ幾何辺が、切る順序によって $q_1$ とも $q_2$ とも記録されます。

そこで**縫合を分類より先に済ませ**、断片の同一性を**大域頂点 ID の集合**で判定するように
変えました。第2段（値ベースの併合）を通した ID は正準なので、平面 ID の別名に影響されません。
凸多角形は頂点集合で一意に定まるので、順序を捨てても領域は復元できます。

`csg/boolean.hpp` の冒頭の手順が「4 → 5」の順になっているのはこのためです。

### 2.10 共平面重複は「符号 0」ではなく「同一領域の対」で検出する ★

§4.3.2 は「$\partial B$ 上に載る断片は符号 0 になります」と書いていますが、
**逆は成り立ちません。** 符号 0 は「相手の平面上」であって「相手の境界上」ではありません。
$B$ の面の外側にある同一平面上の断片も符号 0 になります（2.5 と同じ混同）。

正しい判定は「$B$ の面がその領域を覆っているか」です。そして

- $B$ の面の境界辺は、それぞれ $B$ の平面に載っている（2.1 の併合の帰結）
- 分割は $B$ の全平面で行う（§4.3.1）

ので、**平面 $p$ 上の断片は $B$ の面に丸ごと含まれるか丸ごと外れるか**のどちらかです。
したがって $\partial B$ が覆っているなら、$B$ 側にも**同一領域の断片が必ず存在します**。

そこで「同じ (支持平面, 頂点 ID 集合) の組に両 owner の断片が居る」ことを共平面重複の
定義にしました。向きは `Fragment::flipped` の一致で分かります（同じ支持平面どうしなので）。

選択規則は正則化ブール（§2.3）から決まります。

| | $\cup$ | $\cap$ | $A \setminus B$ |
|---|---|---|---|
| 同方向 | A のみ | A のみ | 両方落とす |
| 逆方向 | 両方落とす | 両方落とす | A のみ |

同方向の面は「両者の外側が同じ側」なので $\cup$ と $\cap$ の境界に残り、$A \setminus B$ で消えます。
逆方向の面は「一方の外側が他方の内側」なので $\cup$ と $\cap$ では内部面になって消え、
$A \setminus B$ では $A$ の表面として残ります。

**副次的に、`seen` による重複除去のバグも直りました。** CP1 の重複キーには owner が
入っていなかったので、A の断片と B の断片が同一領域を占めると**片方が「重複」として
黙って捨てられていました**。共平面重複そのものが消えていたわけです。

## 4. 新規述語のビット幅

§7 の手順どおり、**先に導出して `geom/widths.hpp` に定数を足してから**実装しました。

| 述語 | 上界 | 実測 (b=21) | リム | 用途 |
|---|---|---:|---|---|
| 平面の小行列式 `5b+9` | 114 | 106 | 2 | 平面の比例判定・全順序 |
| 平面の全順序 `6b+11` | 137 | — | 3 | 実際は `5b+8` までしか届かない（下記） |
| 軸平行平面のオフセット `b+1` | 22 | — | `kOffset` に内包 | セル面 |
| 四面体の体積x6 `3b+1` | 64 | 63 | 1 | 入力の向き検査 |
| 入力メッシュの体積x6 `3b+1+16` | 80 | — | 2 | 三角形 $2^{16}$ 枚までの総和 |
| `orient2d_h` `8b+17` | 185 | 170 | 3 | レイキャスト（同次点版） |

**上界超過はゼロです。**

`kPlaneOrder = 6b+11` は 24 ビット（b=21）保守的です。先頭非零成分 $i$ は法線に限られる
ため（$i$ が $d$ なら $a=b=c=0$ で、それは退化三角形の平面）、実際に到達しうる最大は
`kPlaneMinor` と同じ $5b+8$ です。安全側なのでそのまま採っています。

`orient2d_h` は**キャスト元が同次点のときだけ**必要です。入力頂点（`IPoint`）から撃つなら
既存の `orient2d`（$2b+3$）で済みます。

### 4.1 CP2 で足した 2 本（中点の述語）

2.5.1 の代表点フォールバックのために追加しました。**中点を構成せず**、
被符号値の線形性を使って両端の値の重み付き和で評価します。

| 述語 | 導出 | 理論 (b=21) | 実測 | リム |
|---|---|---:|---:|---:|
| `side(plane, 中点)` | $\mathtt{kHomoW} + \mathtt{kSide} + 1 = 15b+33$ | 348 | 317 | 6 |
| `orient2d_h(中点)` | $\mathtt{kHomoW} + \mathtt{kOrient2dH} + 1 = 14b+30$ | 324 | 297 | 6 |

$+1$ は 2 項の和のぶんです。**上界超過はありません。**

$x,y,z$ が $13b+27$、$w$ が $12b+25$ になり、**構成点の型そのものを広げる**ことになります。
`side` は $15b+32$、`cmp_h` は $25b+53$ に膨らみ、Phase 0 の述語全体に波及します。
線形性を使えば、影響はこの 2 本に閉じます。

ケース 5（面がセル境界と完全一致）× union × 深度 0〜3。**通過しました。**

#### 分かったこと ★

**軸平行な立方体だけのコーパスでは、1 点に集まる平面は原理的に 3 枚を超えられません。**

1 軸につき点を通れる平面は高々 1 枚（平行な 2 平面は交わらない）で、軸は 3 本だけだからです。
そして**セル面が立方体の面と一致しても枚数は増えません。** 両者は同一の幾何平面なので
`PlaneTable` が同じ ID に併合し、頂点の平面3つ組が一意に定まるためです。

つまり **ケース 5 は、仕様が期待した「§5.2 の 4 平面同時交差」を突いていません。**
突いているのは §4.2 の重複割り当てのほうです（深度 3 で 144 件）。

そこで**斜面**を持つ対（ケース 5T）を作って確かめました。四面体の面 $x+y+z=0$ を
原点（深度 1 以降のセル角、かつ A の角）に通すと、原点を通る平面は
$x=0$, $y=0$, $z=0$, $x+y+z=0$ の **4 枚**になります。

- **最大枚数 4**（セル面込みで 6）を検出 → **計測は 4 枚以上を検出できます**
- **第2段が発火（値併合 8〜37 件）** → §5.3 の第2段は**必要です**。
  平面3つ組が相異なるのに値が一致する頂点が実際に出ます

**検出できない計測器で「最大 3 枚」と報告しても何も言っていません。** 5T はその番人です。

**ただしケース 5T の位相は通りません**（§7.2）。斜面を持つ入力では現状の実装が
非多様体を出します。**これは CP2 の問いではなく CP3（ケース 7 / 9）の問題で、
この改訂の前から同じです**（旧実装は同じ入力で停止します）。合否には使っていません。

#### 結論

- **CP2 は通過**。§11 の「通れば EMBER 続行の判断が立つ」に該当します
- **5 枚以上は出ませんでした。** 軸平行では 3 枚、斜面を入れると 4 枚（セル面込み 6 枚）
- §5.3 の第2段は**斜面があるときに必要**。軸平行だけなら第1段で足ります
- 4 平面同時交差の発生率は「発散する」水準ではありません（§11 の中止条件 3 には該当せず）

### 6.1 八分木は座標範囲全体を分割する ★

### 6.2 `PlaneTable` の代表の向きは任意

代表は「最初に登録された平面」です。立方体の $-X$ 面から作った平面は法線が $-X$ 向きなので、
`side(t.at(id), p) > 0` が「$x$ が大きい側」とは限りません。

セル面のクリップで保持側を反転させる処理（`r.flipped ? -base : base`）が要りました。
**呼び出し側は代表の向きを仮定してはいけません。**

テストでも一度この仮定を置いて落ちました（`test_split_through_vertex`）。

### 6.3 開領域割り当ては幾何を丸ごと落とす

§4.2 は「共有面 $F$ 上で接するだけの三角形 $Q$ が片側のセルから漏れる」と書いていますが、
実測では**どのセルにも入りません**。

境界 $x = m$ の両隣について、下側は `tri.lo >= chi`、上側は `tri.hi <= clo` で

§10.5 の変異 2 はこれを突きます。

### 正解器の独立性

`plane_cmp` は交差乗算で比較しますが、GMP 正解器は **mpq で先頭成分を割って比を直接比較**
します。同じ変形を使う正解器は正解器ではない（`CLAUDE.md`「通しての約束」）ためです。

`plane_same`（6 本の小行列式）と `plane_cmp`（交差乗算）も**別々の式から導いた**ので、
両者が一致することを性質テストの中心に据えています。片方だけ間違えれば必ず食い違います。
