## 1. CP1 — 段 0 と辺平面（2026-08-28）

### 1.1 §3.1.2 の導出は正しい。$b{=}26$ でも 4 リムに収まります ★

**CP1 の最優先項目でした**（`LOG-phase3-design.md` §8 の未決事項 1）。
実測は `tests/arith/test_bitwidth.cpp`（乱択 $10^6$ 規模）。

| 量 | 理論 | $b{=}21$ 実測 / リム | $b{=}26$ 実測 / リム |
|---|---|---|---|
| **辺平面の法線** $N_e$ | $b{+}1$ | **22 / 1** | **27 / 1** |
| **辺平面のオフセット** $d_e$ | $2b{+}2$ | 42 / 1 | 52 / 1 |
| 辺平面 3 枚の交点からの `side` | $5b{+}11$ | 106 / 2 | 131 / 3 |
| 軸平行 2 枚を含む交点 $w$ | $2b{+}6$ | 43 / 1 | 53 / 1 |
| 軸平行 2 枚を含む交点 $xyz$ | $3b{+}8$ | 65 / 2 | 80 / 2 |
| 支持平面の法線（比較） | $2b{+}3$ | 43 / 1 | 53 / 1 |
| **最悪ケース `side`** | $9b{+}20$ | 191 / **4** | **236 / 4** |

**辺平面は支持平面より小さい**（法線 27 対 53 ビット）ので、最悪ケースは支持平面 3 枚の
ままです。**$b{=}26$ で 254 ビット = 4 リム**、退避条件 1（`SPEC-phase3.md` §15）は
発生しませんでした。

> **案 A（$N_s \times (p_2-p_1)$）なら 6 リムでした。** 構成方式の選択が決定的だ、
> という仕様の指摘は数値でも裏づけられます。

**軸選択の可能性の論証には補いが要りました**（§3.1.3 に反映済み）。
$(\Delta\times e_i)\times(\Delta\times e_j) = (\Delta\cdot(e_i\times e_j))\,\Delta$ なので、
**$\Delta$ の第 $k$ 成分が 0 のとき $i$ と $j$ が平行**になり、候補方向が 2 つに減ります。
それでも $N_s$ に平行になり得るのは高々 1 つなので結論は保たれます。

### 1.2 段 0 — 代表点は 2 経路とも実際に使われます

| 経路 | 実測（22 ケース × 3 演算 × 深度 0〜3） |
|---|---|
| 主経路（float ヒント + 軸平行直線） | **2,925** |
| 予備経路（角の 2 辺平面を内側へずらす） | **1,395** |

**予備経路は飾りではありません。** 深度が上がるほど断片が小さくなり、丸めた整数の
重心が多角形から外れます（深度 0 で 0 件、深度 3 で過半）。**両方が走ることを
`interior` の番人で固定しました。** 片方が 0 になったらテストが落ちます。

#### 1.2.1 刻みを細かくする機構を足しました

EMBER §4.4 は「平面係数を精度限界近くまでスケールアップして刻みを細かくする」と
書いていますが、**具体的な上限は示していません。** Krisite は固定幅なので、
`kNormal` / `kOffset` の余裕から**上げ幅を機械的に決めます**（`plane_scaled_for_shift`）。

平面 $(N,d)$ と $(2^sN, 2^sd)$ は同じ平面なので、係数を上げてから $d$ を 1 動かすと
幾何的な移動量が $2^{-s}$ になります。**型は変わりません。**

予備経路は「角ごとに、粗い刻み → 細かい刻み」の順に試します。実測では細かい刻みまで
必要になった配置はありませんでしたが、**細長い断片では効くはずなので残します。**

#### 1.2.2 境界判定が不要になりました

Phase 1 / 2 は候補ごとに `point_on_boundary` を呼んでいました。段 0 の代表点は
**相対内部**なので、$\partial B$ に載りません（$\partial B$ は $B$ の平面の和集合に
含まれ、断片は $B$ の平面配置のセルなので内部はどの平面とも交わらない）。

**判定は消しましたが、表明としては残しました。** 前提が破れたら止まります。

### 1.3 最大ビット幅が下がりました

| | $b{=}21$ | $b{=}26$ |
|---|---|---|
| 段 0 の前（`kTriSide` = $21b{+}46$） | 487 ビット / **8 リム**（512） | 592 / **10 リム**（640） |
| **段 0 の後**（最大は `kCmpH` = $13b{+}27$） | 300 / **5 リム**（320） | 365 / **6 リム**（384） |

`widths.hpp` から**中点系・重心系の 4 定数**（`kMidSide` / `kMidOrient2dH` /
`kTriSide` / `kTriOrient2dH`）と、`HMidPointD` / `HTriPointD` の型と述語が消えました。

**`kCmpH` は残ります**（`LOG-phase3-design.md` §6 の訂正 3）。頂点の併合に要るので、
`to_mesh` へ移るだけです。

### 1.4 変異 14 — 位相でも体積でも捕まらない誤り ★

軸の選択を「最小の $k$」から「最大の $k$」に変える変異を足しました。

**幾何としては正しい平面が返ります。** 辺の直線を含み支持平面と一致しないという条件は
満たすので、**位相も体積も 1 件も落ちません**（`cp3` / `adaptive` / `split_semantics`
すべて素通りを実測）。壊れるのは**決定性**だけです。

**決定性を直接見ている検査が無ければ、誰も捕まえません。** `interior` の正準性の検査が
主検出器です（21 / 147 件失敗）。

> **テスト側の判定は実装と独立に書きました。** 実装の条件式を呼ぶと「同じ変形を使う
> 正解器」になります（`CLAUDE.md`）。棄却理由（$N = 0$ か $N \parallel N_s$）を
> テスト側で再実装しています。

### 1.5 つまずいた点

**`det2(a,b,c,d) = a\cdot d - b\cdot c` の引数割り当てを 1 か所間違えました。**
外積の 3 成分のうち $c_y$ だけ順序を取り違え、**平行判定が常に偽**になっていました。
支持平面と同一の辺平面が返り、最初の煙テスト（軸平行な三角形）で第 3 点の `side` が
0 になって露見しました。**式をコメントに併記して再発を防いでいます。**

**条件 2 の判定を `int64` で書いたのも誤りでした。** 法線は $2b{+}3$（$b{=}26$ で 55
ビット）、辺平面の法線が $b{+}1$ なので、積は 82 ビットで溢れます。**固定幅で書き直しました。**

## 2. CP2 — 入口と出口の分離、分類の台の移動（2026-08-28）

### 2.1 契約は閉じました

| 関数 | 実測 |
|---|---|
| `from_mesh` | 全 44 メッシュ。**面併合なし**（辺平面を構成するので隣接情報が要らない） |
| `boolean` | 二項正解器と **264 / 264 一致**（22 ケース × 3 演算 × 深度 0〜3、$(C,\chi)$） |
| `to_mesh` | 往復 44 件で元の位相を再現 |

**§10.3.1（連鎖でビット幅が伸びないこと）を確かめました。**

| 段 | 最大ビット幅（$b{=}21$） |
|---|---|
| 1 段 | **142** |
| 2 段 | **142** |
| 3 段 | **142** |

上界は $7b{+}14 = 161$。**CSG が新しい平面を作らない**（OEBSP §3.1）ことが、
実測でも確かめられました。連鎖しても構成点は入力平面の集合から 3 枚を選んだ交点のままです。

### 2.2 分類の台を移すと、前提が 3 つ壊れました ★

**「相手のスープ」から「生成 0 の整数メッシュ」へ移す**のが CP2 の中心でした
（`SPEC-phase3.md` §14）。移した結果、Phase 1 / 2 が暗黙に置いていた前提が壊れます。
**どれも連鎖でしか出ません。**

| # | 壊れた前提 | 正 |
|---|---|---|
| 1 | 「source の平面 = スープに残っている多角形の支持平面」 | **前段で消えた面の平面が抜けます。** source のメッシュ全体から集めること |
| 2 | 「その source の多角形がセルに無い = 曲面が無い」（early-out） | **面が消えても曲面はそこにあります。** 判定は source の三角形で行うこと |
| 3 | 「重なりはスープの多角形どうしで検出できる」 | **スープに面が残っていなくても、source の曲面とは重なります。** `boundary_orientation` で直接見ること |

**3 が最も分かりにくい壊れ方でした。** 重なりを見落とすと代表点が source の**境界上**に
乗り、レイキャストの契約（`point_on_boundary` でないこと）が破れます。**答えが黙って
変わるので、位相検査でしか気づけません。**

### 2.3 面併合をやめた代償 — 共平面の重なりが揃わない

入口で面併合をやめたので（§3.1.4）、同じ平面に載る面が**別々の三角形分割**を持ちます。
重なりの領域が一致せず、`region_key` で潰せません。

**EMBER §4.3 の C4 と同じ手当てをしました。** 支持平面が同じ断片どうしを、
**相手の辺平面**で切って揃えます。自分の辺平面で切っても no-op なので、まとめて適用できます。

### 2.4 残った限界 — 同じメッシュを 2 度使う連鎖 ★

**内外の 1 ビットでは「同じ曲面を 2 度跨いだ」を表せません。**

| 連鎖 | 結果 |
|---|---|
| **別のメッシュ**との連鎖 $(A \cup B) \setminus D$ vs $(A \setminus D) \cup (B \setminus D)$ | **22 / 22 一致** |
| **同じメッシュ**を 2 度使う $((A \cup B) \setminus B) \cup B$ | **17 / 44 で食い違う** |

後者では $B$ が source 1 と source 2 の両方に現れ、その曲面が二重になります。
巻き数なら $w$ が 2 になるだけですが、**真偽値では表せません**。

> **CP3 の「真偽値 → $\mathbb{Z}^n$」がこれを解きます**（`SPEC-phase3.md` §14 の CP3 の変更 1）。
> CP2 の範囲（§10.3 の連鎖の厳密性 = 丸めが入らないこと、§10.3.1 のビット幅）は
> 満たしています。**丸めの問題ではなく、分類の表現力の問題です。**

### 2.5 つまずいた点

**添字を無効化しながら回しました。** 共平面の整列で、グループごとに `local` から
消しては足していたので、**2 つ目のグループ以降の添字が壊れて**いました。
症状は「一部の重なりだけ揃わない」で、**ケース 3 でしか出ませんでした。**
新しい配列を組み立てる形に直しています。

**`det2(a,b,c,d) = a·d − b·c` を今回も間違えました**（CP1 に続き 2 度目）。
式をコメントに併記する規律を、`plane_from_edge` に続き `boundary_orientation` にも
入れました。

## 3. CP3 段 1 — 真偽値から $\mathbb{Z}^n$ へ（2026-08-28）

### 3.1 CP2 の限界が消えました

| 検査 | CP2（真偽値） | CP3 段 1（巻き数） |
|---|---|---|
| 二項正解器との $(C,\chi)$ 一致 | 264 / 264 | **264 / 264** |
| 別メッシュとの連鎖の自己整合 | 22 / 22 | **22 / 22** |
| **同じメッシュを 2 度使う連鎖** | **17 / 44 で食い違う** | **44 / 44 一致** |
| 連鎖でのビット幅（$b{=}21$） | 142 / 142 / 142 | **142 / 142 / 142** |

$(A \cup B) \setminus B \equiv A \setminus B$ が通ります。**曲面を 2 度跨ぐ配置は
$w = 2$ になるだけ**で、真偽値のように潰れません。

### 3.2 表面上の点の巻き数は、3 つに分けて返します

判定点が曲面に載っているとき、巻き数は表裏で違います。`winding_split` は

| 返り値 | 意味 |
|---|---|
| `w_other` | **載っていない面**だけから決まる分（表裏で共通） |
| `c_front` | 基準法線 $+N$ 側で、載っている面が寄与する分 |
| `c_back` | $-N$ 側で寄与する分 |

**載っている面を先に除くのが要点です。** 境界上からレイを飛ばすのは `crosses` の
契約違反で、答えが定まりません。

### 3.3 導出を 2 度間違えました ★

**(1) レイの向きと基準法線の関係を落としていました。**

点 $p$ をシートから $\pm N$ に $\varepsilon$ 離すと、$+X$ のレイがシートを跨ぐのは
**レイが $-N$ 側へ向かうとき**、すなわち $X \cdot N < 0$ のときだけです。

$$w(p_+) = w_{other} + [\,X \cdot N < 0\,]\cdot \mathrm{sign}(N_{S,x}), \qquad
  w(p_-) = w_{other} + [\,X \cdot N > 0\,]\cdot \mathrm{sign}(N_{S,x})$$

最初は「外向き法線が $+N$ なら裏が内側」という**向きだけ**で決めていました。
これは真偽値なら正しく、**巻き数では基準がずれます**（$w_{other}$ がレイの経路に
依存するため）。244 / 264 が食い違いました。

**(2) レイがシートと平行な場合を落としていました。**

$X \cdot N = 0$ だと、どちら側が跨ぐかを決められません。**レイの軸を、基準平面の
法線が非零な軸から選ぶ**ようにして解決しました（`crosses` と記号的摂動を軸について
一般化。摂動の形は巡回順で同じです）。

> **どちらも「真偽値では正しいが巻き数では誤り」でした。** 表現力を上げると、
> それまで隠れていた前提が表に出ます。

### 3.4 辺や頂点に載る点

同じシートを複数の三角形が共有するので、そのまま数えると二重になります。
**内部に載っているものは 1 枚ずつ、境界だけのものは 1 枚**として数えます。
（真に二重なシートが同じ向きで重なっている場合は 1 と数えます。source をまたぐ
二重は別々に数えるので、目的の配置には影響しません。）

## 4. CP3 段 2 — セグメントトレース（**未完。実測を記録します**）

### 4.1 §5.3.2 の指標（伝播を入れたあと）

| 指標 | 実測（22 ケース × 3 演算 × 深度 0〜2） |
|---|---|
| 分類した領域 | 25,527 |
| **経路が見つからなかった領域** | **8,409（32.9%）** |
| **軸平行 1 本で済んだ回数** | **102**（主経路がほぼ機能していない） |
| 内部点の再試行 | 17,478 |
| 参照点の移動 | 6,567 |
| **うち棄却（別候補で回復）** | **2,133（32.5%）** |

**参照点の伝播は入れました**（§5.3.1 の指示どおり、トレースより先に）。移動の 3 分の 1 で
経路が退化しますが、候補を変えれば回復します。**問題は分類の経路のほうです。**

### 4.2 EMBER の前提がこのコーパスでは成り立ちません ★

EMBER §4.2.2 は

> 実用上の大多数の場合、これは有効な経路を与え、単一の軸平行セグメントで到達できる

としていますが、**Krisite のコーパスでは 25,527 領域のうち 102 回**しかそうなりません。

理由は明確です。**このコーパスは退化を狙って作ってあります**（`CLAUDE.md`「退化ケースを
明示的に構成する」「対称性の高い入力はバグを構造的に隠す」）。軸平行な立方体が
セル境界と面を共有し、頂点が一致し、辺が共線です。**軸平行な経路は、ほぼ必ず
どこかの面・辺・頂点に乗ります。**

EMBER の評価は Thingi10K（実データ）で、**この種の配置は稀**です。

### 4.3 足りないのは記号的摂動です

レイキャストには**記号的摂動**があります（`SPEC-phase1.md` §6.1。レイ原点を
$(0, \varepsilon, \varepsilon^2)$ ずらしたものとして扱い、投影の向きが 0 のときは
$\varepsilon$ の項で符号を決める）。**だから退化配置でも止まりません。**

**セグメントトレースには、まだこれがありません。** 退化したら経路を捨てて別を試す、
という戦略だけで、**退化が常態のコーパスでは捨て続けます。**

> **「別の経路を試す」は、退化が例外である前提の戦略です。**
> Krisite の前提は逆で、**退化が常態**です。同じ規律（摂動）をトレースにも入れる
> 必要があります。

### 4.4 次の一手

1. トレースの述語に記号的摂動を入れる（レイキャストと同じ形。経路を $\varepsilon$ だけ
   ずらしたものとして扱い、`side` が 0 のときは摂動項で符号を決める）
2. 摂動が「同じ経路に対して一貫している」ことを検査する（矛盾した符号を返さない）
3. そのうえで §5.3.2 の指標を測り直す
