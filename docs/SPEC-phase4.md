# Krisite — Phase 4 仕様書：並列化

---

## 0. この文書の位置づけ

**Phase 4 は並列化のフェーズです。意味論は変えません。**

**完了条件は正しさです。性能目標は設定しません**（Phase 5）。ただし
**予測と実測が整合すること**は完了条件に含めます（§6）。

前提として `SPEC-phase3.md` の全内容と `IMPL-phase3.md`、`BENCH.md` を使います。
着手前に読んでください。

### 0.1 範囲 — 中核と出口の両方

```
from_mesh   0.7%   ← 並列化しません
boolean    64.6%   ← 並列化します（§2）
to_mesh    34.8%   ← 並列化します（§3）★
```

**出口を含めるのは、含めないと Phase 4 が不健全な形で終わるからです。**

中核だけを $k$ 倍にしたときの内訳（$k = 5.5$、EMBER 並のスケール）:

| 区分 | 現在 | 中核を 5.5 倍にした後 | 割合 |
|---|---|---|---|
| 入口 | 0.8 ms | 0.8 ms | 1.4% |
| 中核 | 75.9 ms | 13.8 ms | 18.7% |
| **出口** | **40.9 ms** | **40.9 ms** | **73.7%** |
| 合計 | 117.6 ms | 55.5 ms | |

**残った時間の 3/4 が Phase 4 の範囲外という状態でフェーズが終わります。**
Phase 5 の性能目標を立てる土台として不健全です。

アムダールの上限（逐次部分 $s = 0.355$）は、中核のみなら $1/0.355 = 2.82$ 倍です。

### 0.2 意味論を変えないことが、ここでも武器になります

**逐次実装がそのまま正解器になります。** Phase 1 の固定深度、Phase 2 の分割戦略不変性、
Phase 3 の二項実装と同じ構造です。

そして §4 で**決定性**を要求するので、**比較はビット単位でできます。**

| 前提 | 根拠 |
|---|---|
| **葉の分類が可変な共有状態に触れずに書ける** | 監査 + 順序非依存の機構（264 / 330、`IMPL-phase3.md` §5） |
| 分類は各領域が独立（参照点の鎖が無い） | 大域レイキャストは source メッシュへの読み取り専用アクセス |

### 1.1 ただし「可変な部分をスレッド局所に保つ」は保証ではなく方針です ★

**順序非依存の検査は「論理的な依存の不在」を示すもので、データ競合は見ません。**

| 対象 | Phase 4 での扱い |

| 出力バッファ | スレッドごとに貯めて結合（§4.2） |

## 2. 中核の並列化 — 再帰タスク木

### 2.1 構造

EMBER §4.5.4:

> 各分割ステップが**本質的に純関数**になるよう慎重に設計した。部分問題の結果の多角形は
> 局所データのみに依存する。…この再帰手続きは work-stealing に完璧に適している。
> スレッドのプールが部分問題の**中央同期キュー $Q$** を持つ。各分割ステップで
> アルゴリズムは**一方の部分問題だけを再帰**し、もう一方を $Q$ に加える。
> 待機中のスレッドは $Q$ から新しい部分問題を取る。

```
分割タスク: AABB と多角形を受け取る
  ├ 分割の判定
  ├ 子 A を【自分で再帰】
  └ 子 B を【キューへ】
葉タスク: 局所 BSP → 分類 → 断片を【スレッド局所のバッファへ】
```

**Krisite は参照点の伝播を持たないので、EMBER より依存が少ない構造です。**
分類は各領域が独立に source メッシュを読むだけです。

### 2.2 burn-in

EMBER §5.3:

> 単一の分割タスクから始まり、2 つのタスクを生む。…したがって我々の手法の開始には
> ある種の**「burn-in」期間**があり、完全な並列性に達するまで時間がかかる。

**小さい入力では burn-in が支配します。** 性能の測定には規模のある入力が要ります（§8.2）。

EMBER §6 は「複数の**静的に事前クリップしたタスク**から始めることで burn-in を除ける」と
将来課題に挙げています。**Phase 4 では実装しません**（§10）。測定して効くと分かったら
Phase 5 で検討してください。

## 3. 出口の並列化 — 段階ごと + バリア ★

**中核とは並列の構造が違います。**

```
頂点の併合 → [バリア] → T 頂点解決 → [バリア] → 接触の分裂 → [バリア] → 三角形化
```

| 段 | 並列性 | 依存 |
|---|---|---|
| 頂点の併合 | **並列整列 + 区分ごとの併合** | — |
| T 頂点解決 | **辺ごとに独立** | 頂点表が完成していること |
| 接触の分裂 | **成分ごとに独立** | 位相（辺の次数）が確定していること |
| 三角形化 | **多角形ごとに独立** | 分裂が終わっていること |

**work-stealing のプールは中核のために設計されるので、そのままでは出口に当たりません。**
Phase 4 は**2 種類の並列構造**を扱うことになります。

### 3.1 頂点の併合が唯一の真に逐次な部分です

第 2 段（値ベースの併合）は「全構成点を `lex_less` で整列し、値が等しいものを併合」
（`SPEC-phase1.md` §5.3）。

**整列は並列にできます。** 併合も、整列後の区分ごとに独立です。

> **Phase 1 の実測では、併合グループの空間的な広がりが 1 セルとその隣接まででした**
> （`SPEC-phase1.md` §5.4）。**大域整列は必要条件ではありません。**
> セル単位で併合し、境界で突き合わせる形も取れます。
>
> **どちらを採るかは実装の判断です。** ただし**決定性を保つこと**（§4）。

### 3.2 バリアの数を測ってください

**3 つのバリアが並列効率の上限を決めます。** 各段の実行時間が偏ると、
バリアで待つ時間が増えます。

**段ごとの時間を記録してください**（§9）。偏りが大きければ、段の融合や
パイプライン化が Phase 5 の検討対象になります。

## 4. 決定性 ★ Phase 4 の要求

> **出力がスレッド数に依らず、ビット単位で同一であること。**

### 4.1 なぜ要求するか

**非決定的な破損はデバッグを不可能にします。** `SPEC-phase1.md` §11 が
「未解決のまま並列化すると、非決定的な破損が出て原因追跡が困難になる」と書いた理由と
同じです。**並列化そのものが非決定性を持ち込んではいけません。**

そして **検証が最も強い形になります。** 逐次実装との比較が「体積と位相が一致」ではなく
**「バイト列が一致」**になり、実装済みの逐次経路がそのまま完全な正解器になります。

### 4.2 達成の方法

**スレッドごとにバッファへ貯め、結合時に正準な順序へ整列してください。**

| 対象 | 正準な順序 |
|---|---|
| 中核の断片 | **葉の識別子**（AABB の Morton 符号など）で整列 |
| 出口の頂点 ID | `lex_less` による整列の結果（もともと正準） |
| 出口の三角形 | 多角形の識別子で整列 |

**結合時の整列は $O(n \log n)$ で、全体に対して安価です。**

> **「速いから」を理由に非決定的な結合を選ばないでください。**
> 決定性を失うと §7.1 の検証が成立せず、**得た速度より高いものを失います。**

### 4.3 退避

決定性がどうしても達成できない場合は、**幾何の多重集合の一致**に落とします
（`SPEC-phase2.md` §9.4.2）。**検証は成立しますが弱くなります。**
その場合は理由を `IMPL-phase4.md` に記録してください。

## 6. 予測と実測 ★

**先に予測を書き、実測と突き合わせてください。**

### 6.1 予測は $k$ の関数で書くこと

中核が $k$ 倍になったとき、出口の割合は

$$f_{\text{out}}(k) = \frac{40.9}{0.8 + 75.9/k + 40.9}$$

| $k$ | 予測 |
|---|---|
| 4.0 | 67.4% |
| 5.5 | 73.7% |
| 8.0 | 80.9% |

**定数（73.7%）で書かないでください。** それは $k = 5.5$ の場合の値です。
外れたときに「モデルが誤り」なのか「$k$ が 5.5 でなかった」のかが分かりません。
**未知が 2 つ混ざります。**

**実測の $k$ で評価してください。**

### 6.2 全体の予測

中核が $k_c$ 倍、出口が $k_e$ 倍になったときの全体は

$$\text{速度向上} = \frac{117.6}{0.8 + 75.9/k_c + 40.9/k_e}$$

**この式が実測と合わなければ、内訳の理解が誤っています。** 速度が出なかったことより、
**予測が外れたことのほうが重大です。** そこで止まってください。

### 6.3 完了条件は「速いこと」ではなく「予測と合うこと」

**性能目標は Phase 5 です。** Phase 4 が問うのは
**「時間がどこへ行くかを理解できているか」**です。

ただし**遅くなっていないこと**（1.0 倍以上）は最低限の床として確認してください。

## 7. 検証

### 7.1 決定性 — 逐次との一致 ★

> **スレッド数 1 / 2 / 4 / 8 で、出力がビット単位で一致すること。**
> **逐次実装（Phase 3）の出力とも一致すること。**

**全コーパス × 全演算 × 全機構有効で回してください。**

これが Phase 4 の主検出器です。**競合は非決定性として現れます。**

### 7.2 ThreadSanitizer ★

> **TSan を有効にした CI ジョブを置いてください。**

**決定性の検査だけでは足りません。** コーパスが小さいので、競合があっても
**たまたま顕在化しない**ことがあります。TSan は**実行された経路上の競合を、
顕在化していなくても検出します。**

`SPEC-phase2.md` の sanitizer ジョブと同じ枠組みで足せます。
**ASan と同時に有効にはできない**ので、別ジョブにしてください。

### 7.3 スレッド局所性 ★

> **可変な状態が共有されていないことを、機構で確かめてください。**

監査（目視）では、あとから共有された変更を捕まえられません。

| 方法 | 内容 |
|---|---|
| 型 | キャッシュ・統計・出力バッファを**スレッド局所であることが型に現れる**形にする |
| 検査 | 共有した変異（§7.5）が TSan と決定性の両方で落ちること |

### 7.4 Phase 1〜3 の検査体系を維持する

**並列モードでも全部通ること。緩めないでください。**

| 検査 | 節 |
|---|---|
| 位相、体積の恒等式・解析値 | Phase 1 §10.1 / §10.3 |
| 分割戦略不変性、深度不変性 | Phase 2 §9.1 / Phase 1 §10.2.1 |
| 二項正解器との一致、$n$ 項と二項の一致 | Phase 3 §10.1 / §10.2 |
| 連鎖の厳密性、ビット幅が伸びないこと | Phase 3 §10.3 / §10.3.1 |
| Manifold との $(C, \chi)$ 一致 | Phase 1 §10.4 |
| 順序非依存 | Phase 3 |

### 7.5 変異テスト

Phase 1〜3 の変異を維持し、追加します。**主検出器と、素通りする組合せも固定すること。**

| 名前 | 埋める誤り | 検出されなければ |
|---|---|---|
| **結合の順序** | 結合時の正準な整列を外す | **決定性を検査していない** |
| **キャッシュの共有** | 構成点キャッシュをスレッド間で共有する | TSan が入っていないか、経路を踏んでいない |
| **統計の共有** | `BoolStats` を共有カウンタにする | 同上 |
| **バリアの除去** | 出口の段の間のバリアを 1 つ外す | 段間の依存を検査していない |

**「結合の順序」は決定性の検査でしか捕まりません。** 位相も体積も、順序が違うだけの
出力を区別しません。`SPEC-phase3.md` の「辺平面の軸選択」と同じ形です。

## 8. テストコーパス

### 8.1 正しさ — 既存のコーパスで足ります

**Phase 1〜3 の全ケースをそのまま使います。** 追加は要りません。

**理由は §7.2 です。** 競合の検出は TSan が担うので、**規模ではなく経路の網羅**が
効きます。既存のコーパスは全機構を通る形になっています。

### 8.2 性能の測定 — 規模のある入力が要ります ★

**既存のコーパスでは burn-in が支配し、スケーリングが測れません**（§2.2）。

**手続き的に生成した大きな入力を 1〜2 件用意してください。**

| 例 | 用途 |
|---|---|
| 細分した球 × 2（数十万三角形） | 一様な分布 |
| 立方体の格子 × 有機的な形状 | 偏った分布（EMBER Fig. 22 に対応） |

**期待値は要りません。** 測定用なので、既存の恒等式検査が通れば十分です。

> **正しさのコーパスと性能のコーパスは目的が違います。** 混ぜないでください。
> 前者は退化を狙い、後者は規模を狙います。

## 9. 記録する数値

**完了条件ではありません**（§6.3 の予測との整合を除く）。Phase 5 の基準線です。

### スケーリング

- スレッド数 1 / 2 / 4 / 8 / 16 での中核・出口・全体の時間
- $k_c$、$k_e$、全体の速度向上
- **§6 の予測との差**

### 中核

- タスクの総数、盗まれた回数
- burn-in の時間（完全な並列性に達するまで）
- スレッドごとの負荷の偏り

### 出口

- **段ごとの時間**（バリアでの待ち時間の上限を決めます）
- 頂点の併合の方式（大域整列 / セル単位）と、その時間

### メモリ

- スレッド局所のバッファの総量
- 構成点キャッシュの総量（スレッド数に比例するはず）

## 13. 退避条件

| # | 想定が破れた場合 | 退避 |
|---|---|---|
| 1 | **決定性が達成できない** | 幾何の多重集合の一致に落とす（§4.3）。**検証は弱くなる** |
| 2 | **出口の並列化が効かない**（$k_e$ が 1.5 未満） | 中核のみで Phase 4 を閉じ、**出口を Phase 5 へ**。理由を測定値とともに記録 |
| 3 | **予測と実測が合わない** | **そこで止まる。** 内訳の理解が誤っているので、原因を特定してから進む |
| 4 | 全体の速度向上が 1.0 倍未満 | **並列化を既定から外す。** 実行時オプションとして残し、原因を Phase 5 へ |

**3 が最も重要です。** 速度が出ないことより、**なぜ出ないか分からないこと**のほうが
Phase 5 の土台として深刻です。
