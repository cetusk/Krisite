## 固定幅整数（`bench/arith_bench.cpp`）

| 演算 | 1 リム (64bit) | 2 リム (128bit) | 4 リム (256bit) |
|---|---:|---:|---:|
| `add` | 0.23 ns | 0.38 ns | 0.70 ns |
| `mul` | 0.56 ns | 1.90 ns | 11.63 ns |
| `cmp` | 0.43 ns | 0.41 ns | 0.41 ns |
| `sign` | 0.41 ns | 0.40 ns | 0.36 ns |

`cmp` と `sign` がリム数にほぼ依存しないのは、符号ビットと最上位リムで決着する経路が
効いているため（SPEC §5.3）。`mul` はリム数の 2 乗で伸びており、筆算の計算量と一致します。

## 読み取れること

**`side()` は 7.8 ns（128 Mops/s）。** 浮動小数点フィルタを入れるかどうかの判断材料として、
これが基準線になります。EMBER が「フィルタ不要」と主張する根拠と整合する水準です。

**`cmp_h` は `side` より重い（11.3 ns）。** 被符号値が 300 ビット（5 リム）と Phase 0 で
最大幅であること（SPEC §3.3）が素直に出ています。

なお、リム単位の積が生む 7 リムを §3 の上界である 5 リムへ詰める `resize` に、
**実行時コストはありません**（`resize` の有無だけを変えた A/B で 9.66 対 9.67 ns）。
Release では下位リムのコピーに縮み、符号を取るだけの後段では幅の差が出ません。

**`intersect3()` が 262 ns で突出して重い。** これは実装の選択によるもので、
`intersect3` は 3x3 行列式を 4 回計算しますが、列ごとに幅が違う（法線 1 リム、
オフセット 2 リム）ため、**正しさを優先して全列を 2 リムにそろえてから** 7 リム幅で
計算しています（`geom/plane.hpp`）。列ごとの幅を保った混合幅の行列式にすれば
数倍は縮むはずですが、Phase 0 では手を入れません（SPEC §0「性能より正しさを優先」）。

なお EMBER の想定では構成点は一度作って何度も `side` にかけるので、
`intersect3` の重さが支配的になるとは限りません。**Phase 1 で実際の比率を測ってから**
最適化対象を決めてください。

## Phase 1 §4.3.3 / §5.4 の計数（CP2 到達時点）

**性能ではなく設計判断のための数値です**（SPEC-phase1 §13）。
`tests/csg/test_cp2.cpp` を実行すると同じ表が出ます。b = 21、union、深度 0 / 1 / 2 / 3。

| # | 構成 | 断片数 | 重複断片 | 構成点 | 併合後 | 値併合 | **1 点の最大平面数** | うち mesh |
|---|---|---|---|---|---|---|---|---|
| 1 | 一般位置 | 48 / 108 / 192 / 366 | 0 / 0 / 0 / 0 | 46 / 100 / 184 / 358 | 同左 | 0 | **3** | 3 |
| 2 | 面が完全共平面 | 40 / 40 / 56 / 224 | 0 / 8 / 40 / 160 | 37 / 37 / 51 / 208 | 同左 | 0 | **3** | 3 |
| 5 | セル境界と一致 | 48 / 48 / 48 / 192 | 0 / 12 / 36 / 144 | 46 / 46 / 46 / 184 | 同左 | 0 | **3** | 3 |
| 5T | セル角を斜面が通る | 34 / 34 / 48 / 154 | 0 / 12 / 19 / 72 | 40 / 40 / 70 / 183 | 32 / 32 / 56 / 146 | 8 / 8 / 14 / 37 | **4 / 4 / 6 / 6** | 4 |
| 6 | 1 格子ずれ | 48 / 108 / 192 / 432 | 0 | 46 / 100 / 184 / 418 | 同左 | 0 | **3** | 3 |
| 8 | 同一の立方体 | 12 / 48 / 48 / 192 | 0 / 0 / 48 / 192 | 8 / 26 / 26 / 98 | 同左 | 0 | **3** | 3 |
| D | 交わらない 2 個 | 32 / 60 / 96 / 308 | 0 | 36 / 64 / 100 / 312 | 同左 | 0 | **3** | 3 |

「1 点の最大平面数」はセル面込み、「うち mesh」は入力メッシュ由来だけ。総当たり
（併合後の全頂点 × 表の全平面で `side` を評価）なので過小評価ではありません。

**読み取れること。**

- **軸平行な立方体だけでは 3 枚を超えません。** 1 軸につき点を通れる平面は高々 1 枚で、
  軸は 3 本だけだからです。セル面が立方体の面と一致しても、同一の幾何平面なので
  `PlaneTable` が同じ ID に併合し、枚数は増えません
- **斜面を入れると 4 枚（セル面込み 6 枚）になり、§5.3 の第2段が発火します**（ケース 5T）。
  第2段の必要性はここで初めて示されます
- **深度を上げても断片が増えないケースがあります**（5, 8）。面がセル境界に乗ると、
  その境界平面は §4.3.1 の大域分割が既に使っているので、新しい切断が入りません。
  増えるのは §4.2 の重複割り当てだけです

計測はまだ**時間**を測っていません。`side` : `intersect3` の呼び出し比率
（IMPL-phase0 §7 が求めているもの）は `BoolStats` に枠があるだけで未計測です。

## 次に測るべきもの

Phase 0 の完了条件には含まれませんが、Phase 1 の設計判断に必要になります。

- `side()` の分岐予測が外れる条件（構成点が平面上に載る割合が高い実データ）
- キャッシュミスを含む現実的なアクセスパターン（プール巡回ではなくランダム参照）
- 混合幅 `det3` にしたときの `intersect3` の改善幅
